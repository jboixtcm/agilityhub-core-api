# Review E7-T03 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/messaging/application/PushSubscriptionService.java:67` — Re-subscribing an endpoint can transfer its existing subscription ID to another account. Pending deliveries still reference that ID, and `NotificationDispatcher.sendPush()` checks only whether it is active. After account A logs out and B subscribes in the same browser, A’s queued notification can therefore be sent to B with A’s title and body. This violates account isolation (R-11-07/T-11-21). Reject foreign ownership, or implement a transfer that invalidates previous deliveries; also check recipient ownership during dispatch. Add a queued-delivery/account-switch regression test.

2. **major** `src/main/java/com/agilityhub/core/clubs/messaging/domain/NotificationCatalog.java:64` — `templateVariables()` adds member variables to every MEMBER catalog template, beyond its documented variables. R-11-12 reserves that general member-variable set for CUSTOM templates; the task explicitly closes per-code allowlists. The new list also differs from `NotificationEngine.known()`: N-02 accepts and previews `[[dog_name_article]]`, but actual delivery removes it as unknown. Use one catalog-approved allowlist for editing, preview and delivery, and test a saved customization through the real engine.

3. **major** `src/main/java/com/agilityhub/core/clubs/messaging/application/engine/TemplateValidator.java:151` — Previously seeded templates contain all three product languages, but validation now rejects languages outside `club.locales`. Existing templates remain untouched, and GET detail returns their complete maps. Consequently, a GET/edit/PUT round trip for an existing template in a `ca/es` club fails with `VALIDATION_ERROR` on its `en` fields. This leaves D9 maintenance incomplete for existing clubs (task steps 1/3 and Definition of Done). Add compatible normalization or migration that preserves edits, plus an upgrade test using an E7-T02 template.

4. **minor** `src/main/java/com/agilityhub/core/clubs/messaging/application/PushSubscriptionService.java:90` — Public-key validation checks only length and the uncompressed-point prefix. It accepts invalid P-256 points, including `(0,0)`, which the new unit test explicitly treats as valid. The integration fixture is also off-curve. Such subscriptions return success but fail during encryption, contrary to step 7’s malformed-key rejection. Validate curve membership, use generated valid public-key fixtures, and add an off-curve rejection test. The report’s claim that the replacement keys are valid is unsupported.

5. **minor** `src/main/java/com/agilityhub/core/clubs/messaging/application/NotificationLog.java:42` — The export receives nested recipient/channel objects that `ExportValues` flattens indiscriminately: recipient cells include internal member IDs, and channel/status cells retain values such as `APP; DELIVERED`. The added translations use `enums.*`, while the exporter looks up `export.value.*`, so notification enum values remain untranslated. This misses R-14-12 and step 4. Add explicit export formatting and assert exact recipient and localized channel/status cells in XLSX/PDF tests.

6. **minor** `src/main/resources/seed/message-templates.ca.json:21` — The N-02 APP seed instructs the member to follow `[[link]]`, but the engine never receives that credential, producing “Entra-hi amb aquest enllaç: .”. The executor acknowledges this unresolved behavior. Before verification, resolve the S11 §8/channel-copy conflict with the organizer and implement an appropriate APP message or non-secret destination, with a real N-02 rendering test.
