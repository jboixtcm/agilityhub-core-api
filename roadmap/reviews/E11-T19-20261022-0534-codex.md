# Review E11-T19 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/identity/api/PasswordGrantProvider.java:34` — The refresh branch ignores `consoleHost`. A club-bound OIDC refresh token for `clubs-admin` reaches `OidcService.refresh`, which restores its club context before issuing tokens. Because `requirePlatformConsole` checks the platform role only when membership is null, this path can issue a **club token on the product host to a non-platform account**. This violates step 1 and S01 R-01-02. Apply the console policy before OIDC tenant restoration; add regression coverage using club-bound OIDC refresh tokens for accounts with and without `AGILITYHUB_ADMIN`. The current refresh test covers only sessions initially issued on the product host.

2. **major** `src/main/resources/platform/product-branding.json:13` — Step 2 remains incomplete: the preset does not match the web’s AgilityHub preset. The readable sibling checkout’s `packages/ui/src/tokens.css:110–135` defines light primary `#1d1d1f`, dark primary `#ffffff`, and dark background `#0b0b0b`; the API instead uses blue primary `#2563EB`, background `#1D1D1F`, and independently chosen neutrals/status colours. `seeds/club-template-default.yaml` copies this mismatch. The new equality test proves only that the two API files agree, not compliance with E157. Resolve the mode/base discrepancy with the organizer, copy the canonical web values, and assert those values. The radius already matches at `8px`.

3. **minor** `src/main/java/com/agilityhub/core/shared/api/TenantFilter.java:111` — The newly documented “other clients → `404 UNKNOWN_HOST`” contract is enforced only for some grants. `optionalHost` still admits magic-link, handoff, and authorization-code exchanges regardless of client. Consequently, a valid `id-web` magic link issued on the ID host can be redeemed on the product host; a `clubs-app` handoff follows the existing club-token issuance path there. This contradicts the updated S01 R-01-02 and `/oauth2/token` description. Enforce the product-host client restriction before the optional-host bypass, or explicitly document an approved exception. Add negative tests with valid grants; the current other-client assertions exercise password login only.
