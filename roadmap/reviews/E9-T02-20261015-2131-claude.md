# Review E9-T02 — minor issues

## Findings
1. **major (needs a ruling)** `src/main/java/com/agilityhub/core/courses/api/CourseRingsController.java` (`GET /rings/{id}/marker-sheet`): the marker sheet is still a guarded 501 stub. The organizer's ruling E96 says «el PDF del full de marques (A8b) el resol E9-T02», so this item of the task is not delivered. The executor only proposes two options (drop the route, or add `RingGeometry.markerSheetFileKey` with a `POST`). The organizer should pick one, then either reopen the task or move the work to E9-T03 explicitly, so it is not lost.
2. **minor** `src/main/java/com/agilityhub/core/courses/domain/CourseModelFacts.java:34-48`: `pathLengthM` is computed in Java (a polyline with `Math.hypot` through the `n1` labels). R-16-01 says «el back no reimplementa geometria a Java»: the server stores what course-core sends. This is geometry, and it may disagree with course-core's own path length. The executor asked about it (question 3). Suggested fix: take `stats.pathLengthM` from the client payload, or from a course-core summary inside `normalizedJson`, and only check it against the schema.
3. **minor** `src/main/java/com/agilityhub/core/courses/application/CourseLibrary.java:310`: when `levels.enabled = false`, the error is `400 VALIDATION_ERROR {fieldErrors[{levelIds, LEVELS_DISABLED}]}`. CATALEG_ERRORS §1 lists `LEVELS_DISABLED` as a top-level **422**, and every other context throws it that way (`DogService.java:104`, `CoverageQuery.java:30`). T-16-12 only says «rebutjats», so nothing in the spec allows a different shape. Suggested fix: `throw new ApiException(LEVELS_DISABLED)`, add it to `@ContractErrors` on POST/PATCH `/courses`, and update `CourseLibraryIT.java:225`. (`LOCALE_NOT_ENABLED` as a fieldError code has precedent in `CatalogService`/`PlanValidator`, so that one is fine.)
4. **minor** `src/test/java/com/agilityhub/core/configuration/E9ContractIT.java:199`: the PATCH half of `T_16_03_aModelIsRequiredUnlessTheSourceIsAnImageAndAPatchKeepsTheStoredOne` only calls `served(...)`, which accepts any of 200/201/204/400/404/409/422. The claim in the test name («a PATCH keeps the stored one») is never asserted. The test even sends `"normalizedJson": null`, which must keep the stored model, but nothing checks it. The tenant/role matrix uses the same loose `served()` for allowed roles. Suggested fix: assert `200` and that the stored `normalizedJson`/`schemaVersion` are unchanged after a PATCH without a model.
5. **minor** `CourseLibrary.java:89-95` with `GlobalCourseRepository.java:22-29`: every `GET /courses` loads into memory all of the club's courses plus every `PUBLIC` library and account course of **all** accounts on the platform, and all active setups. It then filters, sorts and pages in memory (`CourseListing`). The executor records this as an assumption. It is fine at R1 volumes, but the cost grows with the size of the global library. At least record it in `docs/DECISIONS_PENDENTS.md` or MESSAGES as a known limit (or push `owner`/`discipline`/`updatedAt` filters down to Mongo).
6. **minor** `src/main/java/com/agilityhub/core/courses/application/CourseLibrary.java:252-255` (and the same at create, `:174-178`): `apply()` claims new file keys (`files.claim` → `grants.bind`, a write) **before** the `STALE_VERSION` check. The transaction rolls it back, so the data stays correct. But a stale PATCH with a new key that is unknown, foreign or already bound answers `404 NOT_FOUND` instead of `409 STALE_VERSION`, depending on field order. Suggested fix: check the version before touching files, or claim after validation.
7. **minor** `RingGeometryService.java:93-99` / `CourseLibrary.java:191-197`: `DELETE` geometry (`usesRing`/`activeWithPlacement` then `clear`) and `DELETE` course (`activeRings` then `write`) are check-then-act across different documents. A Mongo snapshot transaction does not stop write skew with a concurrent placement or setup creation. Not reachable yet (placements and setups are still stubs), but E9-T03 needs a guard: either touch the ring/course document in the same transaction, or recheck the geometry version when a placement is created. Worth a MESSAGES line for E9-T03.
8. **minor** `RingGeometryService.java:119-124`: when the club draws its first ring, the venue is upserted under the global unique index `venue_slug`, using the club slug. If an existing venue (for example a future partner venue) already has that slug, the result is a `DuplicateKeyException`, so a 500 that also rolls back a valid geometry save. Concurrent first saves can also race on the partial index `venue_club`. The defaults `PaperSize.A4`, `IndoorOutdoor.MIXED` and `VenueVisibility.MEMBERS_ONLY` are hard-coded product values with no parameter. They are not Cànic literals, but A4 should come from the country profile; recorded as an assumption.
9. **nit** Some test ids do not match the spec's T-xx: `T_16_06_calibrationsAreStoredPerRing…` (T-16-06 is geometry validity/stale/delete; calibrations have no T-id), `T_16_03_editsAreInPlace…` and `T_16_03_aCourseShownByAnActiveSetupCannotBeDeleted…` (T-16-03 is schema validation; these test A8a and R-16-03 soft delete). Rule 5 asks for names after the spec id they assert. Rename them, or use the R-id with a descriptive suffix.
10. **nit** `FILE_TOO_LARGE` now carries `{maxSizeBytes}` on `/courses/upload-urls`, but `{maxSizeMb}` on every other upload route. The executor flagged it in MESSAGES. One error code with two detail shapes is a front-end mapping hazard; ask the organizer whether to standardise on bytes.
11. **nit** `CHANGELOG.md` still has the earlier session's line «Courses implementation is blocked pending that repair; this session records evidence without product changes». It now contradicts the new E9-T02 entry right below it; remove it or mark it as superseded.
12. **nit (process)** The report says the new tests were «written with the implementation, not run against the pre-task code». The Steps ask for the failing test first. The 501 argument makes this plausible for the success assertions, but not for the new domain unit tests (`RingGeometryRulesTest`, `CourseModelFactsTest`, `CourseJsonConverterTest`).
