# Review E6-T03 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupNotificationFacts.java:41` — N-20 ownership is checked only when building the notification. If its first email attempt fails, then the dog transfers, `NotificationDispatcher.sendEmail` retries the stored recipient without checking ownership (`src/main/java/com/agilityhub/core/clubs/messaging/application/engine/NotificationDispatcher.java:134`). The previous owner therefore still receives N-20 after transfer, contrary to **R-10-10 / E64 round-2 point 3**. Coordinate a delivery-time ownership check with E7-T02 and add a regression covering failed email → transfer → retry; the new test covers only delayed `TaskCreated` consumption.

2. **minor** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupProjection.java:48` — The note author’s name, gender and account are loaded from the member’s current record when the event is consumed. Writing a note, changing that member’s profile, then dispatching the event permanently stores the later profile as the historical author. This does not meet **S10 §3 / E64 round-2 point 4**, which requires author details as they were when written. Capture the author snapshot in the note-writing transaction and consume that snapshot; test a profile change before dispatch.
