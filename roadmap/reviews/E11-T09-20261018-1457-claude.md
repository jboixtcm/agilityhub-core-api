# Review E11-T09 — minor issues

## Findings
1. **minor** `src/test/java/com/agilityhub/core/identity/application/PasswordHasherTest.java:27` (`T_01_02_INC_37_everyVerificationTakesTheSameTimeWithinTwentyPercent`): this unit test checks real wall-clock times against each other, within ±20 %, using the median of 5 runs.
   - **Why it can flake:** the bcrypt-12 cases take `max(floor, actual)`. The floor comes from calibration at construction time (the longest of 3 warm runs, plus 25 %). One GC pause or a busy shared CI runner during the bcrypt runs can push the median past 1.2 × the floor, and the test fails. INC-71 was exactly this kind of host-dependent flake.
   - **Startup cost:** every Spring context now also runs 4 bcrypt-12 and 4 argon2 checks at startup, because `PasswordHasher` calibrates in its field initialiser.
   - **Suggested fix:** assert `elapsed ≥ hasher.floor()` for every case. Then either compare against the floor with a wider upper margin, or move the strict ±20 % comparison to a tagged or repeated-measurement test.
2. **minor** `src/test/java/com/agilityhub/core/courses/api/BuildSessionsIT.java:121` (INC-71): the task says "each fix comes with a test that fails before it", and there is no red run for this fix. The report says so openly: on Boot 4.1 the race could not be reproduced. The only red is E11-T01's Boot 3.5 log.
   - **The 20 runs miss the original condition:** they ran one after another in one context (`@RepeatedTest` subclass, log `12`). The original failure needed "several builds sharing the container". So the evidence shows the test is stable, not that the fix removes the flake.
   - **Decision for the organizer:** accept this as done, or ask for one run under the parallel-build condition.
3. **minor** `src/main/java/com/agilityhub/core/identity/persistence/ImpersonationGrantRepository.java:59`, `ensureIndexes()`: no test exercises the production upgrade path.
   - On existing databases, `alterIndex` has to turn the old `expiresAt_1` index (`expireAfterSeconds: 0`) into the 1-day retention index. That is the path production will take.
   - The IT only asserts the final index state. On the test container that is almost certainly the "create" branch.
   - If `alterIndex` fails at startup, or silently leaves the TTL at 0, Mongo can delete grants before the sweep runs. `EXPIRED` events are then lost, which is the INC-37 item 1 bug again.
   - **Suggested fix:** an IT that creates the old index with `expire(0)`, calls `ensureIndexes()`, and asserts 86400 s on the same index name.
4. **minor** `src/main/java/com/agilityhub/core/identity/application/ImpersonationExpiry.java:35`: the sweep can starve.
   - `expiredOpen` returns the oldest grants first, capped at 200. A grant whose `expire()` throws every time is logged and picked up again on the next sweep.
   - 200 such poison grants would block every newer grant until the 1-day TTL removes them.
   - **Suggested fix:** skip grants that already failed in this sweep, or page on `expiresAt > lastSeen`. Low likelihood, so a nit-level fix is enough.
5. **minor** `src/main/java/com/agilityhub/core/identity/api/MeController.java:97` (INC-37 item 5): refusing `PATCH /me` to an impersonated token changes behaviour the public contract used to allow ("Any valid account token").
   - The change is declared in S01 §6, the openapi CHANGELOG and the report's assumption 2 ("the web should hide the edit").
   - The organizer should confirm two things: that a web task or INC entry exists so the impersonated app hides the language/name edit, and that "refuse" (rather than "allow + new audit action") is the accepted product decision. Rule 2 of the task allows taking the assumption, but the web impact is outside this repo.
6. **nit** `docs/DEPLOY.md` §"Platform versions (E11-T07)": this commit changes `deploy/compose.prod.yaml` (`CLUB_ADMIN_HOSTS` → `CADDY_APP_UPSTREAM`). That section now says "`deploy/compose.prod.yaml` [is] unchanged … The one Compose file that changed is the local override".
   - The wording follows step 4 literally, but read today it contradicts the INC-64 change.
   - **Suggested fix:** add "by the Boot 4 upgrade".
7. **nit** `src/test/java/com/agilityhub/core/identity/api/OidcIT.java:261`: the INC-37 Javadoc of the rotation tests sits on top of a second Javadoc on the `agePreviousRotation()` helper. As a result, it documents neither test.
8. **nit** `bin/security-scan-test.py:82`: the E11-T07 test switched from the fixed `TODAY` to `datetime.date.today()` to compute `active`. That makes the test date-dependent, unlike the rest of the file.
9. **nit** `deploy/Caddyfile:72`: `forward_auth` puts `{host}` into the query string without escaping it. A crafted `Host` header such as `x&host=y` can change which SPA a request gets. Both SPAs are public static bundles, so there is no security impact, only a messy edge.
