# Review E6-T03 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupContractAccess.java:79` — Task authorization uses the asynchronously maintained `Task.memberId`. After a dog transfer commits, but before its consumer runs, the previous owner can still read the task, obtain attachment URLs, and complete it; the new owner receives 404. This violates R-10-10/R-10-11’s current-owner restriction. Authorize against `DogOwnerAccess.ownerOf(task.dogId())`, and test access immediately after transfer with dispatch paused.

2. **major** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupProjection.java:54` — The transfer consumer unconditionally applies the event’s destination. For transfers A→B followed by B→C, delayed delivery of the first event after the second permanently resets tasks and D14 rows to B. The dispatcher permits this through retries and concurrent workers. S03 R-03-14 and task step 5 require these records to follow the dog. Reconcile against current census ownership or enforce monotonic transfer ordering; test reversed delivery.

3. **major** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupNotifications.java:52` — N-20 combines the **original owner from the event** with the **current task text**. If delivery is delayed until after a transfer and subsequent task edit, the previous owner receives the new owner’s task content by APP/EMAIL, even after task access has been revoked. This violates the owner-only visibility of R-10-10. Suppress or safely reconcile obsolete deliveries before reading and sending current content; add a delayed-delivery transfer test.

4. **minor** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupService.java:65` — `authorGender` comes from the dog’s current owner, although `authorName` and `authorAccountId` can identify the previous owner who wrote the retained note. Transferring Joan’s dog to Laura therefore labels Joan’s note with Laura’s gender. Additionally, `FollowupProjection.java:44` assigns the new owner’s name if the original note event arrives after transfer. S10 §3/§10 requires attribution to the author. Resolve author metadata independently of current ownership and test a retained note across transfer.

5. **minor** `src/main/java/com/agilityhub/core/clubs/followup/application/FollowupService.java:55` — D14 delegates pagination unchanged to the universal list engine, which accepts sizes 200 and 1000. The explicit ≤50-row limit in S10 §3 and task step 5 is therefore unenforced. Add and publish the resource-specific limit, with boundary tests, or obtain an explicit specification amendment.

## Not checked

Maven tests, Docker/manual scenarios, and OpenAPI regeneration were not rerun because this review is read-only. Existing reports and test XML were inspected; the transfer timing scenarios above were traced in code, not reproduced live.
