## Findings
1. **minor** `SignupService.java:543` (`claimDocuments`, the `DOG_DOCUMENT_REQUIRED` check): a "no change" edit can still get `422 DOG_DOCUMENT_REQUIRED`.
   - **What happens.** The check runs on every `VACCINATION_CARD` that is sent, even an unchanged one. With `signup.requireDogDocumentAtSignup = true`, a pending public-signup dog whose card shows `PENDING` with no files fails this check when D2 sends its view back unchanged. Any other edit that echoes the documents (for example a name change) also gets the 422.
   - **How the dog gets there.** E5-T19 lets S03 remove the last card file of such a dog (`DocumentService.remove` sets `PENDING`), or the parameter is turned on after submission.
   - **Why it matters.** This contradicts step 2 («a documents edit that changes no file key of any type is no change»). It also contradicts the new `DogPatch.documents` text «Sending back the view's keys is no change».
   - **Status.** The check predates this task, but step 2 makes sending the view back the normal D2 path.
   - **Fix.** Apply the requirement only when the card's keys differ from the view's (`shown`), and add one IT. Or have the organizer accept the 422 and document it on the description.
2. **nit** `SignupService.java:538` / report assumption 3: refusing a removed key now also applies at submission, but nothing tests or documents it.
   - At `POST /signup` (readmission) and `POST /me/dogs/signup`, a key removed from the reused dog's own card answers `400 FILE_NOT_FOUND`.
   - No IT covers this, and the E5-T21 entry in `docs/openapi/CHANGELOG.md` describes only the D2 `PATCH`.
   - **Fix.** Add one line to the changelog entry. Optionally add a submission IT with a removed key.
3. **nit** `TransactionRetriesTest.java:11-17` (class Javadoc): it says «every retried writer draws its wait from one 50–150 ms range».
   - The S01 and S04 writers do not: `IdentityTransactions.java:21` and `SignupTransactions.java:36` keep their own exponential backoff, 25–500 ms. The executor raised this as question 1.
   - The `jitter()` Javadoc is correctly limited to S05–S09.
   - **Fix.** Say «every S05–S09 writer», or settle question 1.
4. **nit** `SignupService.java:496-500` (readmission branch of `saveDocuments`): assumption 2's per-type filter applies only to public-signup dogs.
   - In a mixed edit of a reused dog (one type changed, one of the dog's own types sent back unchanged), the unchanged own type is copied into `readmissionRequest.submitted.documents`. At validation it then rewrites that document with the same keys.
   - This is harmless today: same keys, and the state is `RECEIVED` either way. It is inconsistent with the public path, though.
   - **Fix (optional).** Merge only the types whose keys differ from `shown`.
