2. **nit** `src/main/java/com/agilityhub/core/platform/domain/SpanishCountryProfile.java:40` — the ES padding (`1234567L` → `01234567L`) is not described in any document.
   - S02 §3 (amended 26-09) only says the tax id is stored "majúscules, sense espais ni separadors". The OpenAPI descriptions say the same and are frozen by this task's byte-identical rule: `SettingsContracts.java:93` and `:148`, `BrandingResponse.java:31`.

   - The contract descriptions need a line in a later contract-touching task. Proposal: "ES: a 7-digit DNI is stored padded to 8 digits".
3. **nit** `docs/DEPLOY.md:574` — still says only "The collection is created at startup (`schedulingCollections`)".
   - Documents written before E5-T17 have no `expiresAt` (Assumption 1). The TTL never removes them, and P9's `ttlPending` (`expiresAt < now`) never counts them either. So they stay forever and nothing reports them.
   - The one-off `updateMany` from Assumption 1 exists only in the task report.
   - Fix: add the TTL index (`ring_slot_lock_ttl`) and that backfill line to DEPLOY.md, for any environment that has run E5-T07…E5-T16 code (staging, local dumps).
4. **nit** `src/main/java/com/agilityhub/core/clubs/scheduling/persistence/SchedulingPersistence.java:280` — the tolerance check after an `ensureIndex` failure checks only the name `ring_slot_lock_ttl` and a 0 s TTL, not the key `{expiresAt: 1}`.

   - The risk is low, but the comment claims "a conflicting definition stays a startup failure". Fix: also compare `index.getIndexFields()` with `expiresAt` ascending.
5. **nit** `roadmap/tasks/E5-T17.md` Assumption 2 — a whitespace-only `taxId` (`"   "`) clears the tax id.
   - This matches the task wording ("non-blank"). But S02 §3's normalization treats spaces like separators ("sense espais ni separadors"), so it could also be read as "only separators", which should be refused.
   - Worth an explicit organizer confirmation. No test pins the `"   "` case either way.
