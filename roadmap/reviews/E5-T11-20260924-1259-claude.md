# Review E5-T11 — minor issues

## Findings
1. **minor** `src/main/java/com/agilityhub/core/clubs/census/persistence/CensusRepository.java:59` — Step 3 asks `save` to fail fast "when a `@ForeignOwned` field differs from the **stored** value". The code compares against the value the entity was **read** with (`loadedForeign`), and only falls back to the stored value when the entity was not read from Mongo. This goes against the wording of the step. The executor's reason is sound: comparing against the stored value would make an admin's census save throw after a concurrent booking `setField` (`BookingsIT.R_08_23_bookingsNeverMakeTheMembersCensusFormStale`). The organizer should accept this explicitly, or amend the step. The failure is also a raw `IllegalStateException`, so it surfaces as a 500 and not as an `ApiException` (AGENTS rule 9). That is acceptable for a guard against a programming error, but the report does not mention it.
2. **minor** `src/main/java/com/agilityhub/core/clubs/messaging/application/SystemNotificationService.java:72,82,94` — `appOnce`, `smsIntentOnce` and `pushIntentOnce` changed from `Propagation.NEVER` to `REQUIRED` for **every** caller, not only the N-15 consumer. `NEVER` used to catch a caller that wrongly ran these inside a business transaction; now such a caller silently joins that transaction. As a side effect, the N-15 APP/SMS/PUSH rows and their outbox events are now written while holding the class's `BookingTransactions` lane, so they run serially with bookings. Suggested fix: keep `NEVER` on the public methods and add a `MANDATORY` variant (or package-level hook) that only `WaitlistNotifications.offered` uses. Or at least list the other callers in the report to show that none of them runs inside a transaction.
3. **minor** `src/main/java/com/agilityhub/core/clubs/bookings/application/WaitlistNotifications.java:147-150` — `markOfferNotified` runs before `send(...)`, and `send` can return early without writing a row: the session or the member is gone, or the member has no account and no phones. In those cases `offerNotifiedAt` records a "delivered" N-15 that was never written. Today this is harmless, because N-46 goes to APP only and would find no recipient either. But the field's Javadoc ("the last offer whose N-15 was delivered") is then wrong, and the `offerNotifiedAt` row proposed for `MODEL_DADES_PLATAFORMA.md` would carry the same wrong meaning. Suggested fix: call `send` first and mark only when at least one row was queued, or reword the field's meaning to "the N-15 of this offer was processed".
4. **minor** `WaitlistNotifications.java:159-160` (step 2) — "comes from a confirmation" is inferred from "the class has a live booking of the payload's `dogId`"; no payload field says so. Consider a `SeatHoldReleased` from `DELETE /seat-holds` that the outbox delivers late, after the same dog has booked the class another way. It would be treated as a confirmation and run the demotion/N-46 path. The outcome is still correct, because the seat is indeed taken and the N-46 ids are idempotent, so this is only a weak proxy. The assumption is documented in the report; noted for the organizer. A `reason`/`confirmed` flag in the payload would make it exact, but it would need a catalog amendment to `CATALEG_ESDEVENIMENTS.md`, so the current choice is defensible.
5. **minor** `src/test/java/com/agilityhub/core/configuration/E2ContractIT.java:230-249` — the new per-route test only covers an **unknown slug** (no key, empty key, wrong key). Key-first has a second half: a **SUSPENDED** club reached without its key, or with a wrong key, must answer `403 INVALID_API_KEY`, not `CLUB_SUSPENDED`. Nothing tests this on any route; `PlansIT:229` only checks `CLUB_SUSPENDED` with the valid key. The code does it right (`PublicClubAccess.java:23-29`). Suggested fix: add the suspended + wrong-key and suspended + no-key cases to the same loop.
6. **nit** `src/main/java/com/agilityhub/core/platform/application/PublicClubAccess.java:24` — an unknown slug returns before the SHA-256 digest; a known slug computes it. The timing difference is tiny, and club slugs are public anyway, so this is not a real enumeration oracle. Mentioned only because the Javadoc says the caller "cannot tell whether the slug exists".
7. **nit** `src/main/java/com/agilityhub/core/clubs/catalogs/api/PublicPlansController.java:28` — the plans route still has an empty `@SecurityRequirements`, while the pages route declares `@SecurityRequirement(name = "clubApiKey")`. Step 6 asks for "one rule for the keyed public routes", yet the OpenAPI still documents the key differently on the two routes. This predates the task, but it could be aligned in the same snapshot.
8. **nit** `WaitlistNotifications.java:85` — N-46 still triggers on "ACTIVE with `notifiedAt` = `offerNotifiedAt`". In FIFO mode, an entry whose offer **expired** (`confirmBy` passed, back to ACTIVE) keeps both timestamps, so a later seat-taken event could send «La plaça ja s'ha ocupat» about an offer that expired rather than one someone took. This predates the task (E5-T08 condition). Worth a look if FIFO expiry leaves `notifiedAt` set; I did not trace the expiry path.
