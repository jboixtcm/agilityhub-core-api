# Review E8-T12 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/payments/application/PaymentRefunds.java:518` — **Shared captures can report an overpayment that never occurred.** Example: a €24 capture covers rows A/B (€12 each), A has a billed €12 credit, and dashboard refund R1 is pending for €12. Reservations allocate R1 to B. When another dashboard refund R2 succeeds for €5, `settlementParts()` excludes B’s reserved capacity and allocates R2 to A. Consequently, `absorb()` emits `REFUND_OVER_CREDIT`/N-55 for €5, although settled refunds plus credits total only €17 against €24 captured. If R1 subsequently fails, that false notification remains. This violates S12’s E101 requirement to report actual incremental overpayment and E103’s capture-wide accounting requirement. Calculate overpayment across the entire intent independently of reservation placement. Add this regression with both terminal outcomes of R1; the shared generator currently never bills credits.
