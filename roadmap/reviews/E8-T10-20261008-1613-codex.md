# Review E8-T10 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/migration/persistence/MigrationResetRepository.java:36` — The counter misses ordinary application writes without audit/outbox events. For example, `SavedViewService.create` inserts a saved view without incrementing it. Creating a view after the production checkpoint therefore still permits reset, which deletes that view. This violates point 2 and S18 R-18-17/T-18-16; the gap includes normal API use, not just direct Mongo writes. Make every application write to data erased by reset participate in the fence, and add a regression using the saved-view service.

2. **major** `src/main/java/com/agilityhub/core/migration/application/PlayoffImportService.java:81` — Reconciliation bypasses lease fencing. `billing.reconcile` calls `BillingSimulationService.simulate`, which commits a replacement simulation and `RemittanceSimulated` event in its own transaction. If this worker pauses until its lease expires and another worker completes recovery or reset, it can still commit these writes before the completion fence rejects it. Point 1’s safe recovery is therefore incomplete. Fence reconciliation’s writes inside their transaction, and test an expired worker resuming at this stage with a nonempty forecast.

3. **nit** `src/test/java/com/agilityhub/core/migration/PlayoffMigrationIT.java:576` — The three recovery tests use `T_18_03`, but S18 assigns T-18-03 to anonymization. Recoverable batch loading is T-18-13/R-18-03. Rename these tests and correct the report’s mapping to preserve the traceability required by AGENTS rule 5.
