# Review E3-T09 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/census/application/SignupService.java:105` — Identity matching ignores `readmissionRequest.submitted.contactEmails`. After a readmission submits a new primary email, another signup with a different DNI and that email receives `NEW` and can create a second pending application. Validating both subsequently encounters `MEMBERSHIP_EXISTS`. This breaks duplicate detection when combining R-04-05 with E38. Include pending readmission emails in the indexed matching logic and test this sequence.

2. **major** `src/main/java/com/agilityhub/core/clubs/census/application/MemberService.java:48` — D2 identity-document edits still modify the original member directly during a pending readmission. `restoreLeft()` neither snapshots nor restores `idDocument`, so submission → D2 DNI correction → rejection permanently changes the original record. This contradicts E38 and step 3’s restoration requirement. Stage this field alongside the other submitted person fields, or explicitly reject such edits; extend T-04-12 to cover editing before rejection.

3. **major** `src/main/java/com/agilityhub/core/clubs/census/application/SignupNotifications.java:41` — Readmissions now retain the old contact email, but N-01 and N-03 still use that address. Applicants submitting a replacement address therefore receive neither confirmation nor rejection there. Rejection also deletes the submitted payload before the asynchronous notification runs. The report acknowledges this unresolved regression; S04 §8 and the notification catalog specify delivery to `APPLICANT`. Preserve submission-specific recipient information through rejection and test delivery with different original/submitted addresses.

4. **minor** `src/main/java/com/agilityhub/core/clubs/census/application/SignupService.java:130` — The indexed family lookup no longer preserves R-04-12’s whitespace normalization. Input whitespace is collapsed, but stored dog names are only trimmed. A stored `Example  Dog` is excluded by the equality query for `Example Dog` before `FamilyHolderMatcher` can normalize both. Index a consistently normalized lookup field, including existing records, and add a regression test.
