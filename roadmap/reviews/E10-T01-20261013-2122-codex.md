# Review E10-T01 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/platform/api/PlatformClubContracts.java:26` — The domain response exposes no TXT verification token or record value. Neither another console response nor `ClubDefinition` supplies it, so the web cannot display the `agh-verify-{token}` challenge required by **R-17-03** and S17 §2. Publish the pending domain’s verification instructions and test their response schema; DNS execution can remain deferred.

2. **major** `src/main/java/com/agilityhub/core/platform/api/PlatformClubContracts.java:89` — Theme updates require uploaded file keys, but there is no compatible upload contract for a tenant-free `AGILITYHUB_ADMIN`. The existing attachment upload requires club roles/context and offers no logo purpose; the other upload routes cover signup and courses. Consequently, the logo flow promised by **S17 §2/§6** cannot be built against this contract. Define the authorized upload route/purpose, schemas and stub tests.

3. **major** `src/main/java/com/agilityhub/core/platform/api/PlatformClubContracts.java:33` — `PlatformClub.paymentProviders` contains only status/masking metadata. It cannot return existing SEPA creditor name/identifier/suffix or MANUAL instructions, although the console must edit that configuration (**S17 §2, R-17-05; model §2**). Publish provider-specific read projections for these non-secret fields, preserving masked IBAN and write-only credentials, with fixtures covering SEPA and MANUAL.

4. **major** `src/main/java/com/agilityhub/core/platform/api/PlatformClubContracts.java:65` — `PlatformClubPage` omits `appliedFilters`, which **CONVENCIONS_API §4** requires for universal lists. The published schema and fixture reproduce the omission, making this response incompatible with the shared list contract. Reuse `ApiContracts.ListPage<PlatformClubListItem>` or add its required filter metadata and assert it explicitly.

5. **minor** `src/main/java/com/agilityhub/core/platform/application/definition/PlatformDefinitionSchema.java:66` — Invalid definitions return `details.fields` containing diagnostic strings. **CONVENCIONS_API §6** requires `details.fieldErrors[{field, code}]` or a single `details.field`; clients following that contract cannot associate these errors with form fields. Convert schema violations to the canonical structure and test nested paths and missing required fields.
