# Review E3-T10 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/census/application/SignupService.java:71` — Checkout scope still depends on current dog ownership. Validate an add-dog submission with `upfrontAmountPaid = 0`, then transfer that dog to another active member: `dogs(memberId)` excludes it, while its unpaid rows retain the original `memberId`. Neither member’s checkout includes those rows. Step 15.1 requires excluding only superseded readmission submissions; S03 R-03-14 permits this transfer. Track payable submissions against their debtor independently of current ownership, and add this regression test.

2. **minor** `src/main/java/com/agilityhub/core/clubs/census/application/SignupNotifications.java:72` — Add-dog rejection emails now use the original public signup’s language. For an original signup in `ca`, followed by an add-dog submission in `es` from an account using `es`, N-03 renders in `ca`: `addDog()` no longer updates `Member.signup`, but rejection delivery still reads its locale. This is a compatibility gap introduced by step 5, against S04 §8 and the notification locale convention. Resolve the rejection recipient’s locale correctly and test differing public-signup/add-dog languages.

3. **minor** `src/main/java/com/agilityhub/core/clubs/common/api/DashboardContracts.java:74` — `RiskNotified.gender` still rejects null in the generated contract. The OpenAPI 3.1 schema combines `type: ["string", "null"]` with `enum: ["MALE", "FEMALE", "OTHER"]`; the enum excludes null. Step 10.4 is therefore incomplete. Include JSON null in the enum or use a separate null branch, and validate a sample containing `gender: null` instead of checking only the schema’s `type`.

4. **minor** `src/test/java/com/agilityhub/core/configuration/S04ErrorContractTest.java:50` — The error-contract check omits both D2 PATCH routes listed in S04 §6. Consequently, `PATCH /members/{id}` still omits `INVALID_IBAN` and `PAYMENT_METHOD_NOT_AVAILABLE`, while `PATCH /dogs/{id}` omits document errors such as `DOCUMENT_TYPE_UNKNOWN` and `FILE_NOT_FOUND`. Step 9’s “complete S04 error lists” claim is incomplete. Add both handlers to the comparison, update their annotations, and regenerate the snapshot.

5. **minor** `src/test/java/com/agilityhub/core/clubs/dashboard/api/DashboardIT.java:182` — T-14-22 still does not verify class-data tenant isolation. Members and dogs are persisted, but class occupancy is supplied by tenant-specific Mockito stubs. The test would pass if the production class query leaked another club’s sessions. Step 11 explicitly strengthens this acceptance row. Seed actual sessions in both clubs and exercise the real occupancy adapter through `/dashboard`.
