## Findings

1. **minor** `src/main/java/com/agilityhub/core/platform/application/definition/PlatformDefinitionSchema.java:73` — **The field name is wrong for unknown properties.**
   - **What happens:** only `required` errors get `error.getProperty()` added to the path. For `additionalProperties` (and a failed root `oneOf`), networknt 1.5.9 reports the *parent* location.
   - **Effect:** the schema root has `"additionalProperties": false` (`seeds/club-definition.schema.json:477`), and `accounts` was removed from its properties. So a console body carrying `accounts` (seed passwords) gets `{"field":"","code":"INVALID_VALUE"}`, an empty field name. An unknown `club.foo` is reported as `club`.
   - **Why it matters:** CONVENCIONS_API §6 says `fieldErrors` must name the offending field.
   - **Test gap:** `E10ContractIT.java:122-123` sends exactly that `accounts` body but checks only the code. I found this by reading the code; I did not run it.
   - **Fix:** also add the property for `additionalProperties`, `unevaluatedProperties` and `dependentRequired`, and assert `{field:"accounts"}`.

2. **minor** `PlatformClubsController.java:153` and `PlatformClubContracts.java:101-103` — **The contract now has two upload routes for the same logos.**
   - The working route is `POST /platform/clubs/{id}/theme/upload-url`, implemented by E10-T02 (no purpose, answers 201).
   - The new route is the stub `POST /platform/clubs/{clubId}/upload-url`, which always answers 501.
   - The `PlatformThemeRequest.*FileKey` descriptions now point only to the 501 route. A web client following the contract gets 501 while the undocumented route works.
   - `{clubId}` is also out of line with the `{id}` used by every other console route.
   - E108 asked for this exact path, so the executor complied, and the report defers consolidation to E10-T02.
   - **Suggested fix (organizer):** record which route survives. Meanwhile, mark the other `deprecated` in the OpenAPI.
   - Also tell E10-T02 that `AttachmentService.validate` only knows the purpose `CLUB_LOGO`. The new purposes `LOGO`/`LOGO_DARK`/`MARK` will need a mapping when the stub is implemented.

   The same applies at nit level to `T_17_10_R_17_12_clubPageReturnsTheAppliedUniversalFilters` and `…PublishesAppliedFiltersLikeListPage`: they assert CONVENCIONS_API §4, not R‑17‑12.

4. **minor** `PlatformClubMapper.java:35` — **The TXT challenge always reads `null` and has nowhere to be stored.**
   - `PlatformDomain.verification` is hard‑coded `null`.
   - `Club.Domain(host, app, status, verifiedAt, primary)` has no token, and MODEL_DADES_PLATAFORMA (`domains[] {host, app, verifiedAt}` plus status) has no challenge field.
   - The published contract promises a token "generated when the domain is added and stable until verified". That needs a persisted field the model does not have, and no model proposal was written (rule 2 / "the model wins").
   - Domain creation is still a 501 stub, so this is acceptable for a contract task.
   - **Fix:** add a MESSAGES entry proposing `domains[].verificationToken` (or similar) so E10-T02 doesn't invent it silently.

5. **minor** `PlatformClubMapper.java:21` — **`accountIdMasked` will always be null in practice.**
   - It reads `accountId` from the stored STRIPE settings, but no code ever writes that key.
   - `PlatformProviders.update` removes it (`PlatformProviders.java:58`), and `test()` saves only `lastTestAt`. No club‑definition path writes it either.
   - Only `T_17_05_R_17_05_providerReadsAndWritesProjectOnlyNonSecretSettings` seeds it, directly into Mongo, so the test passes on a state production never reaches.
   - **Fix:** either have the Stripe test persist the account id from `ping()` (E10-T02) or document "null until …" in the schema, and note it in the handoff.

6. **nit** `PlatformDefinitionSchema.java:68` — **Two codes for "missing field".**
   - These errors use `MISSING_REQUIRED`, but the rest of the codebase uses `REQUIRED` for the same meaning (`ActivityRules.java:38-43`, `MemberService.java:96`, `SignupService.java:631`), so clients must map both.
   - E108 named `MISSING_REQUIRED` "from the catalog", but no catalog lists field‑level codes.
   - **Fix (organizer):** pin the canonical field‑code list in CONVENCIONS_API §6.

7. **nit** `PlatformClubsController.java:200-203` — **The PUT response is read outside the write's transaction.**
   - `providers.update(...)` commits first, then `queries.get(id)` reads in a separate step.
   - A concurrent write between the two would be returned as this PUT's result. Low impact; returning the projection from the saved club inside `update` would avoid it.
