# Review E5-T29 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/platform/application/jobs/JobAdminService.java:116` — Suspending the request transaction lets the job and its audit commit before the idempotency response. If response persistence or the outer commit then fails, `IdempotencyFilter` abandons the key (`:220–223`), while the completed job remains committed. Retrying that key starts another run and returns different `runId`/counters. This breaks the replay guarantee in `CONVENCIONS_API.md` §7; the new test covers only successful persistence. Persist a durable association between the key and the job run, and recover that run on retry. Add failure injection after job completion but before response persistence.

2. **minor** `src/main/java/com/agilityhub/core/clubs/training/api/TrainingController.java:191` — The export advertises `endsAt`, `endsAtLocal` and `memberNumber` in `x-fields`, but `TrainingQueryService.COLUMNS` excludes all three. Consequently, `/training-bookings/export?format=xlsx&fields=endsAt,endsAtLocal,memberNumber` reaches an empty column selection and returns `400 INVALID_FILTER`; mixed selections silently omit them. This leaves the published export contract incomplete against `CONVENCIONS_API.md` §4. Add the appropriate export columns and test the generated file, beyond snapshot metadata.

3. **minor** `src/main/java/com/agilityhub/core/clubs/census/persistence/CensusListProjection.java:146` — Adding `owner.firstName` also changes the dogs export: `ExportValues.text()` concatenates every owner property, so the “Owner” cell now repeats the first name after the full name. The report acknowledges this regression but leaves it unresolved. Preserve the human-readable owner column required by S03 R-03-24 by explicitly rendering `owner.fullName`, with an export regression assertion.
