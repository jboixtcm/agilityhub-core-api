# Review E3-T12 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/census/application/SignupNotifications.java:46` — The allowance is consumed before its decision is persisted. If `admissions.decide()` fails without saving, the retry finds no decision and charges the same bucket again. With cap 1, it records a refusal and completes without sending. This leaves step 2’s delivery-loss defect unresolved for admission-write failures. Make accounting and persistence failure-safe so retries retain the original decision; add a regression test that fails the admission insert before retrying.

2. **major** `src/main/java/com/agilityhub/core/clubs/census/application/SignupNotifications.java:26` — The one-day TTL can delete an admission while its event remains pending. The maximum attempt count and backoff do not bound elapsed time during an API outage or dispatch backlog; pending outbox records have no expiry. After deletion, another event can consume the allowance before the admitted event retries, causing silent loss again. Round 2 explicitly requires persistence **until delivery completes**. Start retention after terminal completion, and test recovery after more than one day with a competing event.

3. **minor** `src/main/java/com/agilityhub/core/clubs/signup/application/SignupPolicy.java:161` — `catalogs.at(submitted)` does not necessarily recover the price known at submission. S05 R-05-16 and `PriceService.create()` allow a replacement price backdated within the current unbilled month. For example, an older January 17 snapshot charged €30 against a €60 price; a January 18 replacement of €30 effective January 1 makes this fallback return `FULL` instead of `HALF`. This violates R-04-15 and round 2’s historical-value requirement. Use evidence of the original price, or return `null` when it cannot be established; test a backdated replacement.
