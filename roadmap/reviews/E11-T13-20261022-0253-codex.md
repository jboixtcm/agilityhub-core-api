# Review E11-T13 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/clubs/census/application/SignupService.java:633` — A twinned own plan can bypass rejection when filtering it leaves the public offer empty. `ownPlan()` returns null, the required-plan check at line 636 is skipped, `policy.require(null)` accepts the empty offer, and `requireAddDogQuotable(..., null)` checks nothing. An otherwise valid add-dog submission consequently creates the dog and `SignupSubmitted` with a zero quote. This violates round 2 item 2’s required-plan refusal with nothing written. Distinguish an offer emptied by twins from a genuinely planless club, and add a regression test where the member’s twinned plan is the only offered plan.

2. **major** `src/main/java/com/agilityhub/core/clubs/signup/application/SignupPolicy.java:89` — Overlap detection always checks `today()`, although D2’s `validationQuote()` prices against each dog’s submission date (`SignupService.java:829`). If a newly selected plan had two prices valid on that date but only one valid today, the guard passes; `quote()` uses `assignable(date)`, which still selects the first twin. A D2 plan change can therefore preview and persist an arbitrary historical price, contrary to R-05-15 and E138. Check overlap at the date actually used for each quote, and test a D2 plan change with historical twins that are no longer overlapping today.
