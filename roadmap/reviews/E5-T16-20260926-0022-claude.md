## Findings
1. **minor** `src/main/java/com/agilityhub/core/platform/domain/CountryProfile.java:409-413`, used by `ClubSettingsService.java:73-74` and `ClubDefinitionWriter.java:112`: a tax id made only of separators now quietly clears the stored tax id under `ES`.
   - **What happens.** `PUT /club {taxId: "-"}` (or `" / "`, `"."`) normalizes to `null`, so the profile check is skipped. `Club`'s constructor then stores `null`, and the request answers 200. Before this change the old guard was `!taxId.isBlank()`, so `"-"` went to `validateTaxId` and got `400 VALIDATION_ERROR`. `club:apply` behaves the same way.
   - **Why it matters.** Assumption 1 only covers `""`. R-02-06 / S02 §3 say the profile checks a tax id the request changes, and the Cànic's tax id is the one the LSSI footer shows (R-02-02). A stray punctuation value now erases it without any error.
   - **Fix.** Refuse a value that is not blank but normalizes to `null`: `VALIDATION_ERROR` with `field = taxId` (or `club.taxId`). Keep `""` / `null` as the explicit way to clear. Add one line to the R-02-06 tests.

   - **Fix (optional).** Document it, or let a profile hook canonicalize the stored form.
