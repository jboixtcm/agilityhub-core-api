# Review E8-T01 (round 2, commit 5ca908d) — minor issues

All eight round-2 points are addressed, and each comes with a test that the before-the-fix logs `12`–`14` show failing when its fix is reverted:

- **Point 1 (guards before stubs):** `POST /checkout-sessions` with `bookingId`/`upfrontPaymentIds` runs `CheckoutService.authorize` and `checkoutReferences` before the stub; the `/me/*` stubs resolve the caller's member first.
- **Point 2 (webhook signature):** the Stripe webhook checks the HMAC-SHA256 signature first, with the 5-minute tolerance, a constant-time compare and `v0` ignored.
- **Point 3:** `MeInactivityPeriod.version` is published.
- **Point 4:** `toMonth` is nullable, and the PATCH bodies keep field presence.
- **Point 5:** `BILLING_BANK_KEY` is the only bank key.
- **Points 6–8:** whitespace check, event catalog rows and leave-reason labels are done.

I found no blocker and no major. The remaining issues are small gaps in "referenced resources first", a deployment item that has no owner yet, and some weakened test assertions.

## Findings
1. **minor** `src/main/java/com/agilityhub/core/payments/api/PackBalancesController.java:56-59` and `src/main/java/com/agilityhub/core/clubs/census/api/LeaveController.java:156-157` — Some referenced resources are still not checked before the stub.
   - `POST /pack-balances` checks the member and dog, but not `planId`.
   - `POST /members/{id}/reactivation` checks the member, but not `planId`/`priceId`.
   - So another club's or an unknown plan/price gets `501` instead of `404`. Round 2 point 1 asked to "check every other 501 route of E8 for the same order: the authorization and the referenced resources first" (AGENTS rule 4).
   - **Fix:** add a tenant-scoped existence check for the plan and price, through `clubs.catalogs.application` for payments or a port for census. Add the two negative tests to `everyStubResolvesItsCallerAndItsReferencesBeforeTheStub`.
2. **minor** `deploy/compose.prod.yaml`, `deploy/.env.prod.example`, `deploy/local-proof.py`, `compose.yaml` — The new `BILLING_SECRETS_KEY` is not forwarded to Core anywhere outside `.env.example`, `application.yml` and `DEPLOY.md`.
   - Without it, every production Stripe webhook answers 401, which is safe but fails silently. The local stack cannot exercise the webhook either.
   - The executor flagged this (round-2 question 1) but left it without an owner.
   - **Fix:** the organizer assigns it explicitly (E11-T04 round 2 or an E8-T04 step), with a `local-proof.py` assertion like the one for `BILLING_BANK_KEY`.
3. **minor** `docs/specs/00-transversal/CATALEG_ESDEVENIMENTS.md` (`UpfrontPayment*` row) and `E8ResponseContractTest.WP_12_A_WP_13_A_eventsHaveExactlyTheS12AndS13PayloadFieldsAndEnvelope` — The row is the union of two emitters' payloads.
   - E3's `UpfrontPayments` and the `BillingEvent` fixture differ: the fixture's `UpfrontPaymentFailed {paymentId, bookingId, reason}` lacks `memberId`, `concept` and `provider`, which the row lists for all three events.
   - The new check only asserts payload ⊆ row. So despite the "Exactly" in its name, it cannot detect a row field the code does not send. Point 7 asked for the rows to follow "the payloads the code already publishes".
   - **Fix:** make the check two-way where a row maps to a single payload. Route the convergence of the `UpfrontPayment*` payloads to E8-T04 explicitly (executor's question 2).
4. **nit** `src/main/java/com/agilityhub/core/clubs/census/api/InactivityController.java:101,114`, `LeaveController.java:76` — The member PATCH and cancellation routes (`/me/inactivity-periods/{id}`, `/me/inactivity-periods/{id}/cancellation`, `/me/leave-requests/{id}/cancellation`) only call `ownPeriod`/`ownRequest`.
   - An erased member's write, which is possible under impersonation, reaches `501`. The two `/me` POSTs answer `409 MEMBER_ERASED` for the same caller (S14 §5).
   - **Fix:** call `mutableMe()` first, as the POSTs do.
5. **nit** `src/main/java/com/agilityhub/core/clubs/census/api/LifecycleRequests.java` (`MonthsPatch`) — The snapshot under-describes the PATCH bodies.
   - `version` has `@PositiveOrZero`, but the snapshot has no `minimum: 0`.
   - Unknown fields are rejected, but the schema does not say `additionalProperties: false`; only the description says it.
   - Web types and mocks generated from the snapshot will miss both.
6. **nit** `src/main/java/com/agilityhub/core/payments/api/BillingRequests.java:53` — The Javadoc on `StripeWebhookEvent` still says "only `id` and `type` are read before the signature is verified". Since round 2, nothing is read before the signature.
7. **nit** `src/test/java/com/agilityhub/core/configuration/E8ContractIT.java` (`T_12_16…`, `…theCheckoutExtensionsAuthorize…`, `…everyStubResolvesItsCaller…`) — These tests now drop `idempotency_records` from the "nothing written" comparison. Round 1's `T_12_16` included it, and step 9 says "no writes on any collection".
   - `IdempotencyFilter` abandons (deletes) the claim on every non-2xx answer, so the exclusion looks unnecessary.
   - **Fix:** put the collection back in the comparison, or explain why a record is left behind.
8. **nit** `src/test/java/com/agilityhub/core/migration/PlayoffMigrationIT.java:110` — `E85_withOnlyTheBillingBankKey…` is named after a ruling, not a spec id (AGENTS rule 5). Prefix it with the relevant T/R id, for example `T_18_04` or `R_12_12`.
