# Review E6-T03 — needs changes

## Findings

1. **major** `src/main/java/com/agilityhub/core/shared/api/IdempotencyFilter.java:161` — Concurrent task completions with distinct valid `Idempotency-Key` values bypass conflict retries. The route allowlist excludes `/tasks/{id}/completion`, so the filter opens an outer transaction at line 194; `FollowupTransactions.run()` then executes without retrying because a transaction is already active. If both requests read `PENDING`, the losing Mongo write conflict can produce **500**, instead of the **422 `TASK_ALREADY_DONE`** required by **S10 R-10-10 / T-10-25**. The existing completion concurrency test omits the header and therefore misses this path. Give completion its own retryable transaction with atomic idempotency recording, following the observations implementation, and add a deterministic overlapping-request test using distinct keys that asserts one 200, one `TASK_ALREADY_DONE`, and one completion event.
