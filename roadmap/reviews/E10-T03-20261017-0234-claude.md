# Review E10-T03: minor issues

## Findings

1. **major** `src/main/java/com/agilityhub/core/platform/application/PlatformDomains.java:160-171` + `persistence/JndiDomainDns.java:26-50`: the re-check treats a failed lookup the same as a lost record. `JndiDomainDns` returns `[]` for every `NamingException` (timeout, SERVFAIL, no network) and for `UnknownHostException`. `recheckPlan` then counts that as `FAILED`. Three such checks make the domain `BROKEN`. As built (E10-T04 plus this task), `BROKEN` means tenant resolution and Caddy's `ask` refuse the host, so the whole club goes offline, not just a notice. Two realistic production cases:
   - (a) The core's resolver fails, or the product host itself resolves to nothing (`dns.addresses(target)` is empty). Every apex domain of every club then fails at the same time.
   - (b) Domains created as `VERIFIED` by `club:apply` with `trustedDomains` were never checked against DNS. The Cànic's `app.`/`admin.agilitycanic.cat` (`seeds/club-canic.yaml:23`) run with the product default `platform.domainRecheckDays = 7`. If those hosts don't point at the droplet yet (before the ADR-008 cutover, or staging with a different `CLUBS_HOST`), P9 makes them `BROKEN` about 3 weeks after the apply.

   R-17-03 asks for «avís a plataforma» after 3 failures; it does not ask for an automatic take-down caused by our own resolver. Suggested fix:
   - Let `DomainDns` tell "answered, no matching record" (NXDOMAIN or a wrong record) apart from "lookup error".
   - Record a lookup error as `SKIPPED` and don't count it. Do the same when the product host's own address lookup is empty.
   - Add a step to the `DEPLOY.md` runbook for trusted domains: verify them, or set `platform.domainRecheckDays: 0`, until the DNS cutover.
   - Add a test where the resolver errors and the domain stays `VERIFIED`.

2. **minor (needs organizer decision)** `PlatformDomains.java:120`, `PlatformClubContracts.java:97`, `docs/specs/S17-consola-de-clubs.md:56`, `docs/specs/S15-processos-programats.md:205`: `ADDRESS` is a third verification method. R-17-03 allows only (a) a CNAME or (b) the TXT challenge. The executor added `ADDRESS` to the public contract (`DomainVerification.method`) and wrote it, plus the new R-15-19 row, the new counters and the `BROKEN` semantics, into the api's spec copies itself. It is reported (Q2, Q3, Q5), but it is a rule change, not an implementation detail.
   - Also, `ADDRESS` proves the host routes to the platform, not who owns it. That is acceptable only because the domain was verified once before.
   - The organizer should approve it explicitly and sync the Dropbox specs (S15 R-15-19, S17 R-17-03, event catalog payloads, model §2 `checkedAt`/`failedChecks`), or ask for a different proof.

3. **minor** `src/main/java/com/agilityhub/core/platform/persistence/ClubRepository.java:129-139`: a console write can overwrite the re-check state. `recordDomainCheck` deliberately leaves the club's `@Version` alone. A console write that read the club before the P9 check still passes its version check, and `updateDomains` replaces the whole `domains[]` array. That restores the old `checkedAt`/`failedChecks`. If `checkedAt` goes back, the domain is due again the next day, so failures can pile up daily instead of weekly. Suggested fix: when a console write builds its `domains[]`, copy `checkedAt`/`failedChecks` from the stored document (read inside the write's transaction). Or have console domain writes `$set` only the fields they own.

4. **minor** (report, Assumptions: «A status change that races a console write gives the item `STALE_VERSION`: the run ends PARTIAL and the next day retries it») is claimed but not tested. No test makes `recheck()` hit `STALE_VERSION` and asserts a PARTIAL run with the domain left due. Add one to `DomainRecheckIT`, or drop the claim.

5. **minor (scope)** The E123 note says «A `BROKEN` domain that is not the primary can be removed». It was deliberately not done here and handed to E10-T04 round 2 (report Q1). Until then, `DELETE` of a `BROKEN` domain still answers `409 INVALID_STATE`. The organizer should confirm that E10-T04's round-2 list owns it, so the rule doesn't fall between the two tasks.

6. **nit** `PlatformDomains.java:194-195`: `RESTORED` overwrites `verifiedAt` with the re-check instant, so the original verification date is lost. The model doesn't define this. Either keep `verifiedAt` and rely on `checkedAt`, or document the choice in model §2.

7. **nit** `identity/application/DemoPlatformAccountsSeeder.java:43`: the seed account is created with `Account.Source.CONSOLE`. It doesn't come from the console. This is harmless locally, but the createdSource of a seeded account is misleading in exports.
