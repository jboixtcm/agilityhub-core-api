# E1-T08 · Learn adapter (Laravel repo agilityhub-api): login/register/reset sync to AgilityHub ID behind a feature flag

## Objective
Work package WP-01-E (Learn part), phase 1 «invisible»: Learn keeps its own login, but every successful login/registration/password reset also syncs the account (email, name, bcrypt hash) into AgilityHub ID through the confidential `learn` client. **Runs in the Learn repository** (`agilityhub-api`, Laravel 10) — a separate change set, not deployed until Jordi says so.

## Spec references
S01 R-01-12, §14 (verified Learn code: `AuthService::login`, `UsersService::store/update`, `ResetPasswordController`, `prod-sync/DEPLOY.md`) · `docs/specs/S19-integracio-learn.md` §14 · ADR-010.

## Context to load
S01 §14 · S19 §14 · this file · in the Learn repo: `app/Http/Api/Auth/Services/AuthService.php`, `app/Http/Api/Users/Services/UsersService.php`, the reset-password controller, `config/services.php`, `.env.example`.

## Steps
1. Config `services.agilityhub_id` (`base_url`, `client_id = learn`, `client_secret` from env, flag `AGILITYHUB_ID_SYNC=false` by default).
2. `AgilityHubIdClient` (Guzzle): `POST /platform/accounts {email, name, locale, passwordHash}` and `PUT /accounts/{id}/password {passwordHash}` with a client-credentials token (scope `accounts:write`), 3 s timeout, **fire-and-forget** through a queued job (`SyncAccountToAgilityHubId`) so Learn's login latency does not change; failures logged, never surfaced to the user.
3. Hooks: after successful `AuthService::login` (only the first time per user: nullable column `agilityhub_account_id` added by migration), after `UsersService::store` (registration), after password reset/update. Never log the password or the hash.
4. Tests (Pest/PHPUnit) with the HTTP client faked: each hook dispatches the job with the right payload; flag off → nothing dispatched.
5. Runbook note: enable with the flag, rollback = flag off; follows `prod-sync/DEPLOY.md`.

Change set ready in the Learn repo (branch, not deployed), flag off by default, tests green, no hash/password in logs.
