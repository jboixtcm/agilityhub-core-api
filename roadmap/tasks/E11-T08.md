**INC-68: the reads I found.**
- Typed reads through `Price` and `PriceRules`: `PriceRepository.forPlan` (Mongo sort on `concept, validFrom, id`); `PriceRepository.current` → `PriceResolver.current`, the price billing uses for a date (in Java, `PriceRules.status`); `PriceService` (overlap, open price, locked edits); `OfferViews` (status); `CatalogSeeds` (seed match on `validFrom.toString()` and the clone source).
- Index: the unique partial index `price_start` (`clubId, planId, concept, validFrom`). Before the fix it saw a date start and a string start as two different keys.
- Raw-document reads:
  - `PlayoffPlanner` (`businessDate`, which read a BSON date **as UTC**, so with a writer JVM east of UTC it was a day early);
  - `DemoSeedService` (`validTo == null`);
  - `PlatformCatalogClone` (string compare, but it reads typed rows from `CatalogSeeds`);
  - `CatalogMigrationProjection.rows("prices")`, `MongoOfferUsage`, `CensusReferences.price` (these do not compare the dates).
- With one stored type, every one of these sees strings.

**INC-68: how existing documents are converted.**
- `CatalogPersistence` runs `PriceRepository.normaliseValidityDates()` at every start.
- It finds the prices whose `validFrom` or `validTo` is a BSON date and sets both to `YYYY-MM-DD`. The day is read with the JVM zone, which is how Spring Data's `LocalDate → Date` converter wrote it.
- The filter repeats `_id`, `clubId` and the old values, so a concurrent edit wins. `clubId` also lets `TenantWriteTracking` register the tenant for the reset fence (R-18-17).
- If the converted start would duplicate another price's start, the document stays a date (it reads the same through the converter) and is logged by id only.
- It is idempotent: the second run converts 0 (tested).
- Seeds need no change: they go through `PriceRepository`, which now writes strings.
