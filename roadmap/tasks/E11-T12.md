# E11-T12 · The E11 gate run (api)

## Objective
E11-T06 closed the api's E11 security gate on 17-10's `main` (ruling E130), and its verification asked for one more run of the heavy proofs on the final code before E11 closes. Since then the correction passes E11-T08…T11 and E11-T13 and the upgrade E11-T07 changed the code. This task gives the organizer and Jordi fresh evidence on the current `main`, before the launch rehearsal of 25-10: it re-runs everything the E11 gate relies on and extracts which spec tests exist and pass.

**Change no product code, test, seed, script or document.**
- If something fails, report it exactly: the command, the exit code, the failing test or check with its message, and a reproduction. Then finish the run anyway.
- A defect found here is not yours to fix (ruling E72: a finding of a later round becomes an INC entry). Write it in `roadmap/MESSAGES.md` for `@organizer` with the reproduction; the organizer opens the incidence.
- Nothing here blocks: the task ends `awaiting_verification` with the evidence even if something is red.

## Steps
1. **Commit.** Record `git rev-parse HEAD` and `git log -1 --format='%H %ci %s'` at the start; every result below refers to that commit. Record `git status --porcelain` too: it must list only this task's files.
2. **Full build.** `./mvnw -q clean verify` under the host lock (`HEAVY_WAIT_MIN=25`, one run inside the evidence runner's one-hour deadline). Report the exit code and a test summary read from `target/surefire-reports` and `target/failsafe-reports`: the totals of each (tests, failures, errors, skipped), the JaCoCo gate and the `ArchitectureTest` rules, plus one line per test class whose name or methods contain `T_14_` or `INC_`.
3. **Traceability.** Copy `roadmap/evidence/E3-T07/trace.py` to `roadmap/evidence/E11-T12/trace.py` and widen it to every spec id (`T_\d{2}_\d{2}`). It writes `trace-tests.csv` (one row per spec id × test method: `specId, class, method, result`) and `trace-summary.md`: per spec S01…S18, how many ids have at least one test method and whether every one of them passes; for S14 §11 (T-14-01 … T-14-30) one line per id with its count, pass/fail or «missing» (and, for a missing one, whether the spec assigns it to the web or to a smoke).
4. **Every smoke.** `ls bin/*-smoke` is the list (today: `deploy-smoke`, `e1-smoke`, `e3-smoke`, `e3-signup-smoke`, `e4-smoke`, `e5-smoke`, `e6-smoke`, `e7-smoke`, `e8-smoke`, `e9-smoke`, `e10-smoke`, `oidc-smoke`, `test-e8-smoke`). Each one's docstring says whether it builds its own disposable Compose stack or needs the local stack running (`docker compose up -d --wait`, the seeds of step 5 applied, `SEED_PASSWORD` set and never printed). Run each one once, under the host lock, one log per smoke; `deploy-smoke` is step 9. Put each smoke's summary lines (its `PASS`/`FAIL` tail) in the report. The `FAILED:` lines that a smoke prints for its required negative checks are not failures: say which they are.
5. **Seeds twice.** On a fresh disposable Mongo (the pattern of `seeds_twice.py`), run twice each, in this order: `bin/core club:apply seeds/club-canic.yaml`, `bin/core club:apply seeds/club-template-default.yaml`, `bin/core seed:demo --club=canic --seed=42`. The second runs must say «0 changes». Exit codes and outputs in one log.
6. **Snapshot drift.** `bin/openapi-snapshot` (host lock): the committed `docs/openapi/openapi.json` must be byte-identical (`cmp`, sha256 before and after); otherwise list the diff per path and report it as a defect (step 11), never commit a regenerated snapshot.
7. **PITest on `clubs.bookings`, `identity` and `payments`.** The gate of E11-T06 step 8 on the current code, scored by `bin/mutation-gate --minimum-bookings 70 --minimum-identity 75 --minimum-payments 80` (assertion kills over all generated mutations, uncovered mutants in the denominator; the thresholds of E11-T03 and ruling E130). Two acceptable methods, say which you used:
   - a fresh run of the `mutation` profile over the three whole packages, cut into bounded batches as `roadmap/evidence/E11-T06/pit/README.md` describes (each batch inside the one-hour deadline, no history input), merged with `--xml` repeated;
   - E11-T06 session 11's delta method: mutate fresh only the classes of the three packages that changed since E11-T06's gate baseline `32a4f066` (`git diff --name-only 32a4f066 HEAD -- src/main/java/com/agilityhub/core/{clubs/bookings,identity,payments}`), splice them into `roadmap/evidence/E11-T06/pit/session11/gate-mutations.xml` with the same refusal rule (any other changed class refuses), and score the merged report.
   Report the per-package table (generated, killed, not killed, percent, threshold, passed). No survivor triage and no new test in this task: a package under its threshold is a defect for step 11.
8. **Security inventory.** `bin/security-inventory` (host lock) → exit 0: every published operation enforces its bearer requirement (`SecurityInventoryIT`), and the S12/S13 role × endpoint matrix (`E8ContractIT`). Report the operation count and compare it with E11-T06's (430): a difference is the new operations of E11-T08…T13, listed by path.
9. **Image and Compose proof.** `docker build -t ghcr.io/jboixtcm/agilityhub-core-api:e11-t12 .` (host lock; the image id in the report), then what CI's «Scan image (amd64)» job runs on it: `bin/security-scan image ghcr.io/jboixtcm/agilityhub-core-api:e11-t12` (no secret, no fixable CRITICAL; every active suppression named with its expiry) and `bin/deploy-smoke --image-tag e11-t12` (the full proof of `deploy/local-proof.py`, not `--security-only`: production Mongo wiring, Caddy HTTPS, branding by Host, backup and restore). Also the dependency audit CI runs: `python3 bin/security-scan-test.py` and `bin/security-scan rootfs target`.
10. **Gate lines.** For each item of `docs/PLA_DESENVOLUPAMENT.md` §11 that the api answers (CI tests green with the JaCoCo thresholds · tenant-isolation and module-off tests in every module · pain.008 golden file + XSD · Stripe in test mode with signed webhooks · backups with a proven restore · the security review: rate limits, headers, secrets, dependencies · `DEPLOY.md` with rollback), one line of evidence from this run (the log and the test or check that proves it). For the items that belong to the web, the release or Jordi (Lighthouse, es/en texts, the E2E flows, Josep's QA, legal documents, Twilio and e-mail in production, DNS and TLS, the D+7 plan) write «not this run: <who>». Add the same for the E11 list of `ROADMAP.md`: each E11 task with its status from `roadmap/STATUS.md`.
11. **Defects.** One table: what failed → command, exit code, message, reproduction → the `MESSAGES.md` entry that reports it. Nothing is fixed here.
12. **The evidence folder.** Trim nothing. Report `du -sh roadmap/evidence`, the ten largest files (`find roadmap/evidence -type f -printf '%s %p\n' | sort -n | tail -10`; on the Mac `find … -exec stat -f '%z %N' {} +`) and the per-task sizes above 20 MB (E11-T10 committed a 16 MB clean-verify log). Add one sentence on what this run adds. The organizer decides what to do with it.

## Fixed conventions
- No product change of any kind: no code, test, seed, script, document, catalog, snapshot or `ROADMAP.md` edit. A regenerated `docs/openapi/openapi.json` that differs is put back from the commit without a git write (`git show HEAD:docs/openapi/openapi.json > docs/openapi/openapi.json`, then `cmp`; say so in the report).
- Heavy runs (`clean verify`, PIT, the smokes, the image, the Compose proof) go through the host lock, each inside the evidence runner's one-hour deadline; a lock holder older than the session is recorded and waited for, never killed.
- Evidence logs are committed under `roadmap/evidence/E11-T12/NN-<name>.log` (`.gitignore` un-ignores `roadmap/evidence/E11-*/*.log`), tokens and secrets truncated, `SEED_PASSWORD` never printed. The task file stays ≤ 120 KB: each log keeps its last 40 lines in the report.
- Fictional data only. Do not rebase or merge by hand (ruling E131). Never edit other tasks or the Organizer verification section.
