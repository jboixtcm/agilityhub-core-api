# E0-T06 · Modules: @RequiresModule guard, dependency validation, MODULE_DISABLED

## Objective
Module gating for endpoints, services and schedulers, with the module catalog as the single source.

## Spec references
`docs/specs/S02-*.md` R-02-07 (T-02-09 back part) · `docs/specs/00-transversal/CATALEG_MODULS.md` (16 modules, dependencies, self-service flag) · `docs/decisions/ADR-012` · `docs/DECISIONS_PENDENTS.md` A23 (self-service modules: FAQ, PUSH, LEARN_LINK).

## Context to load
The documents above · `AGENTS.md` · this file.

## Steps
1. `Module` enum = the catalog (`dependsOn[]`, `selfService`, `defaultEnabled` per preset `MINIM` / `CANIC`); **contract test** parsing `CATALEG_MODULS.md` tables against the enum.
2. `@RequiresModule(Module.X)` on controllers or handler methods → a `HandlerInterceptor` (runs **before** body validation) that checks `ClubConfig.modules` and answers `404 MODULE_DISABLED` in the standard error shape; `ModuleGuard.require(clubId, module)` for services and schedulers (throws `ApiException(MODULE_DISABLED)`).
3. `ModuleDependencyValidator`: enabling a module without its dependencies → `422 MODULE_DEPENDENCY` (`details.missing[]`); disabling a module another enabled module depends on → `422 MODULE_DEPENDENCY` (`details.dependents[]`).
4. A test-only controller (`@Profile("test")`) `GET /api/v1/_test/module-guard` annotated with `@RequiresModule(FREE_TRAINING)` to exercise the interceptor.

## Verification (run all; paste full output in the report)
- `./mvnw -q verify` → green with `ModuleCatalogContractTest`, `RequiresModuleIT` (module on → 200; off → 404 with `{code: MODULE_DISABLED}`), `ModuleDependencyValidatorTest` (`PACKS` without `BILLING` → MODULE_DEPENDENCY; disabling `BILLING` with `PACKS` on → MODULE_DEPENDENCY listing `PACKS`).

## Definition of Done
Guard + validator + contract test green · no module name hard-coded outside the enum.

## Evidence to return
`verify` output; the list of modules loaded with their dependencies (print from a test).
