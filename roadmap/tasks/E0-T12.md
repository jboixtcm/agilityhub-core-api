# E0-T12 · OpenAPI 3.1 generation, committed snapshot and CI diff

## Objective
The API contract is a committed file that the front repo generates types from, and CI fails when the API changes without updating it.

## Spec references
`docs/specs/00-transversal/CONVENCIONS_API.md` §1–5 (base path, pagination, universal list contract, error shape, `x-filterable` extensions).

## Context to load
CONVENCIONS_API · this file.

## Steps
0. Alignment from E0-T11 (organizer, 06-09): remove the 365-day override of `security.eventRetentionDays` so the catalog default (90 days) applies; the parameter stays platform-editable.
1. springdoc: `/api/v1/openapi.json` in **OpenAPI 3.1**, title «AgilityHub Core API», `securitySchemes.bearer`, a shared `ApiError` schema attached to every 4xx/5xx response through an `OperationCustomizer`, tags per context, servers `https://core.agilitydoghub.com` and `http://localhost:8080`.
2. `OpenApiSnapshotTest`: boots the context, downloads the JSON, normalises it (sorted keys, no volatile fields) and writes `target/openapi.json`; `bin/openapi-snapshot` copies it to `docs/openapi/openapi.json`. CI (E0-T03) already diffs that file: an un-updated snapshot fails the build with the message «run bin/openapi-snapshot and review the diff».
3. `docs/openapi/CHANGELOG.md`: one line per endpoint change, maintained by hand in every PR that touches the API (start it with the endpoints existing today).

## Verification (run all; paste full output in the report)
- `./mvnw -q verify && bin/openapi-snapshot && git status --short docs/openapi` → clean on a second run.

- `jq '.components.schemas.ApiError' docs/openapi/openapi.json` → the four fields.
