## Steps
1. **E5-T08 review #1: the N-46 gate lives on the entry.**
   - The N-15 consumer records the delivery of an offer on the waitlist entry itself, in a field such as `offerNotifiedAt`.
   - It writes that field with a conditional update on `{state: NOTIFIED, notifiedAt}`, in the same transaction as the N-15 rows.
   - N-46 reads that field instead of querying `notifications`.

   Test both orders:
   - the offer is delivered, then the seat is taken → N-46;
   - the seat is taken before the N-15 consumer runs → neither a late N-15 nor N-46.
2. **E5-T08 #2.** A `SeatHoldReleased` that does not come from a confirmation (a hold that expires or is released) sends no N-46 and changes nothing. Test.
3. **E5-T08 #3.** `CensusRepository.save` fails fast when a `@ForeignOwned` field differs from the stored value, so that a future writer cannot lose it silently. Test.
4. **E5-T08 #4 (T-07-15).** Add the reported case: an impersonated (`BACKOFFICE`) waitlisted registration is promoted. Assert that N-32b goes to APP only and that the payload has `origin = SYSTEM`.
5. **E5-T08 #5.**
   - Use `DomainEvent.Origin.SYSTEM` instead of the string literal.
   - Make the envelope origin of a promotion `SYSTEM` as well, or say in the report why the envelope must keep the actor.
6. **E5-T08 #6: one rule for the keyed public routes.**
   - Remove `CLUB_NOT_FOUND` from the `@ContractErrors` of the keyed public activities routes.
   - Apply the same key-first rule (`403 INVALID_API_KEY` before the club is resolved) to every keyed public route: the S05 R-05-21 plans and the club pages.
   - Add tests per route; update the OpenAPI snapshot and `docs/openapi/CHANGELOG.md`.
7. **Ruling E29: `Level.progression`.**
   - **The field.** Add `progression` (boolean) to `Level`, to its create and patch inputs, and to the D11 API (S05 §3). It is required in the resource. It defaults to `true` on create, and existing levels read as `true`. The seed sets Teràpia (`TER`) to `false`.
   - **The rule (R-06-03).** The «{first} i sup.» form applies only to a contiguous run of **active progression levels** that reaches the last active progression level and has at least 2 levels. Any set that includes a non-progression level is joined with «+».
   - **Tests:**
     - T-06-02 with the catalog Cadells…G + Teràpia: {D,E,F,G} → «D i sup.»; {G,Teràpia} → «G+Teràpia»; the es and en forms;
     - the seed test;
     - a D11 API test: patch `progression`; `LevelChanged` carries the diff.
   - Update the OpenAPI snapshot and its CHANGELOG. The web adopts the field in E4-W06.
