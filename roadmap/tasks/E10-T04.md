### Assumptions
- **Removal (S17 §5):** only a `PENDING` domain is removed (`PENDING --> [*]`); `VERIFIED`/`BROKEN` → `409 INVALID_STATE {status}`. See question 1.
- **Make primary:** step 1 asks for it and §6 has no route, so `PUT /platform/clubs/{id}/domains/{host}/primary` is added. It has no body and answers every domain. Only a `VERIFIED` domain can be primary. Adding a domain never makes it primary. The first verified domain of an app becomes its primary one, so `ClubAppUrls`/`ClubEmailSettings` (verified first, primary first) keep working.
- **Verification:** the CNAME target is the product host of the domain's app, from the existing deployment variables `CLUBS_HOST`/`ADMIN_HOST`, published as `verification.cnameTarget`. A verified domain has no token left (E112), so re-verifying it is `409 INVALID_STATE`. `BROKEN` is in the enum but nothing sets it yet: the weekly re-check is S15 P9, optional in §13 and not in this task. Without a token (a legacy or `club:apply`-trusted host), only the CNAME works. Tokens are generated for pending hosts created by `POST /platform/clubs` too. A re-apply keeps them, so the definition diff stays empty (the export never carries them).
- **Write concurrency:** the domain routes carry no `version` (the published request has none). They use the club version read in their transaction (`409 STALE_VERSION` on a race), and a host taken by another club meanwhile hits the unique index (`409 HOST_ALREADY_USED`).
- **Support token:** `sub` = the platform account, `aud` `clubs-admin`, no refresh token, no `platformRoles` (so no console route), `jti` = the grant. The contract stays `{token, expiresAt}`: no handoff code. Revocable by its actor (`/oauth2/revoke`, the banner's «Surt») and at once by removing the platform role or blocking the account. The club sees each access in its own audit. A support access into a `SUSPENDED` club is allowed (it is the platform's tool), and every other club rule still applies. Events keep `origin = BACKOFFICE`: `DomainEvent.Origin` is the events catalog's and it has no `PLATFORM_SUPPORT`. Only the audit origin is new (S14 §3, required by R-17-10).
- **Restricted routes** (`SupportAccessService.RESTRICTED`): every `…/export` list export, `/exports/**`, `/billing/exports`, the two `data-export` routes, `/remittances/{id}/file` and `/remittances/files/**`, the member impersonation, and the platform account's own `/me` writes, password, sessions and onboarding. IBANs are masked on every other route already (R-03-27, R-17-05).
- **Public key:** the replaced key's digest is kept in `publicApiKeyPreviousHash` until `publicApiKeyPreviousUntil` (model Annex B, proposal below). A second rotation inside the 24 hours ends the older key at once.
- **Idempotency:** the support token and the public key are answers that a lost response would leave unknown, so they are replayed. They are stored sealed with the same AES-GCM sealing the anonymous signup answers use (`SignupCapabilities`, a key required in staging/prod). INC-49's rows are scoped to the path's club. Each row call opens that club only when it is not the one already open: the handler opens the club itself and may open another one (a clone's source), and `TenantContext` refuses a nested different club.
- **E115 #1:** the fix covers `signupLegal`'s readers. `GET /signup` answers with `legal {privacyPolicyUrl: null, legalTextsVersion: null}`. A submission to such a club still needs a legal version to accept. I did not change the consent check (S04's).
- **E118 #2:** the product hosts are the existing `core.security.cors.platform-hosts` (`CORS_PLATFORM_HOSTS`). The product branding comes from `platform/product-branding.json`: the template club's AgilityHub preset, `ca/es/en`, default `ca`, `GENERIC` profile, `Europe/Madrid`, `EUR`. Only `/branding` opens there, not the manifest.
- **Catalogs:** no new parameter, event, notification or error code. The three audit actions and the `PLATFORM_SUPPORT` origin are entered in S14 in this commit (E109). `LOCALE_OMITTED`/`DEFAULT_LOCALE_COPIED` are response warning codes defined in S17 R-17-08, not errors.
- The model, S14 and S17 edits are in the api's copy of `docs/`.
