### Rules and tests implemented
1. **R-18-03 / T-18-03, point 1:** an exclusive ten-minute infrastructure lease is renewed/fenced at both ends of every census/billing/completion/failure transaction. A new owner marks abandoned RUNNING runs FAILED and restarts from source IDs; completed invoices/packs retain their existing idempotency. `T_18_03_point1_crashAfterCommittedBillingBatchCanRestartWithoutDuplicates` interrupts after 100 committed receipts, observes RUNNING, restarts to exactly 103 without changing the first 100, and still refuses a second completed production load. `T_18_03_point1_liveOwnerAndExpiredOwnerAreFencedPerTenant` covers live-owner refusal, separate tenants, expired-owner takeover, stale release and reset refusal during a live lease. `T_18_03_point1_expiryDuringBatchRollsBackAndCannotMarkTheRunFailed` covers post-write fencing and retry after a rolled-back batch.
2. **R-18-14 / T-18-16, point 2:** the production checkpoint is committed together with completion/audit/outbox. Reset compares the monotonic counter and deletes while holding the same Mongo write lock used by audited/event-producing writers. The counter survives reset; timestamps are not used for ordering. `T_18_16_point2_sameMillisecondWriteRefusesReset` uses the real member edit without advancing the clock. `T_18_16_point2_writeBetweenGuardAndDeletionCannotBeSilentlyLost` interleaves an independent member transaction after the real guard; either the committed edit prevents reset or the writer explicitly loses the lock and rolls back. The original successful-reset and tenant-scoped RESET audit test remains.
3. **R-18-11 / R-18-14 / T-18-15, point 3:** `T_18_15_point3_changedFutureLeaveKeepsMemberAndDecisionTogether` checks member date, existing request ID, requested date, decision date, APPROVED state, unchanged second apply and no notification. `T_18_15_point3_removedFutureLeaveIsRejectedBeforeAnyWrite` checks the existing REEXECUTION_UNSUPPORTED report and the entire database snapshot.
4. **P10 / T-15-28, point 4:** `T_15_28_point4_monthEndReminderClampsConfiguredDayThroughP10` runs the real scheduled P10 for days 29/30/31 in ordinary February, 31 in leap February and 31 in April; exactly one event and N-41, no invoice, no duplicate on repeat.

### Assumptions
- Recovery safely restarts the import rather than preserving a crashed run's report counters. Existing source IDs, validations and transactional batches prevent duplicate business rows. No source content, personal data, credential or fingerprint is persisted in the lease/counter.
