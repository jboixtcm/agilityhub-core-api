## Steps
1. **The security inventory, and INC-45's global check.**
   - In the report, one table of every route family: public, `/oauth2/*` and `/.well-known/*`, `/api/v1/auth/*`, `/me/*`, backoffice, `/platform/*`, `/internal/*`, webhooks, and the signed file routes.
   - For each family, give the authentication, the rate limit (its key and window), CORS, the idempotency key and the audit.
   - One test that walks every operation of the published OpenAPI and calls it without a token. It gets `401` exactly where the operation publishes a bearer requirement. `/oauth2/token` is the exception: it answers `401` for the client's authentication.
   - This closes INC-45.
2. **Rate limits on every anonymous route that writes, sends or looks something up** (PLA_BACKEND §3).
   - `RateLimitFilter` covers the token, the branding, `/public`, `/me`, the magic link and the signup routes today. Close the gaps that step 1 finds. Examples to check: `POST /email-unsubscribes`, `POST /auth/handoff`, and every other anonymous route of the inventory.
   - Limit by IP and, where the request names one, by account or e-mail.
   - Every refusal answers `429 RATE_LIMITED` with `Retry-After` and records a `SecurityEvent`, as today's limits do.
   - The values come from `core.security.rate-limits`, with a line for each in DEPLOY.md.
   - These routes already publish their `429`, so the contract does not change.
   - Test each new limit: at the limit → `429` with `Retry-After`; after the window → it passes again.
3. **The security headers, proven on real responses.**
   - One test per response family (JSON, the token endpoint, errors, file downloads, the OpenAPI and health) that asserts the headers:
     - `X-Content-Type-Options: nosniff`, `Referrer-Policy` and `frame-ancestors 'none'` (or `X-Frame-Options: DENY`) everywhere;
     - the API's CSP;
     - HSTS only in production;
     - `Cache-Control: no-store` on authenticated answers and on the token endpoint;
     - the files' headers of E71: `sandbox` except on inline PDFs, SVG as an attachment.
   - Fix what is missing.
   - The SPAs' headers are Caddy's (`deploy/Caddyfile`, E11-T04): add the same baseline there (`nosniff`, `Referrer-Policy`, `frame-ancestors`, HSTS). The SPAs' CSP is the web's, not this task's.
4. **CORS per club, proven.** Test `ClubCorsConfigurationSource` through real preflight and credentialed requests:
   - a club's own host and its platform subdomain are allowed;
   - another club's host and an unknown origin get no `Access-Control-Allow-Origin`;
   - no wildcard origin ever goes with credentials;
   - `/oauth2/*`, `/.well-known/*` and the health probe behave as documented.
   Fix what is wrong, and write the rule in DEPLOY.md.
5. **Structured logs and Sentry (R-14-18, INC-40).**
   - Production logs are JSON (Spring Boot's structured logging), with `traceId`, `clubId` and `accountId` in the MDC from one filter at the start of each request. `traceId` is the same id that `INTERNAL_ERROR` returns. Local development keeps the readable format.
   - Logs never hold an e-mail, a phone number, an IBAN or a request body: one exclusion list in one place.
   - Test: a request carrying all four → the captured output has none, and has the three ids.
   - Sentry:
     - the Spring Boot starter, off when `SENTRY_DSN` is empty;
     - `send-default-pii: false`;
     - a `beforeSend` that scrubs e-mails, phone numbers and IP addresses;
     - a test of the scrub;
     - `SENTRY_DSN` in DEPLOY.md's variable table (the account is the release's, E12-T01).
   - This closes INC-40's `traceId` point.
6. **Mongo client timeouts.**
   - Set `connectTimeoutMS`, `socketTimeoutMS` (or the client-side `timeoutMS`), `serverSelectionTimeoutMS`, the pool size and its wait timeout, all from configuration and all in DEPLOY.md. Keep `TransactionRetries` working inside them.
   - Test with the Testcontainers Mongo paused:
     - `GET /api/v1/health` reports `DOWN` within the server-selection timeout;
     - an API read answers an error within its bound and never hangs;
     - after the container resumes, both recover.
7. **CI: the image scan, the dependency audit and a compose smoke** (pin every new action by SHA, as the workflow does).
   - **The image:** before the image is pushed, scan it for secrets and for vulnerabilities (Trivy or equivalent). A secret fails the build; so does a CRITICAL vulnerability that has a fixed version. The rest goes to the job summary.

### E85: request budgets and legitimate long operations

The Mongo driver's client-level CSOT is inherited by transaction sessions. A 10-second client value therefore capped a full seed transaction, not only a single query; the organizer observed this on CI. The client no longer sets CSOT, and startup rejects a URI/client `timeoutMS` that would silently reintroduce it. A servlet filter supplies the configured budget to ordinary database operations and new transaction sessions. Session-bound operations own their deadline, including after-commit callbacks (the driver rejects a second database override in that session context). Background operations have no servlet budget, and the default background socket fallback is zero. Connect/server-selection/pool bounds remain finite. HTTP exports, data exports, export downloads, and both club/platform manual-job trigger paths now follow the background rule: neither database operations nor sessions receive an HTTP deadline. There is no finite replacement cap and no largest-run assumption. The scope is removed on success or failure; no domain writer or transaction retry rule changed.

`80-e85-before.log` fails on the old code: the background transaction expires and the export returns 500. `84-e85-regression.log` passes all five focused tests after the correction: a short request expires after its first write, all five long-route shapes finish and commit both writes, a background transaction outlives the short budget, and a subsequent background operation proves scope cleanup.
