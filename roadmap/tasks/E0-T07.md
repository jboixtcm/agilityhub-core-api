# E0-T07 · Audit base: @Audited aspect, AuditEntry, AuditDiff with masking, coverage contract test

## Objective
Work package WP-14-B (E0 part): the audit mechanism every later task reuses, with a contract test that forces every `AuditAction` to be covered by a test.

## Spec references
`docs/specs/S14-tauler-auditoria-exportacions-rgpd.md` §5 (AuditEntry, actions), R-14-09…R-14-11, tests **T-14-07** (AuditDiff masking) and **T-14-12** (AuditContractTest) · `docs/specs/00-transversal/MATRIU_PERMISOS.md`.

## Context to load
S14 §3–5, §9 · this file.

## Steps
1. `AuditEntry` (collection `audit_entries`, tenant; platform-level entries with `clubId = null`): `{ at, actorAccountId, actorName, actorRole, impersonatedMemberId?, support?, action (AuditAction), targetType, targetId, memberId?, changes[] {field, before, after}, ip, userAgent, traceId }`; indexes `{clubId, at desc}`, `{clubId, memberId, at desc}`, `{clubId, targetType, targetId}`. No Mongo TTL (retention purge is a later job).
2. `AuditAction` enum with the actions that exist so far (`PARAMETER_CHANGED`, `MODULE_CHANGED`, `CLUB_UPDATED`, `CLUB_APPLIED`, `LOGIN`, `LOGIN_FAILED`, …; take the names from S14 §5 — add only what E0 needs).
3. `@Audited(action = ..., target = "#result.id")` (SpEL for target id/type) + an aspect that writes the entry **after commit** (`TransactionSynchronization.afterCommit`, or immediately when no transaction is active) with `AuditDiff` computed from `@AuditField` annotated fields (before/after snapshots), `@Sensitive` fields masked («···· ···· ···· ···· 2231» keeps the last 4 chars — T-14-07); `AuditWriter.write(...)` for manual cases; `AuditQuery.lastChange(targetType, targetId)` returning `{at, actorName, action}`.
4. `AuditContractTest` (T-14-12): for **every** `AuditAction` constant there must be at least one test method annotated `@AuditCovers(action)` — the test scans the test classpath and fails listing the uncovered actions. Cover the E0 actions in this task (e.g. `PARAMETER_CHANGED` via a fake service).

### Assumptions
- Task step 3 explicitly wins over S14 R-14-09/R-14-10 for this E0 delivery: auditing is deferred to `afterCommit`, then persisted in `REQUIRES_NEW` to avoid reusing the completed Mongo transaction's still-bound session. Without an active transaction it is immediate. Audit failure after aggregate commit propagates but cannot roll the aggregate back; no durable retry queue is claimed. The organizer clarification is in MESSAGES.md.
- S14's action list is in §4 R-14-09, not §5. `CLUB_MODULES_CHANGED` replaces the task's illustrative `MODULE_CHANGED`; club apply can use `CLUB_UPDATED`. S14 explicitly excludes successful logins from audit and routes failed logins to SecurityEvent, so `LOGIN`, `LOGIN_FAILED` and `CLUB_APPLIED` were not invented.
- Follow the task's storage names `targetType`, `targetId`, `changes.field` and optional `support`, despite S14's `entityType`, `entityId`, `changes.path`. Include S14's optional `reason` to support meaningful manual/no-diff writes. No model/spec precedence was re-decided outside the allowed context.
- E0 scope is the reusable base and fake-service contract tests. S14's audit/export HTTP endpoints, retention job, additional S14 metadata and later verticals' actual mutation annotations remain outside this task's Steps. There are no new parameters, domain events, notifications or error codes.
- Reusable contracts live in `platform.application.audit`; field annotations live in `shared.domain.audit`, so other contexts can adopt them under the existing architecture rules. Mongo-mapped AuditEntry stays in persistence. Tenant writes use a private `TenantRepository` adapter; the append-only facade exposes no replacement/delete methods. Explicit platform operations never read across tenants.
- SpEL examples: `targetType = "'Parameter'", target = "#id"` uses a registered tenant-aware `AuditableLoader`; result-based creation uses `target = "#result.id"`. Existing mutable arguments can supply `before = "#p0"`. Nested object fields must opt in with `@AuditField`; annotated maps/arrays keep JSON values, and collection element changes use complete arrays per R-14-10. Every sensitive selected field must also carry `@Sensitive`; strings of four or fewer characters are hidden entirely to avoid revealing the complete secret.
- `AuditActorProvider` is the identity integration port because AuthContext is not implemented yet. The default adapter snapshots Spring Security/JWT identity and request trace; future identity work can adapt trusted claims through this port. No forwarded-IP header is trusted directly.
