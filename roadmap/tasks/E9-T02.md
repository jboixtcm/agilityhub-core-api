### Assumptions

- **Member course reads**: E9-T01's fixed conventions give «the rest of R-16-09/16 (visible ring, course a visible setup references)» to E9-T03. A MEMBER keeps tenant + `courses.showSetupToMembers` + R-16-03 here (a `PUBLIC` course is readable, a `CLUB` one is `COURSE_NOT_VISIBLE`).
- **Private club courses**: `PRIVATE` on a `CLUB` course means its creator only («Comparteix amb el club» shares it); an `ACCOUNT` course is `PRIVATE` or `PUBLIC`, never `CLUB` (`VALIDATION_ERROR`); the library is always `PUBLIC`.
- **Model rules**: `normalizedJson` is required for `SMARTER` and `EDITOR` (`COURSE_MODEL_INVALID {schemaErrors[{path: "$"}]}`), optional for `IMAGE` (which needs `imageFileKey`, `VALIDATION_ERROR fieldErrors[{imageFileKey, REQUIRED}]`) and inherited by `AGILITYHUB_COPY`, which only `copy-to-club` sets. `sourceFileKey` is not required for `SMARTER` (the library cannot upload). On a `PATCH` a null keeps the stored value, as elsewhere in the api.
- **Stats**: `obstacleCount` is the length of `obstacles`, `bbox` the design size, `pathLengthM` the polyline through the main sequence's numbered labels (`sequenceKey n1`, `sequenceNumber` ascending, to the centimetre). It reads course-core's output but is not course-core's own summary; see the question.
- **List**: the visible set (club + global, read without models) is filtered in memory with the engine's semantics, because the shared engine starts from the tenant's `$match`. `owner=MINE` is the caller's account courses. `level` joins the club levels' codes in catalog order with an en dash («A–B»), else the `agilityhubLevel`. `activeOnRings` are the rings whose active setup shows the course directly or through its placement. The platform list is the `AGILITYHUB` library only.
- **Deletes**: soft, at the stored version, refused while an active setup of the caller's club shows the course; for a global course only the caller's club can be checked. Duplicating needs write permission and keeps owner, visibility and file keys (the files stay bound to the original course).
- **Files**: course grants carry purpose `COURSE_{purpose}`, so no attachment route claims a course file nor a course an attachment. Mismatched, foreign, unknown or already-bound keys are `404 NOT_FOUND` (T-16-21); the upload URL's five minutes do not apply to the claim (as D2's documents). Types: `text/plain` only for `SMARTER_SOURCE`, `image/*` for `COURSE_IMAGE` and `THUMBNAIL`, `application/pdf` for `BUILD_SHEET`, always within `files.allowedTypes`. A library course cannot carry files (no tenant, no upload route).
- **Geometry frame and checks**: course-core's frame (origin bottom-left, x along `lengthM`), so NORTH/SOUTH doors run along `lengthM`, EAST/WEST along `widthM`; marker positions are not bounded (markers may stand outside the fence). A removed geometry starts again at version 0. Removal is audited, not published (`RingGeometryChanged` is «geometria desada»).
- **Inventories**: `GET ring:{ringId}` answers the effective inventory (its own, else the club's), its `scope` telling which; none → `404`. No `version` (S16 §6), so the last write wins on one document per scope.
- **Venue** (E9-T01 step 4: E9-T02 creates it): created insert-only on the club's first geometry save, with the club's slug, name and city, `indoorOutdoor = MIXED`, `visibility = MEMBERS_ONLY`, `partnerStatus = INACTIVE`, `defaultPaperSize = A4` (the country profile is not readable from `courses` across the context rule).
- **Calibrations** (§14.2, no R-xx owner): served here beside the geometry; the ring must exist, a geometry is not required.
- Events: `CourseImported` for a Smarter creation, `CourseCreated` otherwise, `CourseCopied` for duplicate and copy, `CourseUpdated{courseId, diff}` only when something changes (the model as `{before, after}` course versions, never its JSON), `CourseDeleted`, `RingGeometryChanged`, `InventoryChanged`; library events have `clubId = null`.

No operation added or removed.

Assumption meanwhile: the client renders it from the geometry.

4. **Member reads of a course a visible setup references** (R-16-16) and the MEMBER projection: E9-T03 with `RingSetupPort`, as E9-T01 assigned.
