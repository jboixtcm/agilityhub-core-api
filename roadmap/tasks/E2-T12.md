# E2-T12 · Club pages (ClubPage): rules, privacy, image consent, welcome guide — CRUD, publication, public read, seed (S05)

## Objective
The club edits its own texts (rules, privacy policy, image-rights clause, welcome guide, free pages) from D11 «Pàgines del club»; the student app «Info» (screen 30) and the public signup (screen 19 «Normes del club: consulta-les aquí») read them; consents record the page `version` they accepted (S04, E3).

## Spec references
S05 §6 rows `/club-pages*` and `/public/{clubSlug}/pages/{key}` (added 09-09), S05 change log 05-09 (`ClubPage` entity), R-05-21b (provisional texts marked «[Text pendent — el club l'omplirà des de Paràmetres]»), S11 change log 05-09 (screen 30 tabs FAQ · Normes · other active pages), S04 change log 05-09 (signup link, `pageVersion` in consents), `docs/MODEL_DADES_PLATAFORMA.md` §3 (`ClubPage`), CATALEG_ESDEVENIMENTS `ClubPageChanged` (added 09-09), S14 R-14-09 (`CATALOG_CHANGED`) · `docs/legal/NORMES_CLUB_PLANTILLA.md`, `docs/legal/AUTORITZACIO_IMATGE.md`, `docs/legal/POLITICA_PRIVACITAT_CLUB_PLANTILLA.md` (seed sources; drafts pending legal review).

## Context to load
S05 §6 (the three `club-pages` rows), the FAQ implementation of E2-T03 (`clubs/catalogs/*`: `CatalogService`, `@Audited(action = CATALOG_CHANGED)`, `LocalizedText`, `STALE_VERSION` handling), `PublicPlansController` (public `X-Api-Key` + `Accept-Language` pattern), `platform/application/definition/*` (`club:apply` definition codec) · this file.

## Steps
1. **Entity** `ClubPage` (tenant collection `club_pages`, unique `(clubId, key)`): `key` (`RULES · PRIVACY · IMAGE_CONSENT · WELCOME_GUIDE` or a free `[a-z0-9-]{2,40}` key), `title: LocalizedText`, `body: LocalizedText` (Markdown, **limited**: headings, paragraphs, bold/italic, lists, links — no raw HTML, no images; validate with the same limited-Markdown rule used for FAQ answers if one exists, else a small allow-list sanitizer; max 20 000 chars per locale), `version` (int, starts at 1), `publishedAt`, `active`, `lastChange`. Keep the previous published bodies in an embedded `history[]` (last 10 versions: `version, publishedAt, by`) so a consent that references `pageVersion` can be shown later (S04/S14).
2. **Endpoints** exactly as S05 §6: `GET /club-pages?active=` (MEMBER, INSTRUCTOR, ADMIN; members only see `active = true` regardless of the flag), `GET /club-pages/{key}`, `POST /club-pages` (ADMIN, 201; `key` already used → 409 `DUPLICATE_NAME` (the catalogs' conflict code) with `details.field = key`), `PATCH /club-pages/{key}` (ADMIN, `version` in the body → `STALE_VERSION`; `active: true` on a page that was inactive or a body change on an active page = **publication**: `version + 1`, `publishedAt = now`; editing the body of an inactive page does not bump the version), `GET /public/{clubSlug}/pages/{key}` (ANON with `X-Api-Key`, only `active` pages, `Accept-Language` picks the locale with the club fallback chain; 404 otherwise). Rate-limit the public route like `/public/{clubSlug}/plans`.
3. **Audit + event**: every `POST/PATCH` writes `CATALOG_CHANGED` (`entityType = ClubPage`, `entityId = key`, `details {version, active}`) inside the transaction and publishes `ClubPageChanged {key, version, active}` through the outbox.
4. **Seed (`club:apply`)**: optional `pages[]` section in the club definition (`key, title, body, active` per locale, or `bodyFile` relative to the definition for long texts); idempotent (no change → no write, no version bump). `seeds/club-canic.yaml` gets: `RULES` (ca body = the marker paragraph «[Text pendent — el club l'omplirà des de Paràmetres]» followed by the draft of `docs/legal/NORMES_CLUB_PLANTILLA.md`; es/en = marker only; `active = true`), `IMAGE_CONSENT` (the clause of `docs/legal/AUTORITZACIO_IMATGE.md` with the marker, `active = true`), `PRIVACY` (draft of `POLITICA_PRIVACITAT_CLUB_PLANTILLA.md` with the marker, **`active = false`** until the legal review). No `WELCOME_GUIDE` seed. The E12 exit check «no text with the marker in production» is a later task; here just keep the marker text as a constant in one place (`ProvisionalText.MARKER`).
5. **OpenAPI**: regenerate the snapshot (`docs/openapi/openapi.json`) + `docs/openapi/CHANGELOG.md` entry; the `ClubPage` schema must list `key, title, body, version, publishedAt, active, lastChange`.

## Fixed conventions

- No literals in code for user-facing texts: the seed bodies come from the definition files; API error messages through `messages_{locale}.properties`.
- Tests: `T-05-CP-01` CRUD + publication versioning (inactive edit keeps version; activation bumps; body edit on active bumps; `history` keeps 10), `T-05-CP-02` MEMBER sees only active pages / ADMIN sees all, `T-05-CP-03` public route with `X-Api-Key` + `Accept-Language` fallback + 404 for inactive, `T-05-CP-04` `STALE_VERSION`, Markdown/size validation, `T-05-CP-05` audit `CATALOG_CHANGED` + outbox `ClubPageChanged` in the same transaction, `T-05-CP-06` `club:apply` seeds the three pages idempotently (second run: 0 changes).
