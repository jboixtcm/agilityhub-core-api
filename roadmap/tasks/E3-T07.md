# E3-T07 · Gate E3 audit run (api)

## Objective
Jordi asked for an exhaustive review of gate E3 before he closes the stage. Codex and the organizer audit the code separately. This task gives them fresh evidence on the current `main`: it re-runs everything the E3 gate relies on, and it extracts which spec tests exist and pass.

**Change no product code, test or seed.**
- If something fails, report it exactly: the command, the exit code, and the failing test with its message. Then finish the report anyway.
- Nothing here blocks: set `awaiting_verification` at the end.

## Spec references
- S04 §11 (T-04-01 … T-04-34).
- S14 §11: T-14-01 … T-14-06, T-14-11, T-14-22, T-14-23 and T-14-25.
- `roadmap/ROADMAP.md`, section «Gate E3 (back)».

## Steps
1. **Commit.** At the start, record `git rev-parse HEAD` and `git log -1 --format='%H %ci %s'`. Every result below refers to that commit.
2. **Full build.** Run `./mvnw -q clean verify`. Report the exit code and a test summary: the totals, plus one line per test class whose name or methods contain `T_04_` or `T_14_`.
3. **Traceability.**
   - Write a script `roadmap/evidence/E3-T07/trace.py`. It reads `target/surefire-reports` and `target/failsafe-reports` and writes `roadmap/evidence/E3-T07/trace-tests.csv`: one row per test method, with `specId, class, method, result`.
   - `specId` is each `T_04_nn` / `T_14_nn` in the method name. A method named `T_04_12_T_04_13_…` gives one row per id.
   - Then write `roadmap/evidence/E3-T07/trace-summary.md`. For every id of S04 §11 and every S14 id above: how many test methods it has, whether all of them pass, and «missing» when there is none.
4. **E3 smoke.** Run `bin/e3-smoke` twice on a fresh local stack. Commit both logs, and put the second run's summary table in the report.
5. **Seeds.** Run `bin/core club:apply seeds/club-canic.yaml` twice and `seed:demo --club=canic --seed=42` twice, as the smokes do. The second runs must say «0 changes».
6. **Snapshot drift.** Run `bin/openapi-snapshot`. The committed `docs/openapi/openapi.json` must be byte-identical (`cmp`); otherwise list the diff.
7. **Gate lines.** For each line of «Gate E3 (back)» in `roadmap/ROADMAP.md`, give one line of evidence from this run.
