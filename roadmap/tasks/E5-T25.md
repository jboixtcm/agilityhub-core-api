## Steps
1. **The booked dog on `Booking`.**
   - Every `Booking` that a MEMBER reads carries `dog`, a `HoldDog` (`id`, `name`, `sex`), as `SeatHoldResponse.dog` does. That covers `GET /bookings/{id}`, the `POST /bookings` answer and the cancellation answer.
   - Screen 07 writes «Classe {description} · amb la Duna»: the Catalan article depends on the sex.
2. **The in-time deadline on `Booking` (R-08-10).**
   - A MEMBER cannot read `/parameters`. Screen 07 still needs the threshold for its warning and its late note («Falten menys de 4 hores…»).
   - `Booking` therefore carries `lateCancelThresholdMinutes`: the booking's club value of `bookings.lateCancelThresholdMinutes`, 240 at the Cànic.
   - It also carries `cancellableInTimeUntil`: the class start minus that threshold, computed by the api, so the client does no date arithmetic.
   - Both come on every `Booking` that a MEMBER reads, the cancellation answer included: its late note names the threshold.
3. **The waiting dog on `WaitlistEntry`.** `WaitlistEntry` carries `dog` (`HoldDog`). `dogName` alone gives no sex for the Catalan article.
4. **03's rows (`ReservationRow`, `GET /me/home`).**
   - A class row carries `ringColor`, the ring's colour, for the mockup's coloured dot.
   - An `ACTIVITY` row carries `activityId`, as S07 §2 says `/me/home` delivers it.
5. **`BookedBy.self` (07's «Reservada per {name}»).**
   - `BookedBy` gains `self: boolean`: `true` when the reader's own account made the booking.
   - The web must stop deciding by comparing first names: an account name like «L. Serra», or two group members with the same first name, get it wrong.
   - `displayName` and `viaClub` are unchanged.
6. **The `Idempotency-Key` of `POST /bookings` (R-08-08, amended 26-09).**
   - The key is one client UUID per body. A retry of the same body reuses it. A different body, for example another booking chosen for the swap after a failed attempt, gets a new one.
   - The operation's description stops saying «Idempotency-Key = seatHoldId».
   - ITs:
     - the same key with the same body answers the same response, a stored `409` included;
     - a new key with a new body on the same hold is processed;
     - the same key with another body answers `IDEMPOTENCY_KEY_REUSED`.
7. **`BOOKING_NOT_CANCELLABLE` is 422** (`CATALEG_ERRORS.md` and S08 R-08-10, amended 26-09). The code already answers 422. Check that the snapshot publishes 422 on `POST /bookings/{id}/cancellation` and nowhere 409 for it. Contract test.
