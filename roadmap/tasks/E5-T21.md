## Steps
1. **Removed files stay removed (E5-T19 review #1).**
   - `writeDocuments` carries the stored rows that have `removedAt` over into the new `files`, in D2's `PATCH` and when a reused dog is validated (`applyReadmission`).
   - `claimDocuments` refuses a key whose stored row has `removedAt`: `400 FILE_NOT_FOUND`, as an S03 key gets.
   - Extend `R_04_19_R_04_08_d2RemovesOneFileOfAPendingPublicSignupDog`. After the `DELETE`: (a) a `PATCH` that sends back the view keeps the `removedAt` row, and P9 still counts the file as referenced; (b) a `PATCH` that sends the removed key answers 400, and the file does not come back. Add one IT for a reused dog's validation.
2. **A no-op documents edit (E5-T19 review #5).** A `documents` edit that changes no file key of any type is no change: no new `version`, no `SignupEdited`, no audit entry, no dashboard refresh. IT: sending back the view changes nothing.
3. **The file limit (E5-T19 review #4, R-04-08).** The limit of 10 files per request counts only the new uploads the request claims, not the kept files. IT: a type with 10 kept files takes one more.
4. **One shared retry backoff (E5-T18 review #1).** The S07, S08 and S09 writers (`ActivityTransactions`, `BookingTransactions`, `TrainingTransactions`) use `TransactionRetries.jitter()`, so every writer draws from one 50–150 ms range. Fix the class Javadoc. `TransactionRetriesTest`'s name is then true.
5. **`ClubUpdate.taxId` (E5-T18 reviews #3 and #4, S02 §3).**
   - The property is nullable (`types = {"string", "null"}`), with «blank or null clears it», like `displayCity`.
   - A club definition's schema refuses `taxId: null` (a definition clears it with `""`). Pin that refusal with a test.
   - Regenerate the snapshot, and add one `docs/openapi/CHANGELOG.md` entry.
6. **The mandate text, word for word (E5-T18 review #6).** The approved mockup 19 wins over the wording of E5-T18 step 1:
   - ca «Autoritzo a [[club_legal_name]] l'emissió de rebuts sobre aquest compte amb caràcter indefinit mentre es mantingui la meva relació amb aquesta entitat (llei 16/2009, de 13 de novembre, de serveis de pagament).»;
   - es «Autorizo a [[club_legal_name]] la emisión de recibos sobre esta cuenta con carácter indefinido mientras se mantenga mi relación con esta entidad (ley 16/2009, de 13 de noviembre, de servicios de pago).»;
   - en stays as E5-T18 left it.
   
   Update the test that asserts the three texts.
7. **Names and docs (E5-T18 reviews #2 and #5; E5-T19 reviews #2 and #3).**
   - `CatalogServiceRetryTest` `R_05_08_…` → `R_05_07_R_05_08_…`; `TransactionRetriesTest` `R_09_06_R_09_13_…` → `R_09_06_…`.
   - `R_15_19_theDeployBackfill…` reads the `--eval` expression from `docs/DEPLOY.md`, and asserts `getModifiedCount()` equals 1.
   - The E5-T19 entry of `docs/openapi/CHANGELOG.md` names the submission routes that now refuse a duplicate key (`POST /signup`, `POST /me/dogs/signup`).
   - The descriptions of `DogPatch.documents` and `SignupDocumentFile.fileKey` say that a kept file keeps its stored name.
