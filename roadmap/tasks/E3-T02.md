# E3-T02 · Signup domain (S04 WP-04-2): identity/phone/postal validation per country profile, FirstMonthCalculator, UpfrontAllocator, FamilyHolderMatcher, SignupPlanCatalog, upfront lines, state machines

## Objective
Work package WP-04-2: every signup rule that can be tested without Mongo is a pure domain service with the S04 §11 unit tests T-04-01…10 green.

## Spec references
S04 R-04-01 (id documents ES/GENERIC), R-04-02 (postal code → towns), R-04-03 (phones E.164, emails), R-04-04 (gender ICU), R-04-09 (plans shown + entry fee resolution), R-04-12 (holder matcher), R-04-13 (family fare proposal), R-04-14 (upfront lines incl. add-dog `ADDITIONAL_DOG_FEE` and the day-25 rule, decision B13), R-04-15 (half month / full month), R-04-16 (cascade allocation), R-04-17 (consent versions), §5 state machines (`Member.status` with `Member.signup`, `UpfrontPayment.status`) · tests **T-04-01…T-04-10** · `CATALEG_PARAMETRES.md` (`signup.*`, `billing.entryFeePerDog`, `billing.familyDiscountPercentFromSecondDog`, `billing.upfrontCutoffDay`, `billing.nextInvoiceDayOfMonth`, `files.*`) · `docs/DECISIONS_PENDENTS.md` B13, B14, A17b.

## Context to load

## Steps
1. **`clubs/signup/domain`**: `IdDocumentValidator` (ES DNI/NIE check letter, passport only when DNI/NIE empty → `ID_DOCUMENT_AMBIGUOUS`; GENERIC free ≥ 4) — extend the existing census validator if it already covers this, `PhoneNormalizer` (reuse E2-T06), `EmailRules` (RFC-lite, lower-case, distinct, first = primary), `PostalCodeTowns` (0/1/>1 semantics over the E2-T02 dataset; GENERIC → always 0, free town).
2. `FirstMonthCalculator` (R-04-15): inputs club-local today, `signup.firstMonthSplitDay`, monthly price → options A/B with labels' data (`startDate`, amount HALF_UP of `amountMinor/2`), proposed `nextInvoiceDate` = day `billing.nextInvoiceDayOfMonth` of the month after `startDate`; T-04-05 table including the `2026-08-15T22:30:00Z` instant (club time zone decides the day).
3. `UpfrontLines` (R-04-14): per plan type + `BILLING` flag + mode (public / add-dog: `ENTRY_FEE` + `ADDITIONAL_DOG_FEE` of the current month, or entry only with the «1st of next month» option when today ≤ `billing.upfrontCutoffDay`); `UpfrontAllocator` (R-04-16): cascade `ENTRY_FEE → FIRST_MONTH/PACK`, `PAID/PARTIAL/DUE`, `UPFRONT_AMOUNT_EXCEEDS_DUE`; T-04-06, T-04-07.
4. `FamilyHolderMatcher` (R-04-12): normalisation (lower-case, accents stripped, spaces compacted), all tokens of `holderName` (≥ 2) contained in the member's full name **and** a non-`LEFT` dog named `dogName`; exactly one → `FOUND` + `holderDisplayName` («Marta R.»); `INACTIVE` dogs do not count, `PENDING` holders do; T-04-08. Family fare proposal (R-04-13): `FAMILY` price if the resulting group has ≥ 2 non-`LEFT` dogs, else `STANDARD` with the `billing.familyDiscountPercentFromSecondDog` hint.
5. `SignupPlanCatalog` (R-04-09): `Plan.active ∧ showOnSignup` ∧ type allowed by modules (`PACK`→`PACKS`, `SINGLE_CLASS`→`SINGLE_CLASS`), catalog order, `STANDARD` current price, entry fee resolution (`Plan.entryFee.amount` ?? `billing.entryFeePerDog × percentOfStandard/100` ?? MONTHLY 100 € / PACK·SINGLE 0), no amounts without `BILLING`; T-04-09.
6. Consent versioning (R-04-17): `ConsentPolicy.check(request, club.legal)` → `400` (not accepted) / `CONSENT_VERSION_OUTDATED`; add-dog mode only re-asks when the last `PRIVACY_POLICY` entry is older than `legalTextsVersion`.
7. State machines as pure functions with the transition table of S04 §5 (`SignupState` for `Member.status` + `signup`, `UpfrontPaymentStatus`), used by E3-T03; gender ICU snapshots for N-02 and the image warning (T-04-10) through the existing `IcuMessageSource` (ca/es/en).

### Assumptions

- E3-T01 was `awaiting_verification` at start; roadmap/README.md permits proceeding. No other task or Organizer verification section was edited.
- MODEL_DADES_PLATAFORMA Annex B wins over older S04 examples: Price has a concept, not a FAMILY/STANDARD scope; FamilyFareProposal receives an eligible family Plan/Price from its caller. Price validity uses the existing inclusive validTo convention. No new price schema.
- Explicit entryFee.mode=STANDARD preserves the standard charge for every type. An absent override defaults MONTHLY to the configured charge and PACK/SINGLE_CLASS to zero; AMOUNT/PERCENT/NONE keep model semantics. MAINTENANCE plans do not receive a FIRST_MONTH charge.
- Dogs use model PENDING/ACTIVE/INACTIVE. INACTIVE is excluded from matching/family-count proposals, including rejection. Holder tokens match whole normalized name tokens. Internal match ids remain server-side; PublicResult exposes only outcome and short name.
- ADDITIONAL_DOG_FEE is a pure quote concept already required by B13/S04 and E3-T01's wire contract. This task creates no UpfrontPayment document or persistence migration.
- Calendar days require 1–31; days absent from shorter months clamp to the last day. The caller supplies effective club/scoped parameter values and chooses the returned TODAY default or ALTERNATIVE. Percentages reuse existing Money/EntryFeeCalculator rounding; first-month halves explicitly use HALF_UP.
- Consent versions are opaque: only the latest granted current-version PRIVACY_POLICY acceptance skips the add-dog prompt. Entries use model acceptedAt with injected Clock; persistence adapters must append without rewriting history.
- Census and signup share canonical document/phone normalization. GENERIC supports PASSPORT/OTHER and 7–15-digit international phones; ES preserves its default prefix and shared libphonenumber parsing.
- No controller/OpenAPI schema changes; the committed snapshot is unchanged. E3-T03 owns transactional loading, role/capability checks, mapping/serialization, persistence, events and sending. No new environment variables or secrets.
