## Steps
1. **Member routes for dual-role accounts (INC-16, ruling E41).** The `MEMBER` guard becomes `hasRole('MEMBER')` (plus the impersonation clause as today) in the three controllers: an account whose membership is `[MEMBER, INSTRUCTOR]` or `[MEMBER, ADMIN]` uses `/me/home`, `/me/bookable-classes`, `/seat-holds`, `/bookings`, `/waitlist-entries*`, `/me/training-summary`, `/training-bookings*`, `/me/training-bookings`, `/me/activities*` and the activity registration routes as a member; a token without the MEMBER role still gets `403 FORBIDDEN`. Her own cancellation (`POST /bookings/{id}/cancellation`, `BookingsController.java:198-207`) runs through the MEMBER branch (origin MEMBER, no `INSTRUCTOR_NOTICE`) when the booking is hers; the INSTRUCTOR branch stays for other members' bookings. Invert the assertion of `E5ContractIT.T_08_26_T_09_30_memberRoutesRejectStaff…` (staff-only token → 403; MEMBER+INSTRUCTOR → 200) and give the Cànic demo seed one instructor with her own dog (T-08-26, T-09-30 renamed to what they now prove). Grep every other `!hasAnyRole('ADMIN','INSTRUCTOR')` and apply the same rule.
2. **Impersonation `launchUrl` (INC-15, rulings E17/E47).** `POST /members/{id}/impersonation-token` returns `launchUrl = https://{club app host}/entrar?handoff=<code>`: a one-shot handoff code (60 s, `HandoffCode` with `sourceClientId = "impersonation"` bound to the grant id) that `POST /auth/handoff` (`HandoffService.exchange`) redeems once into the grant's impersonation JWT for `clubs-app` (the body keeps `token` and `expiresAt` for API clients). The JWT never travels in a URL. `ImpersonationHandoffIT` asserts `launchUrl`, the single redemption, the second redemption refused, the expiry, and that the redeemed token carries the `imp` claim and the member id (T-01-11). The web adopts it in E4-W16.
3. **Password recovery without `current` (INC-24, ruling E49).** A magic link with `purpose = RESET` issues a session whose access token carries a one-shot `pwdreset` claim (or an equivalent server-side mark on the family) valid 15 minutes; `PUT /me/password` honours it once: no `current` needed although the account has a hash; the mark is consumed on the first change and the ordinary rule applies afterwards. A LOGIN link issues no such mark. `PasswordService`/`IdentityCoreIT` tests: RESET link → set password without `current` → 200; second change → `INVALID_CREDENTIALS` without `current`; LOGIN link → `INVALID_CREDENTIALS` without `current`.
4. **`Idempotency-Key` on keyed PUT and DELETE routes (INC-23, ruling E46).** `IdempotencyFilter.shouldNotFilter` becomes method-aware: any route that declares the header in the contract (the four E6-T01 routes today — `PUT /class-sessions/{id}/attendance`, `PUT /dogs/{id}/observations`, `DELETE /tasks/{id}`, `DELETE /attachments/{id}`) is filtered like a POST; the replay reproduces the stored status and body (a 204 replays as 204); an IT replays a PUT and a DELETE and a GET is never filtered. Add a contract test: every operation whose OpenAPI parameters include `Idempotency-Key` with `required: true` is in the filter's set (read the snapshot, no hand-kept list). **Already in place (27-09):** E6-T02 and E6-T03 made the filter take these four routes with two hand-kept patterns (`KEYED_PUT` and `KEYED_FOLLOWUP` in `IdempotencyFilter`), and their ITs replay them; E6-T02 round 2 makes every replay pass the route's authorization first (ruling **E62**). This step replaces the hand-kept patterns with the set read from the contract and keeps those tests green; do not redo E6-T02 round 2's authorization fix.
5. **Health pings Mongo (A7-07, INC-01 semantics).** `GET /api/v1/health` answers `200 UP` only when a bounded (1 s) Mongo `ping` succeeds; otherwise `503 {status: DOWN}` with the same envelope shape and a WARN log with `traceId`; no tenant, no locale, no data (the E3-T06 regression `T_02_01_INC01_…` stays green). The Docker HEALTHCHECK and both compose files are unchanged.
6. **Test clock guard (A7-05).** `TestClockController` and `ClockConfiguration` carry the same profile expression as the other test-only beans (`(local | test) & !staging & !prod`) and the controller is `@PreAuthorize("denyAll")` unless the `test`/`local` profile is active; a test starts the context with `local,staging` and proves the route is absent and the application clock is the system clock.
7. **P2 write-conflict retry (A6-02).** In `SchedulingTransactions`' nested branch a Mongo `WriteConflict`/`DuplicateKey` is rethrown as-is (or wrapped keeping the cause) so `JobRunner.write` retries the item; `JobRunner.retryable` inspects the cause chain with `TransactionRetries.conflict`. IT: a risk-review cancellation that meets a concurrent booking on the same class ends `SUCCEEDED` after a retry, not `PARTIAL {INVALID_STATE}`.
8. **Signed downloads: an SVG is never shown on the api's origin, and the stored name is readable (review of E5-T26 #1 and #2, ruling E61).**
   - `AttachmentsController.download` (shared by `SignupFilesController`) answers `Content-Disposition: attachment` for `image/svg+xml`, whatever the purpose; the other `image/*` types stay `inline`.
   - Every download response carries `Content-Security-Policy: sandbox`. It does not stop an `<img>` from showing the file.
   - `ClubCorsConfigurationSource` adds `Content-Disposition` to the exposed headers, so the web's app can read the stored name when it downloads with `fetch`.
   - IT: an SVG uploaded through the anonymous signup route downloads as an `attachment` with the sandbox CSP; a PNG stays `inline`; a cross-origin `GET` from the club's web origin exposes `Content-Disposition`.
9. **Docs.** `docs/openapi/CHANGELOG.md` (steps 2, 4, 5), the root `README.md`/`docs/DEPLOY.md` (health semantics; the dual-role rule), `seeds/README.md` (the instructor with a dog). The organizer has already amended S01, S08 R-08-19 and `CONVENCIONS_API.md` §7; do not edit `docs/specs/`.
