# E2-T08 · Asynchronous export engine: ExportJob, worker, limits, signed downloads (S14 WP-14-C)

## Objective
Work package WP-14-C: large exports run in the background with a per-club limit and expiring download links.

## Spec references
S14 R-14-12 (file names, `hmac16`), §3 `ExportJob {status QUEUED|RUNNING|READY|FAILED, downloadUrl (signed, 7 days), rows, format, requestedBy}`, R-14-13 (limit 2 running jobs per club → `429 EXPORT_LIMIT`), retention (exports 7 days per `docs/DECISIONS_PENDENTS.md` A18d) · tests **T-14-10, T-14-15, T-14-16**.

## Context to load
S14 §3, §4 (export rules), §6 rows `/exports*`, §11 · E2-T07 renderers · this file.

## Steps
1. `ExportJob` collection + worker (`@Scheduled` poller claiming `QUEUED` jobs with `findAndModify`, one at a time per instance), renderers reused from E2-T07 streaming to S3 (or local storage in `local` profile), signed URL 7 days, TTL cleanup 7 days.
2. `GET /exports`, `GET /exports/{id}`, `POST /{resource}/export` → `202 {jobId}` when > 5 000 rows (E2-T07 threshold), `429 EXPORT_LIMIT` on the 3rd running job.
3. File naming `{clubSlug}_{resource}_{yyyyMMdd-HHmm}.xlsx` (club local time), `hmac16(email)` helper for pseudonymous exports (T-14-10).
