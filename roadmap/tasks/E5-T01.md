### Assumptions
1. **S15 routes are 501 stubs.** E5-T05 step 1 replaces "E5-T01's 501 stubs", so `/jobs*`, `/risk-review` and `/platform/jobs*` run the guards: `JOB_UNKNOWN`, `MODULE_DISABLED` of the process, the tenant-scoped run, and an unknown club → 404. The framework itself is real. `JobTriggerService.trigger(JobName, dryRun)` is the audited service that E5-T05's controllers will call after `JobCatalog.byRoute(name)`. `GET /jobs` row building and the overview `health` are E5-T05.
2. **`RiskReviewForm`.** S15 form A is published under this schema name because `RiskReview` already names the S14 dashboard card inside `GET /dashboard` (E3-T04, a different shape). Renaming the existing schema would break the web client. See Questions 1.
3. **`CatchUpWindow` is an enum** (`HOURS_24`, `END_OF_LOCAL_DAY`, `END_OF_LOCAL_MONTH`, `UNLIMITED`, `CONTINUOUS`) instead of `Duration` (null = unlimited). Two R-15-01 windows end at a club-local boundary that a Duration cannot express.
4. **`job_runs` claim index.** The unique `{clubId, job, scheduledFor, trigger}` index is *partial* on `exclusive: true`, which marks non-dry `SCHEDULE`/`CATCH_UP` rows that execute. With a plain unique index, a `SKIPPED{LOCKED}` row (T-15-03), a dry run followed by a real run in the same minute, or a reaped run's retake would collide.
5. **An occurrence is "taken" once a scheduled row covers it or a later occurrence.** The check is `scheduledFor >=`, so the tick never goes back in time. Moving `jobs.dailyTime` from 06:00 to 07:00 therefore does not resurrect yesterday's 07:00 as a late run (tested in T-15-05). `SKIPPED{LOCKED}` rows and runs reaped after their lease expired do not count.
6. **Club iteration.** The tick iterates `ACTIVE`, `ONBOARDING` and `SUSPENDED` clubs (not templates). A `SUSPENDED` club records `SKIPPED{CLUB_INACTIVE}` (R-15-03 plus A18e).
7. **`JobFailed` on a missed window** carries `status: "SKIPPED"` (the `JobRun` status). It is the only `SKIPPED` that emits `JobFailed`. Counter keys may not contain dots, because they travel as Mongo map keys in the `SchedulerRun` payload; the recorder throws. E5-T05 P9 must name its counters without dots, e.g. `ttlPendingSeatHolds` instead of `ttlPending.seat_holds`. Parameter snapshots and counters are stored in `job_runs` as key/value lists for the same reason.
8. **`Week` marks.** `Week.openedAt`/`openingNotifiedAt` are added as trailing record components with a legacy constructor (the same pattern as `ClassSession.finishedAt`). The two `Week` copy sites preserve them. `ClassSession.finishedAt` and `risk{exempt, notifiedBookingIds[], adminNotifiedAt, lowAlertSentAt}` already existed (E4-T01); I verified them in `E5PersistenceIT`. `Booking`/`TrainingBooking` carry `reminderSentAt`. `idempotency_records` is reused, not redeclared.
9. **N-42.**
   - It lives in `clubs.common.application`: `identity` already depends on `clubs.messaging`, so a messaging consumer that reads admins would create a cycle (ArchitectureTest).
   - Variables follow the catalog (`job_name`, `error_count`; S15 §8 also writes `date`).
   - Delivery is APP + EMAIL; `SystemEmailRenderer` now allows N-42.
   - `job_name` resolves `jobs.name.<JobName>` in the recipient's locale.
   - Once per job and local day, through deterministic notification ids.
10. **No Sentry integration exists in the code base.** Item and job failures are logged at ERROR with `jobRunId`, `job`, `clubId` and `traceId`.
11. **Test clock and test job.** `POST /api/v1/test/clock {instant | advanceSeconds}` exists only under `test`/`local`, needs no tenant and is hidden from OpenAPI. `ClockConfiguration` serves an `OffsetClock` (system time + offset) under those profiles and `Clock.systemUTC()` otherwise. `MockClock` now extends `MutableClock`. `TEST_NOOP` is a `JobName` value (task 7k) but its bean exists only under `test`. It supplies its own definition (not in the catalog), is never listed, and the wire `job` enum lists only the 10 catalog names.
12. **Impersonation rules.**
    - Member routes carry `@AllowsImpersonation`; every other E5 route answers `IMPERSONATION_DENIED` (403). The platform routes may answer `FORBIDDEN` first because their `@PreAuthorize` rejects `imp`.
    - `POST /waitlist-entries/{id}/cancellation` accepts `ADMIN` directly (S08 §6 «MEMBER (pròpia) · ADMIN»).
    - `POST /bookings/{id}/cancellation` accepts `INSTRUCTOR`; the `bookings.instructorLastMinuteNotice` check is E5-T02.
    - `DELETE /seat-holds/{id}` has no resource guard (204 "also when already gone").
13. **Calendar route.** `GET /bookings/{id}/calendar.ics` is a public host-resolved route (`permitAll` plus TenantFilter public) with `security: []` in OpenAPI. The stub checks that `token` is present and the booking exists; signature verification is E5-T02.
14. **Wire choices.**
    - `*Local` fields are strings (`YYYY-MM-DDTHH:mm` or `HH:mm`).
    - The `impersonation` object of `MeHome`/`TrainingBooking` is `{actorName}` (S08/S09 only show `null`).
    - `displayState` uses codes (`CONFIRMED · DONE · NO_SHOW · CANCELLED · CANCELLED_LATE · CANCELLED_BY_CLUB · PAYMENT_PENDING`) for the Catalan labels of S08 §6.
    - `WaitlistEntry` carries `classSession` for screen 07.
    - Fixtures omit null fields because the round trip uses `NON_NULL`; the spec examples' `null`s are therefore represented by absence.
15. **Event payloads.** They follow S08/S09/S15 §7 plus Annex A, as the task says. `WeekOpened`, `ClassAtRisk` and `ClassAutoCancelled` use the extended S15 §13 payloads. `ClassBelowMinimum` uses the catalog's `classId, countedDogs, minDogs` (S15 writes `classSessionId`). `WaitlistExpired` adds `classId` (S15 §7). `SchedulerEvent` lives in `shared.domain.events` so the platform framework and the owning contexts' jobs can emit it (cross-context access only through `application`/shared).
16. **`/ring-blocks` is untouched.** `GET /ring-blocks` already declares `x-filterable: ringId, kind, reason, state, from, to` (asserted again in `E5ContractIT`).
17. **Handoff to E5-T04.** `clubs/catalogs/persistence/MongoUsageCounter` still reads the provisional `status` field on `training_bookings` (E2-T03). The real field is `state` (ACTIVE); E5-T04 should adapt it when training bookings become real.
