# E1-T03 · Email base with SendGrid: EmailSender, per-club layout, webhook, SYSTEM path for N-25/N-26/N-27

## Objective
Work package S11 WP-11-B0 (stage E1): transactional email that the identity flows need, with a fake for tests and a real SendGrid sender. **Organizer note (06-09)**: the SendGrid account is NOT needed to code this task — the key is read from the environment only. `SendGridEmailSender` is tested against a mocked HTTP server (WireMock or OkHttp `MockWebServer`, already a Testcontainers-free unit/IT); the real-send smoke test is deferred to E1-T10 / staging, when Jordi provides `SENDGRID_API_KEY` and the verified sender domain (`agilitydoghub.com`).

## Spec references
`docs/specs/S11-comunicacions.md` WP-11-B0, §8 (N-25, N-26, N-27 in `CATALEG_NOTIFICACIONS`), §10 (recipient locale) · `docs/decisions/ADR-005-*.md` (SendGrid) · S01 §8.

## Context to load
S11 §3 (MessageTemplate — read only, the engine is E7), §6 webhook route, WP-11-B0 row · ADR-005 · CATALEG_NOTIFICACIONS rows N-25, N-26, N-27, N-02 · this file.

## Steps
1. `EmailSender` interface (`send(EmailMessage)`, `EmailMessage {to, subject, html, text, from, replyTo, locale, tags}`), `SendGridEmailSender` (API key from `SENDGRID_API_KEY`, sender `MAIL_FROM_PLATFORM`; per-club `from` name + `reply-to` from `Club` config when the club's domain is verified, otherwise the platform sender), `LogEmailSender` (profile `local`), `FakeEmailSender` (tests: in-memory mailbox with a `lastTo(email)` helper).
2. Thymeleaf layout per client (club logo/colors from `Club.theme` or the AgilityHub brand for `apps/id`), templates for N-25 (magic link), N-26 (password changed), N-27 (access resent) in `ca`, `es`, `en` using `messages_*.properties` keys and `ClubFormats` (E0-T08).
3. `SystemNotificationService.send(code, accountId, variables)` = the `SYSTEM` path: not configurable per club, locale = `Account.locale`, records a `Notification` document (collection `notifications`, minimal shape from S11 §3 so E7 can extend it: `{clubId?, accountId, code, channel EMAIL, status QUEUED|SENT|FAILED, providerMessageId, sentAt, error}`).
4. `POST /webhooks/email/sendgrid` (signature verification with the SendGrid public key from env; events `bounce`, `dropped`, `spamreport` → `Account.emailStatus = BOUNCED|COMPLAINED` and an audit entry; idempotent by `sg_event_id`).
5. Parameters/catalog: only existing keys; propose in the report if something is missing.

## Verification (run all; evidence = command + exit code + last 40 lines; long outputs → `roadmap/evidence/<ID>/*.log`)
- `./mvnw -q verify` → green with `SystemNotificationServiceIT` (N-25/26/27 rendered in the three locales, recorded, sent through the fake), `SendGridWebhookIT` (valid signature → status updated; invalid → 401; replay → no double update).
- `SendGridEmailSenderTest`: request body/headers asserted against a mocked SendGrid v3 `POST /v3/mail/send` (bearer header present but its value never logged), `202` → `SENT` with the `X-Message-Id`, `4xx/5xx` → `FAILED` with the error recorded, timeout handled.
- Real send (deferred, not part of this task's DoD): when a key exists in a local `.env` (never committed), one N-25 to a test mailbox — paste the SendGrid message id (never the key).
