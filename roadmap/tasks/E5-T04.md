# E5-T04 · Free training (S09 WP-09-B + WP-09-C)

## Objective
Work packages S09 WP-09-B and WP-09-C: a dog with the right to train alone books half-hour ring slots inside the booking window, at most three per week counted **by session date**, with the partial unique index as the final guarantee against double booking; an instructor reserves or blocks a ring without a student through the `/ring-blocks` endpoints E4-T03 already owns; and the two ports S06 has been calling with null objects (`TrainingOccupancyPort`, `TrainingConflictPort`) plus E3-T04's `TrainingBookingsQuery` get their real implementations, so the day grids (10, 23, D12, D4) show «Ocupada»/«Entren.» and class creation, ring deactivation and activity publication see real conflicts.

## Steps
1. **`TrainingEligibilityService`** (R-09-01): `canFreeTrain(dog) = dog.status == ACTIVE ∧ (dog.freeTrainingOverride ?? level(dog).grantsFreeTraining)`; with `levels.enabled = false` only an explicit `freeTrainingOverride == true` grants it (null = no). `eligibleDogs(memberId)` = own dogs plus, with `FAMILY_GROUP`, the dogs of the group's members whose owner is `ACTIVE`, ordered own-first then by `Dog.name`, each with `rightSource LEVEL|MANUAL` and `ownerName` (null for own). Expose `membersWithRight()` for S16's N-31 (E9). T-09-01, T-09-02.
2. **`TrainingSlotService`** (R-09-03, R-09-04, R-09-15) — slots are **computed, never persisted** (`training_slots` is not created at R1): for each local day of `[from, to]`, closed when the date is in `club.holidays` or `club.openingHours[dayOfWeek]` is null; otherwise walk `open → close` in `training.slotMinutes` (30) steps, building instants with `ZonedDateTime.of(date, time, club.timeZone)` (Java semantics: a gap shifts forward, an overlap takes the **first** occurrence); load in one query per collection the overlapping `ClassSession` `DRAFT|ACTIVE` with a ring, `RingBlock` `ACTIVE` and `TrainingBooking` `ACTIVE`; per (ring, slot) apply the priority `BLOCKED/CLASS` → `BLOCKED/RING_BLOCK` → `BOOKED/TRAINING` (or `OWN_TRAINING` when one of the bookings is the queried `dogId`) → `FREE`, with «overlap» = `a.from < slot.endsAt ∧ a.to > slot.startsAt`; rings exist only when `Ring.active ∧ Ring.allowsFreeTraining`, `capacity = Ring.trainingCapacity ?? training.capacityPerRingSlot`; `bookable = FREE ∧ startsAt > now ∧ inside the window` for MEMBER, `anyFree` per slot. MEMBER requests are clipped to `[today, today + training.bookingWindowDays]`, other roles to ≤ 31 days. INSTRUCTOR/ADMIN cells additionally carry `occupants[]`, `block` and `classSession`. With `COURSES` and (`courses.showSetupToMembers` or role ≠ MEMBER) each ring carries `setup` from `Ring.activeSetupId`. Cache: a static layer (steps 1–3 without bookings) keyed `{clubId, date}`, TTL 60 s, invalidated by the consumers of step 8; the booking layer is always live and **the unique index, never the cache, is the source of truth for concurrency**. T-09-03, T-09-04, T-09-05, T-09-06, T-09-22, T-09-29.
3. **Training week and counter** (R-09-05, decision B15): `weekStart` of a slot = the last local occurrence of `bookings.weekOpensAt` ≤ `startsAt` (reuse E5-T02's `BookingWeeks.lastOpening`, do not re-implement it); the counter of a unit (`bookings.limitUnit`: `DOG` → `dogId`, `MEMBER` → `memberId`) = `ACTIVE` bookings with that `weekStart`, **including sessions already done**, against `training.maxPerWeek` (3). The count is by **session date**, never by booking date. `GET /me/training-summary?dogId=&date=` returns `eligibleDogs`, `defaultDogId` (= `Member.lastDogForTraining` while still eligible, else the first eligible), `limitUnit`, `weekOpensAt`, the week of `date` (default today), `counter{used, limit, remaining, resetsAt}`, `cancellableBookings[]` (future `ACTIVE` still inside the cancellation threshold) and `bookingBlock`/`inactivity`. T-09-08, T-09-09, T-09-10, T-09-35.
4. **`TrainingBookingService.book(dogId, startsAt, ringId?, override?)`** (R-09-06, R-09-07, R-09-08), `Idempotency-Key`, one Mongo transaction retried whole (≤ 3) on `DuplicateKey`/`WriteConflict`: (1) `$inc` `Dog.trainingSeq` (unit `DOG`) or `Member.trainingSeq` (unit `MEMBER`) to serialize the counter; (2) eligibility (`422 DOG_NOT_ALLOWED`), ring bookable (`422 RING_NOT_RESERVABLE`), member conditions (`422 MEMBER_NOT_ACTIVE` / `422 BOOKING_BLOCKED` / `422 INACTIVITY_PERIOD`, reusing E5-T02's `InactivityPort`), slot on the grid (`422 SLOT_NOT_ON_GRID` — S09 writes 400, catalog rule 0 gives 422, see Fixed conventions) and inside the window (`422 SLOT_OUT_OF_WINDOW`, `422 CLUB_CLOSED` for a holiday or out-of-hours date); (3) no overlapping `TrainingBooking` or class `Booking` of the same dog → `422 DOG_ALREADY_BOOKED` (query `clubs.bookings.application` directly — that direction is allowed); (4) counter < limit → `409 TRAINING_LIMIT_REACHED {limit, used, weekStart, weekEnd, cancellableBookings[]}`; (5) slot state → `409 SLOT_TAKEN {ringId, startsAt, reason, freeRings[]}`; (6) insert with the lowest free `seatIndex`, the partial unique index `{clubId, ringId, startsAt, seatIndex}` on `ACTIVE` being the final guarantee; (7) `Member.lastDogForTraining`, `AuditEntry` when impersonated, `TrainingBooked` on the outbox. Without `ringId` («Qualsevol») pick the first `FREE` ring by `Ring.order` then `name`, moving to the next one on retry; none free → `SLOT_TAKEN`. `override {limit, reason}` is accepted **only** with an impersonation token (else `422 OVERRIDE_NOT_ALLOWED`) and skips step 4 only — never the window and never the uniqueness; audit `TRAINING_BOOKED_BY_CLUB` with `reason`. T-09-07, T-09-11, T-09-14, T-09-15, T-09-16, T-09-17, T-09-18, T-09-23, T-09-32, T-09-33, T-09-34.
5. **Cancellation** (R-09-10, R-09-14): `POST /training-bookings/{id}/cancellation {reason?}` allowed while `now ≤ startsAt − training.cancelThresholdMinutes` (instant arithmetic, DST-proof), else `409 TRAINING_CANCEL_TOO_LATE {thresholdMinutes, minutesBefore}`; an ADMIN with an impersonation token may cancel late with a mandatory `reason` (`cancelReason = ADMIN_LATE`, audited `TRAINING_CANCELLED_BY_CLUB`); a booking block never prevents cancelling. The seat and the week counter are freed, `TrainingCancelled {…, by, cancelReason, late}` is emitted; a second call → `409 INVALID_STATE`, the same `Idempotency-Key` → the same 200. Service methods for the system paths, callable inside another transaction and **not scheduled here**: `cancelFutureByMember(memberId, by, cancelReason)` (S15 P5c, E8), `cancelForInactivity(memberId, from, to)` (S13 `InactivityResolved`, E8), `cancelForDog(dogId)` (`DogDeactivated`) and `cancelByClub(bookingIds, cancelReason)` (the `TrainingConflictPort` half, step 7) → `CANCELLED_BY_CLUB` with `cancelReason ∈ RING_BLOCK · CLASS_CONFLICT · RING_NOT_RESERVABLE`. T-09-12, T-09-25, T-09-28.
6. **`TrainingOccupancyService`** (R-09-12) → the real `TrainingOccupancyPort`: intervals `{ringId, from, to, type: TRAINING|RING_BLOCK, reason, memberName?, dogName?, note?, id}` for a range; for a MEMBER viewer the result is redacted to `{type, reason}` (the grid cell reads «Ocupada» plus the lower-case reason, never who nor the note); INSTRUCTOR/ADMIN get names, reason and note. Training bookings occupy `training.slotMinutes`. Check against E4-T03's `DayGridQuery` that cells render as specified for both views and that nothing leaks in `view=member`. T-09-19, T-09-27.
7. **`TrainingConflictService`** (R-09-13) → the real `TrainingConflictPort`: `findActiveBookings(ringId, from, to)` used by S05 (deactivating a ring or clearing `allowsFreeTraining`), S06 (creating/moving a class, blocking from D4 or screen 24) and S07 (activity publication); live bookings → the caller answers `422 RING_HAS_BOOKINGS {bookings[]}` unless an ADMIN sends `cancelBookings: true`, in which case `cancelByClub` runs **inside the caller's transaction** (`Propagation.MANDATORY`) with the right `cancelReason` and emits `TrainingCancelled{by: ADMIN, origin: BACKOFFICE}`. Verify end to end with E4-T03's `RingBlockService` and E4-T04's activity publication. T-09-20, T-09-21, T-09-28.
