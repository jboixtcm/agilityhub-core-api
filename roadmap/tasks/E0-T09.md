# E0-T09 · identity skeleton: Account, Membership, password grant, JWT/JWKS, GET /me

## Objective
The minimum authentication that every other task and the front shells need: accounts, memberships per club, `password` grant issuing JWTs, `GET /me`. The full AgilityHub ID (magic link, sliding refresh, OIDC provider, impersonation, handoff, lockout) is stage E1.

## Spec references
`docs/specs/S01-agilityhub-id-i-acces.md` §3 (entities), §6 (`POST /oauth2/token` password grant, `GET /me`), rules R-01-01 (email normalisation), R-01-02 (host → club context), R-01-03 (hash verification); tests **T-01-01, T-01-02, T-01-07, T-01-17** · `docs/decisions/ADR-010` · `docs/specs/00-transversal/MATRIU_PERMISOS.md`.

## Context to load
S01 §3, §5–6, §9 · ADR-010 · MATRIU_PERMISOS · this file.

## Steps
1. `Account` (collection `accounts`, global): `{ email (normalised: trim, lower-case, NFC; unique), name, locale, passwordHash?, platformRoles[], status (ACTIVE|BLOCKED), security { failedAttempts, lockedUntil, tokenFamilyVersion }, externalIds {learnUserId?}, onboardingPending, createdAt }`. `Membership` (collection `memberships`, global but carrying `clubId`): `{ accountId, clubId, memberId?, roles[] (MEMBER|INSTRUCTOR|ADMIN), status (ACTIVE|SUSPENDED), defaultProfile? }`; unique indexes `accounts.email`, `memberships {accountId, clubId}`.
2. `PasswordHasher`: verifies bcrypt `$2y$`/`$2a$`/`$2b$` (Learn hashes) and `argon2id`; creates **argon2id** (OWASP parameters) for new passwords; constant-time behaviour with a dummy hash when the account does not exist (T-01-02). Include a fixture hash generated with PHP `password_hash()` (bcrypt cost 12) for the test.
3. Spring Authorization Server: RSA key pair loaded from the `AUTH_JWK_PEM` environment variable (with `kid`; a generated key in `local`/`test` profiles), `/oauth2/jwks`; a **custom `password` grant** (`AuthenticationConverter` + `AuthenticationProvider`) that resolves the club from the request host (`TenantContext`), loads the account, verifies the hash, checks the membership at that club and its status, and issues an access token JWT (15 min) with claims `sub, clubId, memberId, roles, activeProfile, locale` + an opaque refresh token (family id, single rotation for now; the sliding policy is E1). The resource server validates JWTs on every non-public route.
4. `GET /api/v1/me` → `{ account {id, name, email, locale}, membership {roles, memberId, defaultProfile}, modules[] }` filtered by the request host (T-01-17: never `passwordHash`, `security` or tokens in any response); roles map to `ROLE_MEMBER|ROLE_INSTRUCTOR|ROLE_ADMIN`; enable `@PreAuthorize`.
5. CLI command `identity:seed-test-accounts` (profiles `local`/`test` only): creates `admin@example.test`, `instructor@example.test`, `member@example.test` with memberships at the club whose slug is passed (`--club=canic`), passwords from `.env.example` (`SEED_PASSWORD`). The CLI runner itself is created in E0-T10; here add the command class and register it when the runner exists (coordinate: if E0-T10 is not merged yet, add a temporary `ApplicationRunner` and note it).
6. Errors: wrong password → `401 INVALID_CREDENTIALS` (standard shape, also for OAuth error responses — wrap the SAS error into the API error contract); account without membership at the host → `403 NO_MEMBERSHIP`; suspended membership → `403 MEMBERSHIP_SUSPENDED`; no token → `401 UNAUTHENTICATED`.
