# E7-T02 · Notification engine (S11 WP-11-B) — outbox consumer, RecipientResolver, ChannelResolver, TemplateRenderer (ICU + [[var]] + club formats), dispatcher with retries, TwilioSmsSender + monthly cap, WebPushSender (VAPID), email bounces and List-Unsubscribe; the E4–E6 SMS intents become real sends

## Objective
Work package S11 WP-11-B: one engine turns every domain event of the outbox into notifications — catalog lookup, template, recipients, channels, render in the recipient's language, dispatch behind `EmailSender` / `SmsSender` / `PushSender` with idempotency and retries — and replaces the ad-hoc notification code the earlier stages wrote per vertical. The SMS intents E4–E6 queued (`channel = SMS`, `status = QUEUED`, no sender) start being sent for real; CLUB_CHANGES messages and the released-seat notice (N-15) carry SMS; email bounces suppress the address.

## Steps
1. **Ports out of `messaging`** (`clubs/messaging/application/ports`, each with a null-object `@ConditionalOnMissingBean` default; the adapters live in the owning context's `application` package so ArchUnit stays green and `messaging` never imports another context's `persistence`): `MemberDirectoryPort` — `Optional<MemberContact> find(memberId)` and `List<MemberContact> findAll(Collection<String>)` where `MemberContact {memberId, accountId?, displayName, locale?, emails[{address, bounced}], phones[{e164}], preferences NotificationPreference, status, dogNames}`, `List<MemberContact> byIds/byFilters(...)` for E7-T04; `StaffDirectoryPort` — `List<MemberContact> admins()` (memberships `ACTIVE` with role ADMIN), `List<MemberContact> instructors()` (all active) and `instructorsOf(classSessionId)` (the `ClassSession.instructorIds`, new **and** old on `N-08b`); `BookingRelevancePort` — `boolean stillActive(bookingId?, trainingBookingId?, Instant startsAt)` (R-11-16) and `WaitlistRelevancePort` — `boolean stillNotified(waitlistEntryId, Instant now)` (R-11-11 `CLAIM_SEAT.enabled`, computed on read); `SignupContactPort` — `Optional<ApplicantContact {email, locale, displayName}> applicant(signupId|memberId)`. Every port has an in-memory double in tests reproducing the S11 examples.
2. **Outbox consumer** (`NotificationEventHandler`): one `DomainEventHandler` bean per distinct `eventTypes[]` value of the `NotificationCatalog`, registered programmatically in `MessagingConfiguration` with **durable bean names** `notifications.<EventType>` (the dispatcher uses bean names as consumer ids — never rename one). Pipeline exactly as S11 §6: `specsFor(evt.type, evt.payload)` → template (`MessageTemplate{clubId, code}`, else the product seed, created on first use per R-11-01; `status = DISABLED` → skip entirely) → `spec.stillRelevant(evt)` (else a single `Notification` with a `SKIPPED_STALE` delivery, R-11-16) → per audience and recipient: locale (`Account.locale` → `club.defaultLocale` → first available; `APPLICANT` → `signup.locale`), variables, render, `notifications.upsertByDedupKey(...)`, `channelResolver.resolve(...)` adding each delivery **if absent**, save, `dispatcher.trigger(id)`. Idempotent per `eventId` (the outbox already records `processedAt`): reprocessing reuses the document and creates no new delivery. Runs **outside** the business transaction (the outbox dispatcher already guarantees that) and never inside a Mongo transaction while doing network I/O (decision E13).
3. **`RecipientResolver`** (R-11-02): `MEMBER` = the members of the payload (`memberId`, `affected[]`, `entryIds[]`…; on a booking of a family-group dog, the owner **and** the booker); `INSTRUCTORS` = `instructorsOf(classId)` when the payload carries a class, otherwise all active instructors; `ADMINS` = `StaffDirectoryPort.admins()`; `APPLICANT` = the signup email. The same person in two audiences gets two notifications (different `dedupKey`s). `LEFT` members receive only what their own event mandates (N-28), never N-24. One notification **per dog** when the subject is a dog (`subjectKey = dogId`). T-11-14, T-11-08.
4. **`ChannelResolver`** — implement the R-11-03 truth table literally, one method returning the list of deliveries with their initial status: `APP` → always `DELIVERED` for `MEMBER`/`INSTRUCTORS`/`ADMINS` when the template's matrix cell is on; `EMAIL` → `QUEUED` to **every** non-`bounced` address, `SKIPPED_BY_PREFERENCE` when `emailByCategory[category]` is false (only for `MEMBER` and only when `category != SYSTEM`), `SKIPPED_NO_CONTACT` when every address bounced (plus the admin notice of R-11-08); `SMS` → `QUEUED` **per phone** when the matrix cell is on and the `SMS` module is on (preferences can never remove it — «+SMS» is fixed, Josep 18-08), `SKIPPED_MODULE_OFF` with the module off, `SKIPPED_CAP` + a forced `EMAIL` delivery at the cap (R-11-06); `PUSH` → from `catalog.push[audience]` (never from the template), `QUEUED` per `ACTIVE` subscription, `SKIPPED_NO_CONTACT` without any, gated by `pushClubNews` only for `CLUB_NEWS`, `SKIPPED_MODULE_OFF` with `PUSH` off; `INSTRUCTORS`/`ADMINS` ignore preferences entirely; `APPLICANT` is `EMAIL` only; a matrix cell off produces **no** delivery document and the notification is still stored (R-11-10). T-11-02 is a parametrised test over **every catalog code × every row of the table** (preference ON/OFF × module ON/OFF × contact present/absent) — build it as a table-driven test so E7-T04 can reuse the same data provider; T-11-03.
5. **`TemplateRenderer`** (R-11-05): (1) resolve `LocalizedText` per field with the R-11-01 fallback; (2) ICU4J `MessageFormat` through the existing `IcuMessageSource` with `ApostropheMode.DOUBLE_REQUIRED` (Catalan apostrophes «l'app», «d'aquest» must survive — T-11-04) and the arguments `gender`, `late`, `decision`, `kind`, `count`; (3) `[[var]]` substitution with **already formatted** values; unknown variable → empty string + `WARN` log at render time (the `400` belongs to saving, E7-T03); (4) capitalise the first letter of title and body; (5) email = subject from the title + Thymeleaf layout of the club (reuse the E1-T03 layout: logo, colours, name from `Club.theme`) + plain-text part; SMS per step 6. **`VariableFormatter`** (extend `ClubFormats`, club `timeZone`, recipient locale): `class_date`/`date` → «ahir» · «avui» · «demà» within ±1 day, else `fmtDate(weekday)` («dimecres 12»; with month beyond 6 days), short form for `date` («dt 4»); `class_time` «18:50»; training `time` «8:00–8:30»; `review_time` «7:30»; `review_day` relative; `effective_date`, `week_start` long form; `from_month`/`to_month` `fmtMonth`; `amount`, `fee` `fmtMoney`; `pack_expiry` short; `level_name`, `activity_title`, `class_description` = resolved `LocalizedText`/`displayDescription`; `dog_name_article` («la Duna», «en Rock», «l'Ares» in `ca`, bare name in `es`/`en`; share the rule with `packages/i18n` of S08 — back-end copy here); `dogs` «Duna (C), Rock (D)»; `changes` «Hora: 18:50 → 19:00 · Pista: Central → Muntanya»; `calendar_links` email only; `masked_account` «···· 2231». Staff audiences render the non-editable product copy `notif.N-xx.staff.title/body` from `messages_*` (decision in force, part C S11). T-11-01, T-11-04, T-11-05 (snapshot of **every** seeded code in `ca`, `es`, `en`, staff texts included), T-11-15 (`Europe/Madrid` vs `America/Argentina/Buenos_Aires`), T-11-40.
6. **SMS** (R-11-06): `SmsSender` interface `SendResult send(SmsMessage {to (E.164), body, senderId, tags})` with `record SendResult(String providerRef, boolean retryable, String error)`; implementations `TwilioSmsSender` (Messages API, `from` = `messaging.sms.senderId`, credentials from the environment `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, optional `TWILIO_MESSAGING_SERVICE_SID`; HTTP client with timeouts; 4xx → not retryable, 429/5xx/timeout → retryable), `LogSmsSender` (profile `local`), `FakeSmsSender` (tests: in-memory outbox with `lastTo(phone)`), selected exactly like `EmailSender` is today. **Credentials are not available yet**: build and test everything against `FakeSmsSender`/`LogSmsSender` and a mocked HTTP server (WireMock or OkHttp `MockWebServer`, as `SendGridEmailSender` is tested), finish the task, and write one `roadmap/MESSAGES.md` entry addressed to `@jordi` asking for the Twilio account SID/token, the sender id or messaging-service SID and the VAPID key pair, stating that the real send is verified at staging (same treatment as `SENDGRID_API_KEY` in decision E13). Body = rendered `smsBody`; transliterate to GSM-7 when `messaging.sms.transliterateToGsm7` (`í ó ú ç ï · — ’` → `i o u c i . - "`); truncate at **160** characters with «…»; never a link. One delivery per phone. Counter: before each send, if `Club.usage.smsSentMonth >= messaging.sms.monthlyCap` (1000) → `SKIPPED_CAP`, force an `EMAIL` delivery even when the preference is off, and emit `SmsCapReached{month, cap}` → **N-49** to `ADMINS` **once per month**; on success `usage.smsSentMonth++` atomically (`$inc` with the club-local `usage.smsMonthKey` check, S15 R-15-15 g resets it). `SENT` is the terminal SMS state at R1 (no Twilio delivery callback — decision in force).
