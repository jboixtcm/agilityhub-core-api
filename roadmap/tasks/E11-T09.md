## Steps
1. **INC-37, the identity minors** (26-09 review, items A1-02…A1-13). Check each item against the current code. Fix the ones that are still open, each with a test. For the ones a later task already fixed, name the commit or the test. The items, as the review wrote them:
   - `ImpersonationEnded` has no `reason` and is never emitted on expiry;
   - `LOGIN_FAILED` has no `emailHash` (E11-T01 added it to some security events: check this one);
   - T-01-02's timing is not measured, and argon2 and bcrypt hashes take different times;
   - the Learn import re-flags onboarding and pins bcrypt cost 12;
   - `PATCH /me` is allowed under impersonation without audit;
   - the key-rotation guard (15 min) is shorter than the impersonation JWT (60 min);
   - `docs/DEPLOY.md` misses `OIDC_LEARN_CLIENT_SECRET`, `MAIL_FROM_PLATFORM` and `SENDGRID_WEBHOOK_PUBLIC_KEY`;
   - `magic_link_tokens.ipHash` is not salted;
   - N-26 has no `device`;
   - `Account.name` is never synced from the census (R-01-14).
2. **INC-64, the app of a verified admin host** (E11-T02's question 3; the organizer accepted the proposal).
   - Caddy asks the api which app a verified host serves: `forward_auth` to an internal route (for example `GET /internal/domains/app?host=`, answering `X-Club-App: clubs | clubs-admin`, cached). This replaces `CLUB_ADMIN_HOSTS`.
   - The internal route cannot be reached from outside: Caddy refuses `/internal/*` from the internet. It is not in the public contract.
   - Prove it with a Caddy run: a `clubs-admin` domain verified during the run serves the admin app without a reload. Use a step of an existing smoke or a new `bin/` smoke.
   - `docs/DEPLOY.md` drops the manual step.
   - If Caddy cannot be run, set the task `blocked` and say what is missing.
3. **INC-69, E9-T07's minors:**
   - one place decides which course a ring setup shows: `RingSetupService.shown()` calls `shownCourse()`, and a test ties `CourseAccess.shownBySetup` and `RingSetupRepository.showsCourse` to it;
   - the member's `placement` is `null` when the shown course was deleted, as `hasViewer` already is;
   - `RingGeometryIT`'s instructor-read test no longer cites T-16-06;
   - S16 §5's build-session diagram uses the session statuses of the code (E109).
4. **INC-70, E11-T07's minors:**
   - `bin/security-scan-test.py` asserts only that no active exception names `org.springframework:spring-webmvc` 6.2.19, CVE-2026-47884 or CVE-2026-47890, so the exceptions mechanism stays usable;
   - Jackson is pinned to the same-line patches (`jackson-bom` 2.21.7 and Jackson 3 3.1.7, or later on the same lines), and the image scan shows those HIGH findings gone;
   - `docs/DEPLOY.md` names `deploy/compose.prod.local.yaml` as the one Compose file that changed (`SPRING_MONGODB_URI`);
   - one line next to the Boot 4 upgrade notes in `docs/DEPLOY.md`: no separate Micrometer starter is needed.
5. **INC-71, a flaky test.** `BuildSessionsIT.T_16_10_theQueryTokenIsAcceptedOnlyByTheEventStream` reads the SSE `Content-Type` before it is set when several builds share the container (E11-T01's logs `10` and `11`). Make it wait for the stream's headers, and show 20 repeated green runs.

Each fix comes with a test that fails before it (for documentation, the diff). Do not edit `docs/INCIDENCIES_OBERTES.md`: the organizer marks the incidences resolved when it verifies the task. If an item needs a product decision that the specs do not give, write the assumption in the report and go on with the others.
