### Step 2 · INC-64, the app of a verified admin host

- **api**: `GET /internal/domains/app?host=` (`InternalDomainsController`, `@Hidden`, not in `openapi.json`): always `200`, no body, `X-Club-App: clubs-admin` for a `VERIFIED` `clubs-admin` domain, else `clubs`. It shares the ask's security chain: loopback/RFC1918 peer only, and a forged forwarded header gets `403`. `HostTenantResolver.app()` caches found hosts only (5 min), and `invalidate()` clears that cache after every domain change commits. So a verification serves its app at once, and a removal is followed at once.
- **Caddy**: the `https://` catch-all imports a new `(club_spa)` snippet. It drops the client's `X-Club-App`, then `forward_auth {$CADDY_APP_UPSTREAM}` (`core:8080`) sends `uri /internal/domains/app?host={host}` with the upstream's `Host` and without `X-Forwarded-*`, `Authorization` or `Cookie`, and `copy_headers X-Club-App`; the answer picks the root. `CLUB_ADMIN_HOSTS` is gone from the Caddyfile, both Compose files and `.env.prod.example`. `/internal/*` stays unreachable from outside: `CORE_HOST` answers `404` and the SPA sites never proxy it.
- **Caddy run**: `deploy/test_e11_t09.py` runs the real snippet in `caddy:2.10.2-alpine` against a stub that refuses any leaked forwarding header, credential or foreign `Host` (`14`). The first version served the members' SPA on the admin host: Caddy puts the two `root` lines in one exclusive group where the first match wins, so they were swapped (found with a debug run of the stub's access log). `bin/deploy-smoke` (`19`, production topology, new image) does the rest. `approved-admin.localhost` first serves `clubs`. Then `deploy/local/verify-admin-host.js` writes it as a `VERIFIED` `clubs-admin` domain while Caddy runs: the local stack has no DNS egress, so this write stands for the console's commit. The next requests serve `clubsadmin` (`/`, deep link, `/index.html`, with the security headers and `no-cache`), its branding resolves `canic`, and a client's `X-Club-App: clubs-admin` on a members' host changes nothing. `/internal/domains/app` is `404` on `core.localhost` and the SPA on a club host. Caddy's `/config/` hash, `StartedAt` and `RestartCount` are identical before and after: no reload.
- **Console path** (verification commit + cache eviction): `PlatformDomainsIT.T_17_03_INC_64_aVerifiedAdminDomainServesTheAdminAppOnceItsVerificationCommits` (red `10`: the route did not exist → 401; green `22`).
- **Docs**: DEPLOY.md drops the manual step 5 (the steps are renumbered), describes the route and the smoke, and loses the `CLUB_ADMIN_HOSTS` inventory row. S17 R-17-03 + «Canvis» and the verify operation's description say the same (E109).
