# E3-T11 · Gate E3 audit re-run (api)

## Objective
E3-T07 ran the gate E3 audit on the code before the fixes. This task runs it again once E3-T08, E3-T09, E3-T10 and E3-T12 are verified. It gives the organizer the evidence to close gate E3 (back). The organizer opens it.

**Change no product code, test or seed.** If something fails, report it exactly (the command, the exit code, the failing test and its message), and finish the report anyway. Set `awaiting_verification` at the end.

## Spec references
- S04 §11 (T-04-01 … T-04-34) and S14 §11 (T-14-01 … T-14-06, T-14-11, T-14-22, T-14-23, T-14-25).
- `roadmap/reviews/gate-E3/consolidated.md`, «Tests that must exist after the fixes».
- `roadmap/ROADMAP.md`, section «Gate E3 (back)».

## Steps
1. **Commit.** At the start, record `git rev-parse HEAD` and `git log -1 --format='%H %ci %s'`. Every result refers to that commit.
2. **Full build.** `./mvnw -q clean verify`: the exit code, the totals, and one line per test class whose name or methods contain `T_04_` or `T_14_`.
3. **Traceability.**
   - Re-run `roadmap/evidence/E3-T07/trace.py` straight after the build. Copy it to `roadmap/evidence/E3-T11/` first, and point its output there.
   - Write `trace-tests.csv` and `trace-summary.md` as in E3-T07.
   - Add a section «Audit tests» to `trace-summary.md`. For each api item of the consolidated report's required-tests list, give the test class and method that proves it, and whether it passes:
     - a retry after a lost 201: the same `Idempotency-Key` gives the same 201;
     - family-plan add-dog;
     - a validation with the family fare;
     - a dog edit after an add-dog;
     - D1 fresh right after a validation, with no sleep;
     - an S3-signed upload against MinIO;
     - a readmission that is rejected, with the original data intact;
     - a percent-encoded route that is still rate-limited;
     - the per-plan quote (pack, Teràpia, days 5 and 17).
4. **E3 smoke.** `bin/e3-smoke` twice on a fresh local stack. Commit both logs, and put the second run's summary in the report.
5. **Seeds.** `bin/core club:apply seeds/club-canic.yaml` twice, and `seed:demo --club=canic --seed=42` twice. The second runs must say «0 changes». Reuse `roadmap/evidence/E3-T07/seeds_twice.py`, and delete any demo files it leaves under `.local/`.
6. **Snapshot drift.** `bin/openapi-snapshot`: the committed `docs/openapi/openapi.json` must be byte-identical (`cmp`).
7. **`GET /dashboard` with the seed.** Print the values the gate line quotes:
   - `pendingSignups` and `olderThanWarn`;
   - `activeMembers`;
   - `classOccupancy` and `trainingBookings`;
   - `dogsByLevel`: the number of columns, the level codes, `others` and `totalActiveDogs`.
8. **Gate lines.** For each line of «Gate E3 (back)» in `roadmap/ROADMAP.md`, give one line of evidence from this run. Propose the new text of the lines whose values changed (for example the class block since E4-T05, and the chart after E35).
