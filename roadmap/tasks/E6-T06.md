### Assumptions

1. **The whole text.** «el text» is searched in the task's whole text and in the dog's member note, not only in the
   120-character `textExcerpt`. So a row can match on a word it does not show.
2. **Names through the census port.** Follow-up never reads the `dogs` or `members` documents (E6-T03's rule, ArchUnit
   `FOLLOWUP_WITHOUT_CENSUS_OR_BOOKINGS`). So the list does not `$lookup` them:
   - `FollowupCensusAccess.search` returns the matching dog, member and note ids;
   - D14's `$match` is an `$or` over those ids, `authorName` and the matching task ids.

   For that, the universal engine takes a list's own search (`ListDataset.withSearch`). Every other list keeps the regex over
   its searchable paths. `FOLLOWUP.searchable` names the four searched fields, so `ListQuery` accepts `q`.
3. **The member's full name** is «first last1 last2» joined by single spaces, as D14's `memberName`. An erased member
   matches nothing: D14 shows no name for them either.
4. **The author's label** is the name on the author's newest visible row. A row keeps its author as they were then (E64),
   so an author renamed later shows the newest name.
5. **Label fallback:** a value whose record is gone (an erased member, a missing dog) keeps its value as its label, as in
   `/training-bookings/filter-values`.
6. **`trainingSlotMinutes`** is always sent, `null` with FREE_TRAINING off (`NOT_REQUIRED` + nullable), like E6's other
   nullable fields.
7. **Step 4 covers every state without a page:** `CANCELLED`, and a `DRAFT` one after an unpublication. It uses the page's
   own rule, so the two cannot drift apart.
8. **The universal `$match`** is now built as `{$and: [criteria documents…]}` instead of Spring's `andOperator`. The shape
   is the same, and every list's tests pass in the full verify.
