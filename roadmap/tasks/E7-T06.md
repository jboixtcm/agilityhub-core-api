## Steps
1. **Templates stored before this round are brought up to date (codex review #1, claude review #1).**
   - Databases created earlier hold two older kinds of template.
     - E7-T02's first use copied `messages_*`, with ICU `{var}` arguments and `FEMALE`/`MALE` select keys. Round 1 lower-cased `gender`, so an E7-T02 N-02 now greets every woman with «Benvingut».
     - E7-T03's round 1 stored N-02 with «Entra-hi amb aquest enllaç: [[link]].». It renders an empty link, and saving it unchanged fails with `TEMPLATE_UNKNOWN_VARIABLE`, since `link` is no longer an APP variable.
   - Add one idempotent upgrade, at start-up or in `club:apply` and the lazy seed (say which):
     - a catalog template the club never edited (`customized = false`) takes the current seed in the club's languages;
     - an edited one keeps the club's words, with the `gender` select keys lower-cased and N-02's link sentence removed.
     Nothing brings the old texts back.
   - Test with the literal E7-T02 N-02 and N-15 texts and with a round-1 N-02:
     - GET, then PUT unchanged → 200;
     - a delivery to a `FEMALE` member → «Benvinguda»;
     - no delivery has an empty link;
     - an edited body keeps the club's words.
2. **The applicants' surnames reach N-01 and N-03 (codex review #2, claude review #2; R-11-12).**
   - Both codes' audience is `APPLICANT`. They accept `[[member_last_names]]` because their rows declare `member_name`, but `derived()` fills it only for members.
   - Derive it for any audience that has the name facts; for an applicant, from the signup's facts.
   - Test real deliveries of «Cognoms: [[member_last_names]].» → the applicant's surnames:
     - `SignupSubmitted` (N-01, the applicant's e-mail);
     - `SignupRejected` (N-03).
3. **The preferences answer the account's own language (review #3; E7-T03 step 6).** `locale` is `Account.locale` as stored, even when it is not one of the club's languages; `availableLocales` stays separate. Screen 12 and D10 read the same answer. Test: `Account.locale = en` in a `ca/es` club → `locale: en`.
4. **Variable parity over every templated code.** A test that, for each templated code and each of its audiences (N-01 and N-03 included), renders every variable the template may use with that audience's real facts, and fails when one renders empty. List in the report any code it had to fix.
5. **The seed uses only its rows' variables (claude review #3; AGENTS rule 2).**
   - N-08b's seed body uses `{class_description}`, and N-32c's SMS uses `({date})`. Neither is in its CATALEG_NOTIFICACIONS row.
   - `seedArguments` lets them through as if they were selectors: a second, hidden variable list.
   - Limit `seedArguments` to the names of `select` and `plural` arguments, and rewrite the two texts without those variables.
   - If a text needs one of them, propose the row change in `MESSAGES.md`, and ship the text without it meanwhile.
