### What changed, step by step

1. **Templates stored before E7-T03's round 2 (codex #1, claude #1). Where: at the API's start-up.**
   - `TemplateUpgrade` (`clubs.messaging.application`, a `SmartInitializingSingleton`) runs once per start-up. It runs before
     the web server and the schedulers, so no request or outbox delivery reads an old template.
   - It walks every club that holds a template (`MessageTemplateRepository.clubIds()`), one tenant at a time.
   - `bin/core` commands (`core.command` set) skip it, so `club:apply --dry-run` still writes nothing. `club:apply` and the
     lazy seed already store the current seed, and keep an existing template (E7-T03 assumption 21).
   - **Never edited** (`customized = false`): the current seed's texts in the club's languages (`TemplateProvider.seed`). The
     matrix, icon, colour and state stay the club's.
   - **Edited** (and `CUSTOM`): the club's words in the club's languages (D9's `normalized`). Every `{gender, select, …}`
     gets lower-case keys (`FEMALE`→`female`, `MALE`→`male`, `OTHER`→`other`). N-02 loses the sentence of its link: the six
     sentences the product shipped (E7-T02's ca/es/en, round 1's ca/es/en), then any sentence with `[[link]]`/`{link}`.
     `customized` is computed again against the seed. A correction that would stop the text parsing keeps it. A text left
     blank takes the seed's text of that language.
   - **Safe to repeat:** an up-to-date template is not written. The write is conditional on the version read: a D9 save in
     between wins, and the template is read again (3 attempts). A template that cannot be written logs a WARN with the club
     and template ids only, and never stops the others or the start-up. `updatedBy = system:template-upgrade`.

### Assumptions
1. **Start-up, not `club:apply`** (step 1's choice). Only the server delivers and edits templates. Running before its web
   server and schedulers start means nothing reads an old template. `bin/core` commands skip it, so a `--dry-run` writes
   nothing; `club:apply` keeps an existing template as before. The upgrade reads every club that holds templates (any
   status), not only the active ones.
2. **What an upgrade replaces.** A never-edited template takes the seed's texts only. Its matrix, icon, colour, `enabled` and
   status are club choices that `customized` does not track, so they stay.
3. **No audit entry nor `MessageTemplateChanged`.** The upgrade is a product data migration, like
   `messaging:migrate-notifications`; it is marked by `updatedBy = system:template-upgrade` and a new `version`. A D9 client
   holding the old version gets `STALE_VERSION` and reloads.
4. **Edited templates keep only the club's languages.** Their other languages (E7-T02 stored `en` in a ca/es club) are product
   copy the club can neither see nor edit in D9. They are dropped, so an `en` recipient reads the club's default (R-11-01).
   This also closes E7-T03 round 2's assumption 2 for those templates.
5. **N-02's link sentence** = the six sentences the product shipped, plus any sentence of the club's with `[[link]]` or
   `{link}` (delimited by `.`, `!`, `?` or a line break). The club's other sentences stay.
6. **`member_name` of N-01/N-03 is the full name** (first name, `lastName1`, `lastName2`), as `MemberContact.displayName` for
   every other audience. N-01's admin copy now shows both surnames. A readmission's `applicant` payload has no `lastName2`
   (CATALEG_ESDEVENIMENTS), so its surnames are `lastName1` only until proposal P2.
7. **`locale` without a stored language:** `Account.locale` absent, or a member without an account, reads `club.defaultLocale`.
   `NotificationPreferences.locale` is a required string in the contract, so it is never null.
8. **Parity scope.** The parity is checked for the audiences that read the template (MEMBER, APPLICANT). The staff audiences
   read the non-editable product copy; for them the test checks that no value is missing. The events are synthetic
   envelopes with their producers' payloads, delivered to the real engine and owners over real documents (no producer
   service is called).
