# E5-T02 · Class bookings (S08 WP-08-B)

## Objective
Work package S08 WP-08-B: a member holds a seat, confirms it (swapping an existing booking when the week limit is reached), pays for it when the club sells single classes, cancels it inside or outside the 4 h threshold, and every one of those transactions is serialized per class so no overbooking is possible under concurrency. The task also replaces the doubles other contexts have been living with: E4-T03's `ClassBookingsPort` and E3-T04's `BookingActivity` / `ClassOccupancyQuery` get their real adapters, and E4-T05's `DemoClassBookingsAdapter` + `demo_class_bookings` collection are retired. Waitlist is E5-T03, free training E5-T04, the scheduled processes E5-T05, the `/me/home` and `/me/bookable-classes` aggregates E5-T06.

## Steps
1. **Booking-week arithmetic** (`clubs/bookings/domain`, pure, no Spring/Mongo — the `ArchitectureTest` domain rule applies): `BookingWeeks.lastOpening(now, weekOpensAt, zone)` → the last local occurrence of `{dayOfWeek, time}` ≤ `now`; `week(instant)` → `{key: YYYY-MM-DD of the opening, start, end}`; `relative(classStartsAt, now)` → `CURRENT` · `NEXT` · `LATER`; `opensAt(week)` = `start(week) − 7 days` as an **instant** derived from the local occurrence (169/167 h weeks across DST). No literal «SUNDAY» anywhere: a club with `{MONDAY, 00:00}` must work (T-08-44). T-08-01, T-08-02, T-08-42.
2. **Limit calculation** (`BookingLimits`, pure): counted states = `ACTIVE`, `PAYMENT_PENDING`, `CANCELLED_LATE`; not counted = `CANCELLED`, `CANCELLED_BY_CLUB` (R-08-02). Unit from `bookings.limitUnit`: `DOG` → by `Booking.dogId`; `MEMBER` → by `Booking.memberId` (**the dog's owner**, not the person who booked). Max = `bookings.maxCurrentWeek` (2) for `CURRENT`, `bookings.maxNextWeek` (1) for `NEXT`. `swappable` = counted `ACTIVE` bookings of that week with `classStartsAt − now ≥ bookings.lateCancelThresholdMinutes`; `notSelectable` = the rest of the counted ones with `reason: DONE` (`classStartsAt ≤ now` or `CANCELLED_LATE`) or `LATE_WINDOW`. `reached ∧ swappable.isEmpty()` → the informative path of R-08-03/R-08-09. T-08-03, T-08-04, T-08-05, T-08-43.
3. **Eligibility** (`BookingEligibility`, one class, one ordered list of checks so `/seat-holds`, `/bookings`, `/waitlist-entries` and `claim` cannot drift apart): dog accessible (own or, with `FAMILY_GROUP`, of the group) → `404 DOG_NOT_ACCESSIBLE`; dog `ACTIVE`; member (owner **and** booker) `ACTIVE` → `422 MEMBER_NOT_ACTIVE`; `Member.bookingBlock.active` of either → `422 BOOKING_BLOCKED {reason}` (not audited, only logged with `traceId`, R-08-05); `leaveDate` set and `classStartsAt ≥` end of the local `leaveDate` day → `NOT_BOOKABLE{LEAVING}` / `422 CLASS_NOT_BOOKABLE` (A20c, and S15 §13-6: use *end of the leave day*, state it in the report); `INACTIVITY` on and the class's **local date** inside an `APPROVED`/`ACTIVE` `InactivityPeriod` → `422 INACTIVITY_PERIOD {from, to}`; `levels.enabled` and `Dog.levelId ∉ ClassSession.levelIds` (empty = all) → `422 LEVEL_NOT_ALLOWED`; class `ACTIVE` and `now < startsAt` → `422 CLASS_NOT_BOOKABLE`; week `LATER` → `422 NOT_YET_OPEN {opensAt}`; pack empty or expired → `422 PACK_EMPTY`. `InactivityPeriod` (S13) and `PackBalance` (S12) are **E8**: declare `InactivityPort` and `PackBalancePort` in `clubs/bookings/application/ports` with null-object defaults (`@ConditionalOnMissingBean`: no periods; packs disabled) plus a `test`/`local` in-memory adapter the tests and the demo seed drive, and say in the report that S12 WP-12-E and S13 WP-13-B replace them (decision B11). T-08-04, T-08-10, T-08-23.
4. **`SeatHoldService.hold(classSessionId, dogId, waitlistEntryId?)`** (R-08-07) — one Mongo transaction through a new `BookingTransactions` helper modelled on `SchedulingTransactions` (retry on `WriteConflict`/`TransientTransactionError`, ≤ 3 attempts, 50–150 ms randomized backoff; document the **lock order**: `seat_locks` → `class_sessions`, and note that `cancelAllByClub`, called from a scheduling transaction that already holds the class, must *not* take `seat_locks`): `seat_locks.findOneAndUpdate({_id: classSessionId}, {$inc: {version: 1}}, upsert)` → eligibility → limits → `taken = bookings ACTIVE|PAYMENT_PENDING + live seat_holds of other dogs` (**always** filter `expiresAt > now`: the TTL lags up to 60 s, T-08-33) → `taken ≥ ClassSession.capacity` → `409 CLASS_FULL {heldOnly: activeBookings < capacity}` (or `409 SEAT_TAKEN` when `waitlistEntryId` is present) → upsert the dog's hold with `expiresAt = now + bookings.seatHoldSeconds` (re-entering **refreshes** the same hold) → `SeatHeld`. The response carries `serverNow`, `holdSeconds`, the class and dog cards, `limit{…}` and `pack`. `DELETE /seat-holds/{id}` → delete + `SeatHoldReleased`, 204 also when it no longer exists; TTL expiry emits nothing. T-08-14, T-08-29.
5. **`BookingConfirmationService.confirm(seatHoldId, swapBookingId?)`** (R-08-08, R-08-09) — `Idempotency-Key` (the front sends the `seatHoldId`; a repeat returns the stored response, **including** a stored 409, per `CONVENCIONS_API` §7 and the existing `IdempotencyFilter`): one transaction — hold exists, belongs to the caller's `accountId`, `expiresAt > now` (else `409 SEAT_HOLD_EXPIRED`); lock `seat_locks`; **re-run every check** (state may have changed); limit reached → `swapBookingId` must be in `swappable` (`422 SWAP_NOT_ALLOWED`) and is cancelled first (`CANCELLED`, `cancelReason = SWAP`, `late = false`, pack refunded, `SeatReleased` per R-08-11) ; capacity re-checked excluding the hold; create `Booking` `ACTIVE` (or `PAYMENT_PENDING`, step 7) with `classStartsAt`, `classEndsAt`, `bookingWeekKey` denormalized, `origin`, `bookedBy {accountId, impersonatedMemberId?, displayName}`, `swapFromBookingId?`; `PackBalancePort.consume(dogId, bookingId)`; delete the hold; consolidate a live waitlist entry of the dog if any (`CONSOLIDATED`, the entry service arrives in E5-T03 — call it through a `WaitlistConsolidationPort` in `clubs.bookings.application.ports` with a null-object default this task ships and E5-T03 implements **in the same context**, or wire it directly if E5-T03 is already merged; say which in the report); write `Member.lastDogForClass` of the **booker**; emit `BookingCreated` + `SeatHoldReleased` (+ `PackConsumed`). Response = `Booking` + `calendarLinks {google, outlook, ics}` where the `.ics` URL carries an HMAC token valid until `classEndsAt` (`GET /bookings/{id}/calendar.ics`, `text/calendar`, no JWT, no personal data beyond the class and the dog name). T-08-15, T-08-16, T-08-17, T-08-31, T-08-32.

### Assumptions
1. **Seed booking instant.** `BookingContext.now()` is the injected clock. The only exception is `BookingContext.asOf`, package-private and used only by `DemoBookingSeeder`: the W+2 classes the E4-T05 timeline books are `NOT_YET_OPEN` on the run date. Every rule runs unchanged, but `bookedAt` can be up to a week ahead of the run.
2. **Check order and codes.**
   - An inactive dog answers `404 DOG_NOT_ACCESSIBLE`, as S08 R-08-04 writes («actiu i propi o del grup»), not `DOG_NOT_ACTIVE`.
   - `ALREADY_BOOKED` is checked after the eligibility list.
   - The leave-date check uses the **owner's** `leaveDate` and blocks from the end of that local day (§13-8 + S15 §13-6).
   - `BOOKING_BLOCKED.details = {reason}`, `CLASS_NOT_BOOKABLE.details = {reason: LEAVING}` for the leave case, and `INACTIVITY_PERIOD.details = {from, to}` as ISO dates.
3. **Swap semantics.**
   - `swapBookingId` must be in `swappable` **and** the limit must be reached; otherwise `422 SWAP_NOT_ALLOWED` with no change.
   - At the limit without `swapBookingId`: `422 SWAP_NOT_ALLOWED` when something is swappable, `409 BOOKING_LIMIT_REACHED` otherwise.
   - A counted PAYMENT_PENDING booking is not selectable; outside the threshold it is reported as `LATE_WINDOW`.
   - The old booking of a swap sends N-05 and the new one N-04.
4. **Lock order and concurrency** (javadoc of `BookingTransactions`).
   - Order: `seat_locks` (new class first, then the swapped booking's class) → `class_sessions` counters → `bookings`/`seat_holds`.
   - At most 3 attempts with 50–150 ms backoff, then `409 STALE_VERSION`.
   - In-process fair lanes per club+class keep a burst on one class queued inside a JVM; Mongo write conflicts remain authoritative across replicas.
   - `cancelAllByClub` takes no seat lock: a racing booking conflicts on `class_sessions` and, retried, sees the class CANCELLED.
   - `ClassSessionService.bookingCounters` locked the club-wide catalog documents, which would make every booking of a club conflict with every other. It was replaced by `ClassSessionBookingAccess.counters`: MANDATORY transaction, version CAS, ACTIVE class only.
5. **`cancelAllByClub` also cancels the live waiting-list entries** (R-08-16 `CLASS_CANCELLED`). The task says that half lands in E5-T03, but `bin/e4-smoke` and T-08-25 need `waitlistIds = 2`. E5-T03 can move the loop into its waiting-list service. No `BookingCancelled`/`WaitlistLeft` event is emitted here: N-08a notifies.
6. **Ports (decision B11).** Defaults are null objects in `BookingsAutoConfiguration`, which backs off to any application or test bean:
   - `PackBalancePort` (packs disabled) and `InactivityPort` (no periods): replaced by S12 WP-12-E and S13 WP-13-B in E8. The local/test in-memory stand-ins are used by the tests and the seed.
   - `AttendanceStatePort` (E6).
   - `WaitlistConsolidationPort` (E5-T03, same context; shipped as a null object because E5-T03 is not merged).
   - `SingleClassChargePort`: default over `UpfrontPayments.createOne` (`concept = SINGLE_CLASS`) + `PaymentProvider.createCheckoutSession` (metadata `bookingId`, expiry `bookings.paymentPendingMinutes`); replaced by S12 WP-12-D in E8.
   - The pack stand-in does not emit `PackConsumed`/`PackRefunded`; the real S12 adapter emits them in the same transaction.
   - The pack applies when PACKS is on and the port returns a balance (S12's real adapter will decide on `Plan.type = PACK`).
   - `checkoutUrl` is returned in the 201 only (not persisted).
   - Without a payment gateway (staging/prod before E8), PAY_TO_BOOK answers `501 NOT_IMPLEMENTED`.
   - The existing signup checkout's `UpfrontPaymentSucceeded` carries no `bookingId`, so the consumer ignores it.
7. **`ClassOccupancyQuery.booked`**: the existing S14 adapter in scheduling (`SchedulingDashboard.schedulingOccupancy`) reads `counters.booked`, which the booking transactions now maintain. I added no second bean. `BookingActivity` is the new real adapter (`dogsWithBooking` by class start over ACTIVE/CANCELLED_LATE; `activeBookingsByLevel` by the dog's current level).
8. **`ClassBelowMinimum`.**
   - Payload is the catalog's `{classId, countedDogs, minDogs}` (the task and S15 write `classSessionId`; kept consistent with E5-T01).
   - `countedDogs` = ACTIVE + PAYMENT_PENDING bookings.
   - Emitted on any in-time cancellation (member, swap, system) of an ACTIVE, not-yet-started, non-exempt class, once until the count reaches `classes.minDogs` again.
9. **Audit, one entry per mutation.** An impersonated late cancellation writes `BOOKING_CANCELLED_BY_CLUB` (with `late = true` in the diff), not also `BOOKING_CANCELLED_LATE`. The actor is the admin and the impersonated member is recorded.
10. **Notifications.**
    - Recipients: N-04 goes to the owner and to the group member who booked. N-05 goes to the owner only (S08 §8 names the second recipient for N-04 only). SYSTEM cancellations produce no S08 notification (S13/S15 notify).
    - N-36 carries the catalog variables. `actor` is the localized «el club» (`notif.N-36.actor`), and a rendering-only `change = BOOKED|CANCELLED` selects the created/cancelled wording. `club_name`, `entityId` and `action = OPEN_BOOKING` are added as in N-08a.
    - `calendar_links` is the `.ics` URL.
    - Email for N-36/N-40 goes to the member's contact address; with an app account on the same address, it goes to that account in the recipient's locale.
11. **Idempotency.** For `POST /bookings` (and the future claim route) the filter uses the retryable branch. It stores 409/422 business outcomes so a repeated key replays them; `STALE_VERSION` and `IDEMPOTENCY_KEY_REUSED` release the key instead.
12. **`.ics`.** The token is `HMAC(clubId|bookingId|exp)` with `exp = classEndsAt`. It uses a new env var **`BOOKING_CALENDAR_KEY`** (32 bytes base64), random in local/test and **mandatory in staging/prod** like `SIGNUP_CAPABILITY_KEY`, documented in `.env.example`, `DEPLOY.md` and both compose files. Any mismatch answers 404. The URL host is the club's verified `clubs` domain; it falls back to a relative path. The body holds only class data and the dog's name.
13. **Consumers** run inside the outbox dispatcher's transaction (no lanes). A conflict fails the delivery and the outbox redelivers it. The redelivered update is a no-op (T-08-46).
14. **`cancelFutureByMember`** (S15 P5c / S13) and `cancelBySystem` are implemented and tested, never late, pack refunded. They are not scheduled here.
15. **`NotificationQueued` payload.** It says `channel: EMAIL` for APP rows (seen in the curl log). This is pre-existing behaviour of `SystemNotificationService.appOnce`; I did not change it.
