# E0-T10 · Club-as-code: CLI runner, club:apply with dry-run diff, JSON schema, seeds canic / minim / template

## Objective
Work package WP-17-A (E0 part): a club is fully described in a YAML file and applied idempotently; three seeds exist. Catalog sections (levels, rings, plans, FAQ, message templates) are defined in the schema now and applied by later stages without changing the format.

## Spec references
`docs/specs/S17-consola-de-clubs.md` §3–6, R-17-01, R-17-02, tests **T-17-01** (E0 part), **T-17-02** (host uniqueness) · `docs/specs/S02-*.md` §7 (seeds) and **T-02-12** · `docs/MODEL_DADES_PLATAFORMA.md` §2 · `docs/specs/00-transversal/CATALEG_PARAMETRES.md` (Cànic values) · `docs/specs/00-transversal/CATALEG_MODULS.md` (presets).

## Context to load
S17 §3–6, §9 · S02 §7 · MODEL §2 · the two catalogs · this file.

## Steps
1. `seeds/club-definition.schema.json` (JSON Schema 2020-12) with sections `club` (slug, name, locales, defaultLocale, timeZone, currency, countryProfile, status), `domains[] {host, primary}`, `theme`, `modules[]` or `preset`, `paymentProviders[]`, `parameters {key: value}`, `admins[] {email, name, locale}`, `catalogs {levels[], rings[], instructors[], plans[], prices[], faq[]}` (defined now; applied from E2), `messageTemplates[]` (applied from E7). Validate with networknt `json-schema-validator`.
2. CLI runner: when the app is started with `--core.command=<name> [args]`, run the command and exit with code 0/1 **without** starting the web server (`spring.main.web-application-type=none` when the property is present). Script `bin/core` = `java -jar target/core-api-*.jar --core.command="$@"` (builds the jar if missing). Register `identity:seed-test-accounts` from E0-T09.
3. `club:apply <file> [--dry-run]`: validates the file, computes a readable diff per section (`+ added`, `~ changed`, `= unchanged`), applies inside a transaction, writes an `AuditEntry CLUB_APPLIED` with the summary, publishes `ClubUpdated` / `ParameterChanged` (catalog names) **only if something changed**; idempotent (second run = 0 changes, no events); a second club with an already used host → error `HOST_ALREADY_USED` (T-17-02 part); a module without its dependencies → `MODULE_DEPENDENCY`. `club:export <slug>` prints the YAML of an existing club.
4. Seeds (fictional people only, `@example.test` emails): `seeds/club-canic.yaml` (Europe/Madrid, `ca` + `es`, EUR, ES, hosts `app.agilitycanic.cat` + `admin.agilitycanic.cat`, theme with the mockup colors — take them from `docs/pantalles/**/*.html` `:root` variables —, preset `CANIC`, `paymentProviders [SEPA_XML, MANUAL]`, every parameter whose Cànic value differs from the product default), `seeds/club-minim.yaml` («Club Mínim», `en`, GENERIC, AgilityHub theme, preset `MINIM`, `STRIPE` + `MANUAL`, hosts `minim.example.test`), `seeds/club-template-default.yaml` (template for cloning; no domains).
5. Expected fixtures for T-02-12: `src/test/resources/fixtures/branding-canic.json`, `parameters-canic.json`.

## Verification (run all; paste full output in the report)
- `bin/core club:apply seeds/club-canic.yaml --dry-run` → diff with every section `+`; `bin/core club:apply seeds/club-canic.yaml` → applied; run again → «0 changes»; `mongosh --eval 'db.domain_events.countDocuments()'` unchanged between the 2nd and 3rd run (events are named `ClubUpdated` / `ParameterChanged`).
- `bin/core club:apply seeds/club-minim.yaml`; `curl -H 'X-Club-Host: app.agilitycanic.cat' localhost:8080/api/v1/branding | jq .theme.colors.primary` and the same for `minim.example.test` → two different themes.
- A copy of the seed with `PACKS` but no `BILLING` → exit 1 with `MODULE_DEPENDENCY`; a copy with the Cànic host under another slug → exit 1 with `HOST_ALREADY_USED`.
- `./mvnw -q verify` → green with T-02-12, T-17-01 (E0 scope), T-17-02 and a schema test over the three seeds.
