# E0-T01 · Repository skeleton, Maven build and context architecture test

## Objective
A Maven project that compiles and runs its tests, with the bounded-context package structure and an ArchUnit test that protects it. This is the base of every other task.

## Spec references
`docs/PLA_BACKEND.md` §1–4 · `docs/decisions/ADR-001` (modular monolith), `ADR-002`, `ADR-003`, `ADR-004` · `docs/MODEL_DADES_PLATAFORMA.md` §0 (glossary).

## Context to load
`AGENTS.md` · `docs/PLA_BACKEND.md` · `docs/decisions/ADR-001-*.md` · this file.

## Fixed conventions (do not change)
- Java **21**, Spring Boot **3.5.x**, Maven wrapper (`./mvnw`), base package `com.agilityhub.core`, MongoDB 7 (replica set, needed for transactions), virtual threads enabled (`spring.threads.virtual.enabled=true`).
- Contexts (one package each) with the four layers `api`, `application`, `domain`, `persistence`: `shared`, `platform`, `identity`, `clubs.census`, `clubs.catalogs`, `clubs.scheduling`, `clubs.activities`, `clubs.bookings`, `clubs.training`, `clubs.followup`, `clubs.messaging`, `clubs.common`, `courses`, `payments`, `migration`.
- Pin every dependency version (no ranges). Suggested starters: web, validation, data-mongodb, security, oauth2-resource-server, oauth2-authorization-server, actuator, aop; plus springdoc-openapi-starter-webmvc-ui, icu4j, caffeine, bucket4j, json-schema-validator (networknt), testcontainers (mongodb, junit-jupiter), archunit-junit5, jacoco-maven-plugin, pitest-maven (profile `mutation`, not blocking), maven-enforcer-plugin (Java 21).

## Steps
1. `./mvnw` wrapper + `pom.xml` with the dependencies above; `CoreApplication` (`@SpringBootApplication`).
2. Create every context package with a `package-info.java` and the four layer packages (a `.gitkeep` or the package-info is enough).
3. `src/test/java/com/agilityhub/core/arch/ArchitectureTest.java` (ArchUnit): (a) classes in `..domain..` do not depend on `org.springframework.web`, `org.springframework.data`, `org.springframework.security` or `jakarta.servlet`; (b) no cycles between contexts (`slices().matching("com.agilityhub.core.(*)..")`, treating `clubs.*` sub-contexts as separate slices); (c) a context may only depend on another context's `..application..` package (never `..persistence..` or `..api..`); (d) `shared` depends on no other context.
4. `src/main/resources/application.yml` with profiles `local`, `test`, `staging`, `prod`; every secret as `${ENV_VAR}`; `.env.example` listing every variable with a one-line comment; `.gitignore` (target, .env, *.pem, IDE files); `.editorconfig`; `README.md` (start in 5 commands); `CHANGELOG.md` (Keep a Changelog, "Unreleased" section).
5. `GET /api/v1/health` (public) returning `{"status":"UP","version":"...","builtAt":"..."}` from Spring Boot build-info (`spring-boot-maven-plugin` `build-info` goal).

### Assumptions

- The organizer's 2026-09-06 protocol answer resolves the earlier Git blocker. No branch creation is a prerequisite. This task has no dependency on another unverified roadmap task.
- The local profile alone excludes Mongo client/data/repository auto-configuration, explicitly permitted by this task. E0-T02 will supply the MongoDB 7 replica-set development stack. MVC and property-binding tests need no running MongoDB; no persistence behavior is claimed here.
- `configuration` is application wiring outside the 15 context slices, as allowed by PLA_BACKEND.md §1. A custom ArchUnit SliceAssignment splits `clubs.*`; the simple `(*)` pattern would merge those contexts. Only the domain rule allows an empty selection until domain classes exist.
- Dependency versions managed by the pinned Spring Boot parent are fixed transitively; libraries outside that parent have explicit version properties. Maven/Java enforcer ranges constrain installed tools, not dependency resolution. Version references: [Spring Boot managed coordinates](https://docs.spring.io/spring-boot/3.5/appendix/dependency-versions/coordinates.html), [Apache Maven Wrapper](https://maven.apache.org/tools/wrapper/index.html).
- Staging/prod use discrete Mongo connection properties so the environment username/password are applied. A URI would override those separate credentials in [Spring Boot's connection-details implementation](https://github.com/spring-projects/spring-boot/blob/v3.5.16/spring-boot-project/spring-boot-autoconfigure/src/main/java/org/springframework/boot/autoconfigure/mongo/PropertiesMongoConnectionDetails.java). Required variables and optional defaults are documented in `.env.example`; no credential values are committed.
- Health is global public liveness and does not resolve tenants. Default generated users are disabled; other application routes are denied until identity/security roadmap work implements them. No business errors, audit actions, events, notifications, or parameters are introduced.
- The small snapshot script captures the initial health contract from the running local API. Full OpenAPI conventions and CI diff enforcement remain subsequent tasks; no other task file was opened or changed.
- `./mvnw -q verify` and quiet dependency listing suppress Maven INFO output, including BUILD SUCCESS and test summaries. Both required quiet commands were run; supplemental non-quiet commands below expose the requested build/test/dependency evidence.
- The optional mutation profile is configured but not executed; it is not a required verification command.
