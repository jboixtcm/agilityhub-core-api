### Assumptions

1. **What «draw it in the ring's frame» needs (step 1).** The member's `placement` carries the placement's `transform` and `resolvedObstacles` (both, as the step lists them) and the ring geometry's `lengthM`/`widthM` as `ringLengthM`/`ringWidthM`: without the ring's size the viewer cannot draw the ring's frame, and a MEMBER cannot read `GET /rings/{id}/geometry`. Doors, no-go zones, markers and the placement's warnings stay the staff's. No new route: R-16-16's list of member reads is unchanged.
2. **`MemberRingSetup.courseId`** is the *live* course the setup shows (its own, else its placement's, as `hasViewer` already computes it): `null` when that course was deleted, since `GET /courses/{id}` would be `404` anyway. The staff's `RingSetup.courseId` stays the stored value (staff read the placement).
3. **`builtByName`** is the name of the builder's `Account` while that account has a membership in the club (`CensusIdentityService.displayName`, the same lookup S06's `createdByName` uses), else `null`. It is on every staff projection of a setup (the five routes that return `RingSetup`), resolved once per builder on a history page. The member's projection never has it, as S16 §2 says («l'autor només per a instructors»).
4. **`GET /rings/{id}` for an INSTRUCTOR** returns the reader projection S05 §6 already defines for MEMBER/INSTRUCTOR reads, and keeps refusing an impersonated session. MEMBER stays `403` here (they read rings through `GET /rings`). The S05 table still says «com `/levels`» (ADMIN) for `GET /rings/{id}`; S16 §6 now lists the INSTRUCTOR read, and `MATRIU_PERMISOS` already gives INSTRUCTOR «R» on catalogs. S05 is not edited (not in this task).
5. **Step 4's scope.** Besides §2, §6 and T-16-10, the same two discrepancies were in §3 (`BuildSession.obstacles[].status`), §5 (the session diagram) and R-16-11 (`PENDING`, and «`409 STALE_VERSION` només a nivell de sessió tancada»); they are aligned too, so S16 has one set of statuses and one error for a closed session. The session statuses in §5's diagram (`OPEN · FINISHED · ABANDONED` vs the contract's `NOT_STARTED · IN_PROGRESS · COMPLETED · ABANDONED`) are not touched: not asked.
