## Steps
1. **`MessageTemplateService` + `MessageTemplateController`** (ADMIN only; `GET /message-templates` returns `items` in the D9 order — grouped by category `OPERATIONAL · PERSONAL · CLUB_CHANGES · CLUB_NEWS` — with `countsByCategory`, `caps` and `push` read from the `NotificationCatalog`, `variables[{key, label}]` with the label from `notif.variable.<key>` in the **admin's** locale and the code key as the stored value, and `lastChange` from the audit query (R-14-11)). `POST` creates a `CUSTOM` template (`category ∈ PERSONAL · CLUB_NEWS · CLUB_CHANGES`, member variables only, no action, 201). `GET /{id}` adds `titleI18n`, `bodyI18n`, `smsBodyI18n` maps and `seedDefault` (for the «Restaura el text per defecte» diff). `PUT /{id}` edits title, body, `smsBody`, icon, colour, matrix, `enabled` (+ `category` on `CUSTOM`) with `version` → `409 STALE_VERSION`; `DELETE /{id}` archives a `CUSTOM` one (204). Validation, with the exact code and status (`CATALEG_ERRORS.md` rule 0 wins over S11 §6): a matrix cell outside `caps` → `CHANNEL_NOT_ALLOWED` (**422**); `mandatory` (N-02, N-08a, N-15, N-17, N-32c, N-36) with `enabled = false` → `TEMPLATE_MANDATORY` (**422**); `reset` on a `CUSTOM` → `TEMPLATE_NOT_CATALOG` (**422**); `DELETE` on a `CATALOG` → `TEMPLATE_NOT_CUSTOM` (**422**); unbalanced ICU braces → `TEMPLATE_SYNTAX_ERROR` (**400**); a `[[var]]` outside the code's variables → `TEMPLATE_UNKNOWN_VARIABLE` (**400**); a missing `requiredVariables` entry (N-02 `link`, N-08a `admin_text`) → `VALIDATION_ERROR` (**400**) with `details.missingVariables[]` **and** a report proposal for `TEMPLATE_MISSING_VARIABLE` (E7-T01 already raised it — repeat it only if still unanswered); `smsBody` empty with an active SMS cell → `SMS_BODY_REQUIRED` (**400**); rendered `smsBody` over 160 GSM-7 characters with the sample data set → `SMS_BODY_TOO_LONG` (**400**); `body` over 2000 → `VALIDATION_ERROR`. Every change emits `MessageTemplateChanged{templateId, diff}`, writes `@Audited(CATALOG_CHANGED)` (`entityType = MessageTemplate`) inside the same transaction, sets `customized = true` when the text differs from the seed, and invalidates the per-club template cache. T-11-16.
2. **Preview and test send**: `POST /message-templates/{id}/preview {locale, draft?{title, body, smsBody}, sendTest?}` renders the **unsaved** draft with the fictional data set (`notif.preview.*` per locale: «Laura», dog «Duna» level «C», «dimecres 12 · 18:50 · B+C · Central», the rain admin text) and returns `{title, body, emailSubject, emailHtml, sms{text, length, segments, truncated}, warnings[]}` — `warnings` carries unknown variables and a truncated SMS instead of failing. With `sendTest: true` (the backlog's «envia prova») the same rendering is delivered **once** to the acting admin's own account through the engine, `dedupKey = test:{templateId}:{accountId}:{instant}`, audience `ADMINS`, channels APP + EMAIL only (never SMS, never another recipient), and the notification is stored in the log like any other. If E7-T01 did not publish `sendTest` in `TemplatePreviewRequest`, add it here, regenerate `bin/openapi-snapshot` and add the `docs/openapi/CHANGELOG.md` line. T-11-17 (draft preview in `ca`, `es`, `en` with `sms.length/segments/truncated` and the unknown-variable warning).
3. **Seed of the catalog templates**: `seed/message-templates.{ca,es,en}.json` — one entry per `NotificationCatalog` code with `stage = R1` and `category != SYSTEM` (`SYSTEM` codes never get a template, R-11-01), each with `title`, `body`, `smsBody` (only where a cap allows SMS), `icon`, `color` and the default matrix from the catalog's «Públic → canals per defecte» column. The `ca` texts of N-08a, N-15, N-16, N-09, N-19, N-06, N-04, N-02, N-28 and N-13 are **verbatim from S11 §8** (including the ICU `{gender, select, female {Benvinguda} other {Benvingut}}` of N-02 and `{kind, select, TRAINING {…} other {…}}` of N-13); every other code takes its catalog name as the title and a short product body built from its own variables. `es` and `en` are translations of the same content (they are reviewed before go-live — say so in `seeds/README.md`). Staff copy (`notif.N-xx.staff.title/body`) stays in `messages_{ca,es,en}.properties`, never in the seed. Applied per club by `club:apply` (`seeds/club-canic.yaml` gains the templates section, `SMS` and `PUSH` on) and lazily on first use for a club created before a code existed (R-11-01). `reset` restores exactly this seed and clears `customized`. Product defaults only: no Cànic literal in code, everything in the seed files. Add a test asserting one seeded template per eligible catalog code in the three locales, with `[[var]]` sets inside the code's variables.
4. **Notification log** `GET /notifications`, `GET /notifications/{id}`, `GET /notifications/filter-values` (ADMIN): universal list (`ListEngine`, `filter=<field>:<op>:<value>`) over `code`, `category`, `channel`, `status`, `memberId`, `createdAt`, sorted `createdAt desc`; an undeclared field → `INVALID_FILTER` (400); the detail shows the rendered body plus `deliveries[]` with provider reference and last error. Wire the already published `GET /notifications/export` (E2-T01, R-14-12) to the same list definition so columns and filters match. A club never sees another club's rows (`TenantRepository`, 404 on a foreign id). T-11-26, T-11-29.
5. **Member feed** `GET /me/notifications?page&size&audience?` (MEMBER, INSTRUCTOR, ADMIN, including impersonation): only notifications of the caller's account **that have an `APP` delivery**, `createdAt desc`, 20 per page; each item carries `icon`, `color`, rendered `title`/`body`, `channels[]` (SMS listed only when its delivery is `SENT` or `DELIVERED`; email is not shown — assumption in force), `readAt` and `action {type, params, enabled}` where `enabled` is computed at read time (`CLAIM_SEAT` → the waitlist entry is still `NOTIFIED` and, in FIFO mode, `confirmBy > now`; `CHANGE_CLASS` → the dog is still accessible). `POST /me/notifications/{id}/read` and `/read-all` are idempotent (`read-all` marks everything created up to `now`) and return `{unreadCount}`; `unreadCount` must agree with `GET /me/home` (S08). A notification of another account → 404. An instructor sees N-21/N-22 in the same feed. T-11-19.
6. **Preferences** `GET /me/notification-preferences` → `{emailByCategory, smsFixed: true, reminderMinutesBefore, reminderOptionsMinutes[], pushClubNews, locale, availableLocales[], modules{sms, push}}` with the product defaults when the member has no block stored (`OPERATIONAL: false`, `PERSONAL: true`, `CLUB_CHANGES: true`, `CLUB_NEWS: true`, `pushClubNews: true`, `reminderMinutesBefore: null`); `PUT` is partial (an absent field is untouched) and validates `reminderMinutesBefore ∈ messaging.reminderOptionsMinutes` or `null` → otherwise `INVALID_REMINDER_OPTION` (**422**, rule 0 — S11 §6 writes 400); `PUT /members/{id}/notification-preferences` (ADMIN, D10 block) does the same and is **audited** with the existing `MEMBER_UPDATED` (`changes[].path = notificationPreferences`, `actorAccountId`; no dedicated audit action exists — repeat the observation in the report). Both emit `NotificationPreferencesChanged{memberId, diff, byAccountId}`. Preferences can only remove channels the template allows: `APP` never, `SMS` never («+SMS» is fixed), `PUSH` only for `CLUB_NEWS` — the enforcement lives in the `ChannelResolver` (E7-T02); here you only store and expose. `availableLocales` = `club.locales`, `locale` = `Account.locale` (the selector itself writes through `PATCH /me`, S01 — do not duplicate it). T-11-20.
7. **Push subscriptions** `POST /push-subscriptions {endpoint, keys{p256dh, auth}, deviceLabel?}` and `DELETE /push-subscriptions/{id}` (MEMBER, INSTRUCTOR, ADMIN; `@RequiresModule(Module.PUSH)` → `404 MODULE_DISABLED`): upsert by `endpoint` (stored hashed) for the caller's account, `deviceLabel` from the User-Agent when absent, emits `PushSubscribed`/`PushUnsubscribed`; a malformed endpoint or key → `PUSH_SUBSCRIPTION_INVALID` (**422**, rule 0); another account's subscription → 404. The sender and the expiry transitions are E7-T02. T-11-21.
8. **Screen 30 (Info)**: `GET /faq-entries` already exists (`clubs.catalogs`); make sure the reader projection returns only `active` entries with `category`, `question`, `answer` resolved in the reader's locale with the club fallback, ordered per S05 R-05-22, for MEMBER and INSTRUCTOR, and that `FAQ` off → `404 MODULE_DISABLED` (R-11-14). The 05-09 change of S11 adds the tabs **FAQ · Normes · other active `ClubPage`s** to screen 30: the pages come from the existing `GET /club-pages?active=true` (`clubs.content`) — verify that contract serves the member role and say in the report what, if anything, you had to add. No new entity here. T-11-27.
9. **Roles, tenant and impersonation** (T-11-28, T-11-29): every route of §6 with its allowed role 2xx and each denied role 403 (MEMBER and INSTRUCTOR on `/message-templates*` and `/notifications*`); an impersonation token may read and mark the feed and save `/me/notification-preferences` (audited) but is rejected on `/message-templates*` and `/notifications*` (403 `IMPERSONATION_DENIED`); no template, notification or subscription of club A is visible or modifiable from club B (404).
10. **i18n**: back-end keys `notif.variable.<key>` (D9 chip labels: `member_first_name` «persona_nom», `member_last_names` «persona_cognoms», `member_name` «persona_nom_complet», `dog_name` «gos_nom», `level_name` «gos_nivell», `class_date` «classe_data», `club_name` «entitat_nom», `admin_text` «text_admin», `effective_date` «persona_data_baixa», and one per remaining variable), `notif.preview.*` (the fictional data set per locale), `enums.notificationCategory.*` («Operativa», «Comunicats individuals», «Canvis en reserves», «Comunicats del club»), `enums.deliveryStatus.*`, `enums.notificationChannel.*`, `enums.templateIcon.*`, `enums.templateColor.*`, `error.<CODE>` for every code in step 1 — all three of `messages_ca/es/en.properties` in the same commit (the parity test enforces it). Screen literals never contain internal words, parameter keys or requirement codes, and never «parella/parelles».

## Fixed conventions

New parameter/event/notification/error code → proposal in the report and in `roadmap/MESSAGES.md`, closest existing item used meanwhile.
- Assumptions in force (do not re-decide): the 4th preferences row `CLUB_NEWS` exists although mockup 12 does not show it (S11 §13-2, B21); entering screen 11 marks everything read; the feed shows «i per SMS» but never «i per correu»; staff texts are non-editable product copy; non-mandatory templates may be disabled and `CUSTOM` templates in `CLUB_CHANGES` may carry SMS; the seeded FAQ/club-rules texts stay `[Text pendent — el club l'omplirà des de Paràmetres]` (B22) — never invent club copy.

- `LocalizedText` everywhere for template text; the recipient's language wins over the template's language (R-11-15); `Clock` injected; instants UTC, club-local dates through `ClubClock`.
