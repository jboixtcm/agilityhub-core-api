# E8-T13 · The S13 contract fields the web still overlays

## Objective
The review of E8-W04 found that the web still overlays three contract fields that the api has not published (`packages/api-client/openapi/pending.json` in the web repo, quoted below). S13 needs them, so the api publishes them and the web drops the overlays before the E8 gate (ruling E105).

## Spec references

## Context to load
The web's overlays: `SavedView.system` (`boolean`) and `DashboardCounters.pendingInactivityRequests` / `pendingLeaveRequests` (`integer`, `int32`) · `AGENTS.md`.

## Steps
1. **`SavedView.system`** (boolean, read-only). It is `true` for the shared system view «Baixes previstes» of D5 (R-13-17), which every admin of the club sees and nobody can edit or delete, and `false` for every other view. If the api does not create that view yet, create it as R-13-17 says.

### Assumptions

- **Leave state name:** S13 §3/§5 and `LeaveRequestState.PENDING` define the leave decision queue. S14 R-14-08 still says `LeaveRequest REQUESTED`, which is out of date. The code follows the model/S13 (`PENDING`).
