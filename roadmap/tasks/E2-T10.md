# E2-T10 · Playoff migration: MappingConfig, input schema, migration:anonymize and migration:playoff --dry-run (S18 WP-18-A/B)

## Objective
Work packages WP-18-A and WP-18-B: the census importer runs end to end in dry-run over anonymised fixtures. **The column names are known (09-09)**: `docs/MAPATGE_CAMPS_PLAYOFF.md` documents the three exports (`Socis` 51 columns, `Associats / Tipologia`, `Associats / Nivell`, joined by `ID associat`), the column → field mapping, the measured incidents and the open questions B29–B33 (answers arrive later from Josep: keep those cases as warnings, never guess). Receipts and mandates are **not** exported by Playoff (all mandates are new, S12) — no receipt file in this task.

## Spec references
`docs/specs/S18-migracio-playoff.md` §3 (mapping), §4 steps 1–6 and 9, §11 tests **T-18-01, 02, 04, 06, 08, 10** · `docs/decisions/ADR-008-*.md` · `docs/DECISIONS_PENDENTS.md` A24, B7, B8, B9 · S01 §14 (onboarding of migrated accounts).

## Context to load
S18 §3, §4, §6 (CLI), §11 · ADR-008 · **`docs/MAPATGE_CAMPS_PLAYOFF.md`** (§2 column table, §4 level marks, §6 incident table with codes `NO_BANK_ACCOUNT`, `DOG_INFERRED`, `CHIP_MISSING`, `EMAIL_SHARED`, `AGE_SUSPECT`, `NUMBER_CONFLICT`) · E2-T06 census entities (`Dog.handlerName`, `licenses[].category/division`) · this file.

## Steps
1. `migration/` context: `MappingConfig` v1 (YAML: Playoff plan types → plans, level names → levels, column mapping per file) **pre-filled from `docs/MAPATGE_CAMPS_PLAYOFF.md`** (the typology → plan and level-name → level tables; unknown values → warning rows, e.g. «Quota reduïda», «Familiar Abonat/curs», level «Pendent» until B30–B32 are answered), input schema (`docs/migration/playoff-input.md` listing the 51 + tipologia + nivell columns; unknown/missing columns reported, not guessed). Fixtures: build the anonymised set with the **same column headers** as the real exports and the incident mix of §6 (26 no IBAN, 9 without dog, 16 without chip, 7 without email, ~20 shared emails, 4 duplicate numbers, 2 age suspects, 1 duplicate id document) so every incident code has a test row.
2. `migration:anonymize <dir> <out>`: replaces names, emails, phones, id documents, IBANs and addresses with fictional consistent values (same input → same output), keeps structure; used to build `src/test/resources/fixtures/playoff/` (commit only anonymised fixtures).
3. `migration:playoff <dir> [--dry-run] [--club=canic]`: steps 1–6 (validate, members, dogs, family groups, levels/plans linking, accounts with `onboardingPending`) and 9 (report: created/updated/skipped/errors with row references); idempotent by Playoff ids stored in `externalIds.playoff`; dry-run writes nothing.
4. Members who left more than 5 years ago are skipped (A24a: of the 1 252 «Baixa» records only those since 2021 are migrated, as `LEFT` members with their leave date); surnames carrying «(dog name)» are cleaned per R-18-04(c); one person with two records (same id document) = one member with two dogs (R-18-04(a)); migrated members skip the signup age validation (`AGE_SUSPECT` warning) and get `onboardingPending` (S01 §14).
