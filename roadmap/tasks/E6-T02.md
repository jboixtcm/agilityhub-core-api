# E6-T02 · Attendance, instructor day/week and history (S10 WP-10-B)

## Objective
Work package S10 WP-10-B. An instructor opens the day (20), taps one circle per dog on the class sheet (21) and saves: `PRESENT` and `NO_SHOW` are plain marks inside an edit window, and **`NOTIFIED` («ha avisat») cancels the booking through S08 inside the very same Mongo transaction**, so the seat is released and the waitlist is notified without any chance of an overbooked class. The same save feeds `ClassSession.attendanceSummary` with an optimistic-locking `version`, so two instructors on the same class never lose each other's work. On top of that sit the three read aggregates the screens need — the instructor day (20), the week agenda with its landscape PDF (D12) and the student card with the 30-day metrics (22/D13) — plus the member's own history (25) and the universal `/attendances` list. Tasks, attachments, observations and the D14 follow-up are E6-T03; the P3 and P8 scheduled jobs are E6-T04.

## Steps
1. **`AttendanceRepository`** (`clubs/bookings/persistence`) over the `attendances` document of E6-T01: `findByClassSession(classSessionId)`, `findByBooking(bookingId)`, `findByDogSince(dogId, from)`, `stateOf(bookingId)` (for `AttendanceStatePort`), `upsert` inside a transaction, and **`claimForNoShowNotice(clubId, today)`** (R-10-06 + R-15-13): a `findAndModify` over `state = NO_SHOW ∧ noShowNotice.queuedAt = null ∧ classDate < today` that writes `queuedAt` and `eventId` and returns the claimed documents, using the index `{clubId, state, "noShowNotice.queuedAt", classDate}`. Running it twice claims nothing new (**T-10-08**). E6-T04 calls it from the job; here it only has to exist, be tested and be reachable from a CLI command `attendance:claim-no-show [--club=]` in the style of `FinishEndedCommand`.
2. **`AttendanceWindow`** (pure domain, `Clock` injected, no Spring) — R-10-03: `T0 = 00:00` of `classDate` and `T1 = 23:59:59` of `classDate + attendance.editDays` (1), both in `club.timeZone`; `canMarkPresence(role, now)` → `INSTRUCTOR` only inside `[T0, T1]` (`422 ATTENDANCE_NOT_OPEN` before, `422 ATTENDANCE_WINDOW_CLOSED` after), **`ADMIN` always** (and every admin mark outside the window writes `AuditEntry{action: ATTENDANCE_OVERRIDDEN, entityType: "Attendance", entityId, details {classSessionId, bookingId, from, to}}`); `canMarkNotice(now)` → booking `ACTIVE`, `now ≤ T1` and `bookings.instructorLastMinuteNotice = true` (`422 INSTRUCTOR_NOTICE_DISABLED`); from `NOTIFIED` no transition at all (`422 ATTENDANCE_NOTIFIED_FINAL`); class `DRAFT` or `CANCELLED` → `422 INVALID_STATE`; class `FINISHED` stays markable until `T1`. **T-10-01** (Madrid and `America/Argentina/Buenos_Aires`), **T-10-02**.
3. **`AttendanceSheetQuery`** — `GET /class-sessions/{id}/attendance` (R-10-02): rows = bookings with `state ∈ {ACTIVE, PAYMENT_PENDING}` ∪ those whose `Attendance.state = NOTIFIED` (cancelled by «ha avisat», still visible and `final: true`); bookings cancelled by the member, by the club or by the system are **out**. Order `bookedAt` ascending (assumption in force, S10 §13-7). Each row: photo URL signed for 5 minutes (`AttachmentService.url`), `{guia} + {gos}` from `Dog.handlerName ?? Member.firstName` (R-10-00; when they differ the backoffice projection also carries `memberFullName`), `levelCode` (`null` when `levels.enabled = false`), `pendingTasksCount` from `DogFollowupPort` (null-object → field absent, which is also the `TASKS`-off shape), `notice`, `noShowNotice {scheduledFor = next occurrence of messaging.noShowNoticeTime, queuedAt, sentAt}`. `sheet {version, canMarkPresence, canMarkNotice, editableUntil, savedAt, savedByName, noShowNoticeTime}` from step 2 and from `attendanceSummary`. `waitlist {mode, fifoConfirmMinutes, entries[]}` from `WaitlistService` when `WAITLIST` is on, absent otherwise. Class `CANCELLED` → `canMarkPresence = false`, `canMarkNotice = false`, rows inert. **T-10-10**.
4. **`AttendanceSheetService.save(classSessionId, version, items, actor, idempotencyKey)`** — the heart of the stage, R-10-04, **one Mongo transaction** built on `BookingTransactions` (same `seat_locks` serialization per class that S08 uses, same retry on `WriteConflict`/`TransientTransactionError`): (1) `seat_locks.incVersion(classSessionId)`; (2) `version ≠ attendanceSummary.version` → `409 STALE_VERSION` with `details.current` = the whole current sheet; (3) for every item whose `state` differs from the stored one: validate step 2, require the booking to be live or already `NOTIFIED` (else `422 ATTENDANCE_BOOKING_NOT_ACTIVE {bookingId}`), apply, append to `history[]`, emit `AttendanceMarked {…, previousState}`; an item equal to the current state is a **no-op with no event** (resending the whole sheet is harmless); (4) recompute `attendanceSummary` (including `notifiedAfterEnd`, the `NOTIFIED` rows whose booking stayed `ACTIVE`, added by E6-T01 round 2) and `version + 1`, set `savedAt`/`savedByName`. **Any error rolls the whole thing back** — `422` on one of three items leaves the other two untouched (**T-10-12**). `Idempotency-Key` through the existing `idempotency_records` machinery: the same key returns the same body and emits each `AttendanceMarked` once. The `PUT` response is the `GET` shape plus `applied[]`. **T-10-11, T-10-12, T-10-23**.
5. **«Ha avisat» (R-10-05)** — inside that same transaction, marking `NOTIFIED` with `now < classEndsAt` calls `BookingCancellationService.cancel(bookingId, actor, origin = INSTRUCTOR, reason = INSTRUCTOR_NOTICE)` and stores its result in `notice {at, late, minutesBefore, seatReleased, waitlistNotified, afterClassEnd: false, bookingState}`. If E5-T02's method returns less than `{state, late, minutesBefore, seatReleased, waitlistNotified}`, widen its result record (internal, no contract impact) and say so in the report. Consequences are S08's, not yours: `late = now > classStartsAt − bookings.lateCancelThresholdMinutes` (**240**, threshold itself still in time) → `CANCELLED` with the pack refunded, otherwise `CANCELLED_LATE` with no refund; `SeatReleased {notifyWaitlist = WAITLIST ∧ minutesBefore > waitlist.notifyThresholdMinutes (30) ∧ there are ACTIVE entries}` → N-15 to the waiting members; **N-05 to the member with no SMS** (the action is theirs, S08 R-08-19). The moment that counts is the **save**, not when the member phoned (§13-5). With `classEndsAt ≤ now ≤ T1` the booking is no longer cancellable: record `NOTIFIED {afterClassEnd: true}`, leave the booking `ACTIVE` (it counts as attended) and notify nobody (§13-4). Implement **T-10-03** as a table-driven test with the six rows of R-10-05 (16:00, 16:50:00, 16:50:01, 18:20:00, 19:05, 20:30 over a class on Thu 15-10 18:50–19:50) asserting `late`, booking state, pack refund, `notifyWaitlist` and `afterClassEnd` exactly.
6. **`AttendanceStatePort` implementation** (`clubs/bookings/application`): `stateOf(bookingId)` for S08's `displayState` «no presentat» and for **R-08-10**'s precondition (a booking with `PRESENT`/`NO_SHOW` is no longer cancellable → `422 BOOKING_NOT_CANCELLABLE`). Until Jordi answers S10 §13-6, S08 keeps refusing and S10 additionally consumes `BookingCancelled {by ∈ MEMBER, ADMIN, SYSTEM}`: if an `Attendance` `PRESENT`/`NO_SHOW` exists it is a contradiction → append it to `history[]` and log a warning, change nothing else (S10 §7 consumer table).
7. **Event consumers** (`DomainEventHandler`, idempotent by `eventId`): `ClassSessionUpdated {startsAt}` → refresh the denormalized `classStartsAt`/`classEndsAt`/`classDate` of the class's attendances; `ClassCancelledByClub` / `ClassAutoCancelled` → nothing to write (the bookings become `CANCELLED_BY_CLUB` and fall out of the sheet and the metrics); `DogDeactivated` → nothing (attendance is kept); `BookingCancelled` → step 6.
8. **`InstructorDayQuery`** — `GET /instructor/day` (R-10-01): the dropdown lists active `Instructor`s and preselects `Membership.instructorId` of the caller, an `ADMIN` with no instructor profile getting the first by `shortName` alphabetical order (assumption in force); **no «Tot el club» entry**; 7 day chips from today with `hasClasses`; classes of the selected instructor only, but **ring blocks of everybody**; `individual = capacity == 1`; `attendance.status` from `AttendanceStatusCalculator` (`NONE`/`PENDING`/`DONE`/`CLOSED`, E6-T01); `waiting` only with `WAITLIST`. Empty day → empty `classes` (the literal «Cap classe aquest dia» is the front's). **T-10-09**.
9. **`WeekAgendaQuery`** — `GET /instructor/week` (R-10-15): ISO week of `date` in `club.timeZone`, Mon–Sat (Sunday only if it has items, assumption in force); classes from `CalendarQuery` form B (`ACTIVE` + `FINISHED` + `CANCELLED`, never `DRAFT`) each with `attendanceStatus` and `waiting`; trainings and ring blocks from `TrainingOccupancyService.occupancy(range, ringIds, INSTRUCTOR)` (S09 R-09-12: guide + dog on the training, reason + note on the block); `rows[]` = the distinct start times; a training occupies `training.slotMinutes` (the front paints it half height). Filters: `instructorId` narrows **classes only** (trainings and blocks always show), `ringId` narrows everything; `instructorId=me` resolves to the caller. `classes.maxInstructorsPerClass > 1` → `instructorName` joined («Marc, Neus») and `me` matches any of them. `FREE_TRAINING` off → no `TRAINING` cell. **T-10-20, T-10-33**.
10. **`GET /instructor/week/export?format=pdf`** — the same query rendered **landscape** with the club logo and theme colour, synchronous (`200 application/pdf`, `Content-Disposition` `{club.slug}_agenda_{yyyyMMdd}.pdf`), built with the existing PDFBox/Thymeleaf helpers of `clubs/common/application` (`ExportJobRenderer` is the closest pattern — reuse its fonts, header and footer «Pàgina {n} de {m}» + club name). Labels in the caller's locale from `messages_{ca,es,en}` (`export.column.instructor-week.*` and the day/hour headers), dates and times with `club.timeZone`. It is **not** an `ExportJob`: no `x-exportable`, no S3, no rate limit — say so in the report, since it is the only synchronous PDF in the product so far.
11. **`InstructorCardQuery`** — `GET /dogs/{id}/instructor-card` (R-10-08, R-10-09): window `W = [now − 30 days, now)` over `Booking.classStartsAt` of the dog; `present`, `noShow`, `notified` (in-time, informative), `cancelledLate` = `CANCELLED_LATE` bookings (by the member or by a late «ha avisat») **plus** `NOTIFIED {afterClassEnd}`; `classesCounted = present + noShow + cancelledLate`; `attendancePct = round(100 · present / classesCounted)`, `null` when the denominator is 0. **Assumption in force (S10 §13-1, still with Josep): `cancelledLate` is inside the denominator** — do not change it without a written answer. `ACTIVE` past bookings with no mark count nowhere. `trainingsCount` = `ACTIVE` `TrainingBooking` with `endsAt ∈ W` via `TrainingStatsQuery.countDone(dogId, window)`, **per dog** (§13-8), `trainingsPerWeek = round1(trainingsCount / (30/7))`. `lastClasses` = the 5 most recent with `classStartsAt ≤ now` and `state ∈ {ACTIVE, CANCELLED_LATE}` or `Attendance.NOTIFIED`, with `displayState` per R-10-09 (`PENDING` → «sense marcar», assumption). `level.assignedAt` feeds the front's «fa {n} mesos»; `levels.enabled = false` → `level` absent. The `instructorNote`, `tasks` and `observations` blocks come from `DogFollowupPort` (null-object → absent, same shape as `TASKS` off). Never expose `Dog.remarks` on any `/me/*`. **T-10-04, T-10-05, T-10-14**.
12. **`HistoryQuery`** — `GET /me/history` (R-10-14): items of the dogs the caller can reach (own + family group when `FAMILY_GROUP` is on) with `startsAt ≥ start of local day − history.monthsVisible months`, excluding live bookings (those live on screen 03): class bookings `ACTIVE` with `classStartsAt ≤ now` plus **every** cancelled one, including future ones (§13-14); trainings from `TrainingHistoryQuery.itemsFor(dogIds, from)`; activities from `ActivityHistoryQuery.itemsFor(memberId, from)`. Order `startsAt` desc, max 500, no pagination (assumption). Map `state`, `counts` and `detail.kind` exactly as the R-10-14 table for every `cancelReason` × `cancelledBy.role` of S08 (`MEMBER` in time / late, `INSTRUCTOR_NOTICE` in time / late, `SWAP`, `BACKOFFICE`, `INACTIVITY`, `LEAVE`, `CLUB_CLASS_CANCELLED`, `AUTO_CANCELLED`, `PAYMENT_TIMEOUT`) — the front picks the sentence, the api picks the `kind`. `showDog` = more than one reachable dog. Modules off remove the `TRAINING`/`ACTIVITY` types. A dog that is not reachable → `404 DOG_NOT_ACCESSIBLE`. **T-10-07, T-10-19**.
13. **`GET /attendances`** — universal list through the shared engine with `x-filterable: dogId, memberId, classSessionId, classDate, state` and `x-sortable: classStartsAt, classDate`; an undeclared field → `400 INVALID_FILTER`; MEMBER → `403`. No export (`x-exportable` is not declared for this list in S14 R-14-12).
14. **Notifications.** Nothing new is rendered here: N-05 and N-15 belong to S08 and E5-T02/T03 already dispatch them from `BookingCancelled` and `SeatReleased`. Verify with a test that an `origin = INSTRUCTOR` cancellation produces **N-05 without SMS** and, above the threshold, **N-15 exactly once** per waiting entry (**T-10-11**); if E5 dispatches N-36 instead (the backoffice variant), fix the dispatcher and report it.
15. **Concurrency.** **T-10-23**: two instructors save the same sheet with the same `version` in parallel → one `200`, one `409 STALE_VERSION` carrying the new sheet; the loser reapplies only its own rows and gets `200`; the same `PUT` repeated with the same key is identical. **T-10-24**: an «ha avisat» save and a waitlist `claim` on the same class at the same time → the freed seat is only visible to the `claim` after the save commits (`seat_locks` serialization), zero overbooking. **T-10-13**: with `SINGLE_CLASS` on and `charge.mode = CHARGE_ON_ATTENDANCE`, a `PRESENT` mark emits one `AttendanceMarked {previousState: PENDING}` that an S12 double consumes once, and going back to `PENDING` emits `AttendanceMarked {previousState: PRESENT}`; with the module off the same events fire and nothing is charged.
