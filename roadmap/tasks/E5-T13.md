## Steps
1. **E33: first-run baseline (R-15-05).** A club with no `JobRun` of a process whose latest occurrence is outside the window records `SKIPPED{MISSED_WINDOW}` **without** `JobFailed` or N-42. The next misses alert as today. Test (T-15-04).
2. **E34: late completion (E5-T10 review #1).** A provider completion for a booking checkout session that is already `EXPIRED`, or for a `CANCELLED` booking:
   - logs a WARN;
   - leaves a reconciliation mark on the session or line (for example `lateCompletionAt`, with the provider payment id), so that E8-T04 step 12 refunds it.

   No event and no catalog change. Test.
3. **E5-T10 review #2.** Add an IT for a lease lost without a reaper: delete the `job_locks` document during `apply`. Expect the row `FAILED` with `leaseExpired=true`, only item-1 applied, and one `JobFailed`.
4. **E5-T10 #3.** Add a unit test where `charges.abandon` throws after the provider failure. Expect the original exception to be rethrown, with the abandon failure suppressed.
5. **E5-T10 #4.** When the run that claimed the platform cycle ends `FAILED`, the claim is released, so that another club's run can take the pass the same day. Test.
6. **E5-T10 #5 (AGENTS rule 4).** The `platform*` counters and items are not shown in club-scoped run views (`GET /jobs/{name}/runs`, the D11 history). They stay in the stored `JobRun` and in the platform views. Test with an ADMIN of the club that claimed the pass.
7. **E5-T10 #8.** `TIME_FROM_CLOCK` also forbids `OffsetTime.now`, `Year.now`, `YearMonth.now` and `MonthDay.now`, with or without a zone. Add the `ClockRuleTest` cases.
8. **E5-T09 review #5.**
   - The Javadoc of `SchedulerTick` states the lease limit: renewal happens between clubs, so a single club longer than 55 s can lose the lease mid-tick.
   - Drive the `RENEW_AFTER` branch through `tick.run` with two clubs, in a test.
9. **E5-T09 #6.** Rename `T_15_05_aClubWithNoRunHistory…` and `T_15_05_missedWindowSkipsAndAlerts` to `T_15_04_…`: T-15-04 is the R-15-05 test.
10. **E5-T09 #8.** Remove the bare `422` response from the five `/jobs/{name}*` operations and `/platform/clubs/{clubId}/jobs/{name}/trigger` if no 422 code applies any more. Regenerate the snapshot.
