# E4-T02 · Planning domain (S06 P2): WeekTemplate (WEEKDAYS A/B + SATURDAY), TimeBand, TemplateClass with automatic description, DescriptionResolver, InconsistencyDetector, CapacityCalculator use, CoverageCalculator, WeekGenerationUseCase, template/week/coverage endpoints

## Objective
Work package S06 P2: the club designs its weekly offer (templates with bands and single-day classes, automatic description, inconsistencies, coverage per level) and generates a week as a draft from a WEEKDAYS template (A/B alternation by manual choice) plus the SATURDAY template applied automatically, honouring holidays and the club time zone. Every rule that needs no Mongo is a pure domain service (`clubs/scheduling/domain`, no Spring/Mongo imports, ArchUnit-checked); the template, coverage, weeks, generation-candidates and generation endpoints replace their E4-T01 `501` stubs.

## Steps
1. **`WeekTemplateRules`** (R-06-01, pure): bands with `startTime < endTime`, both multiples of `classes.slotMinutes` (`INVALID_SLOT_GRANULARITY`), no overlap inside the template (`BAND_OVERLAP`), inside `club.openingHours` of every day of the `kind` (`OUTSIDE_OPENING_HOURS`); deleting a band with classes → `BAND_NOT_EMPTY`; changing a band's hours moves its classes (generated weeks untouched). `kind` fixes `days` (`MONDAY..FRIDAY` / `SATURDAY`) and is immutable; `name` unique per club and `kind` (`DUPLICATE_NAME`, case-insensitive); `copyFromId` copies bands + classes with fresh ids. T-06-01.
2. **`TemplateClassRules`** (R-06-02): `bandId` of the same template (foreign → 400 `VALIDATION_ERROR`), one `dayOfWeek ∈ days`, `instructorIds` 1..`classes.maxInstructorsPerClass` active and distinct (`TOO_MANY_INSTRUCTORS`), `ringId` active or null («Sense pista»), `levelIds ≥ 1` when `levels.enabled` (`LEVEL_REQUIRED`), `capacity`/`capacityMode` (R-06-04), `description` (R-06-03). Several classes per band and day. Inconsistencies never block saving. T-06-09, T-06-19.
3. **`DescriptionResolver`** (R-06-03, pure, locale-aware through `IcuMessageSource` keys `scheduling.description.andAbove` «{level} i sup.» / «{level} y sup.» / «{level} and up» and `scheduling.description.join` «+»): `displayDescription = description` if not blank; else from `levelIds` sorted by `Level.order` with `Level.name` resolved in the reader's locale: one level → «{name}»; a **contiguous** set of ≥ 2 levels that reaches the last active level of the catalog → «{first} i sup.»; any other set → names joined with «+»; no levels and `levels.enabled = false` → manual text mandatory (`DESCRIPTION_REQUIRED`); `description: null` restores the automatic text. Store only the manual text; the automatic text is recomputed on every read (template and `ClassSession`). Examples of the rule (catalog Cadells·A·B·C·D·E·F·G): {B,C} → «B+C», {C,D,E} → «C+D+E», {D,E,F,G} → «D i sup.», {A,C} → «A+C», {Cadells} → «Cadells», manual «Obed. urbana» wins until cleared. T-06-02, T-06-34 (`es` → «D y sup.», `en` → «D and up», manual text identical in every locale).
4. **Capacity** (R-06-04): `AUTO` → `min(Level.capacity of levelIds)` through S05 `CapacityCalculator` (reuse, do not duplicate); without levels `classes.defaultCapacity`; recomputed when levels change; an explicit «Límit» → `MANUAL` until `capacity: null`. T-06-03.
5. **`InconsistencyDetector`** (R-06-05, pure; input = a list of `ScheduledItem {id, kind: CLASS·BLOCK·TRAINING, day, start, end, ringId?, instructorIds[], levelIds[]}` + catalog state; output `Inconsistency[]` with a deterministic `id` and an ICU message `scheduling.inconsistency.{type}` in the reader's locale): overlap = same day and `start < other.end && other.start < end`; types `RING_DOUBLE_BOOKED`, `INSTRUCTOR_DOUBLE_BOOKED` (one per shared instructor, R-06-15), `RING_BLOCKED`, `RING_TRAINING_CONFLICT` (only with `FREE_TRAINING`), `LEVEL_INACTIVE`, `RING_INACTIVE`, `INSTRUCTOR_INACTIVE`; «sense pista» never conflicts on the ring. Template scope: its `TemplateClass` per `dayOfWeek` and band. The week scope (DRAFT/ACTIVE classes + ACTIVE `RingBlock` + training bookings) is called by E4-T03 with the same class. `canGenerate = inconsistencies.isEmpty()`; `POST …/generation` on an inconsistent template → `TEMPLATE_INCONSISTENT` with `details.inconsistencies`. T-06-04 (template cases), T-06-10, T-06-19.
6. **`CoverageCalculator`** (R-06-06, pure; only with `levels.enabled`, else `GET /coverage` → `LEVELS_DISABLED` 422): for every active level L in catalog order (Cadells included) over the class set C (template scope = visible WEEKDAYS template + visible SATURDAY template; week scope = non-cancelled `ClassSession`): `maxSeats = Σ capacity` of classes with L ∈ `levelIds`, `propSeats = Σ capacity / |levelIds|`; `dogsTotal(L)` = `Dog.status = ACTIVE` ∧ `Member.status = ACTIVE` ∧ `levelId = L` (census read through `census.application`), `dogsActive(L)` = those with ≥ 1 `Booking` `ACTIVE`/`CANCELLED_LATE` in the current week or the `coverage.activeDogWeeks − 1` previous weeks — through E3-T04's shared `DogActivityQuery`/`BookingActivity` port when present on `main` (null-object → 0 until E5); if E3-T04 is not verified yet, define `scheduling.application.ports.BookingActivityPort` with a null-object and record it; `maxRatioPct = round(100·maxSeats/dogsTotal)`, `propRatioPct = round(100·propSeats/dogsActive)`, denominator 0 → `null` + `NO_DOGS`; status from `coverage.thresholds`: `OK` if > ok · `TIGHT` if tight ≤ x ≤ ok · `SHORT` if short ≤ x < tight · `EXPAND` if < short; `scope = WEEK` adds `booked` (active bookings of dogs of the level in the week; port, 0 until E5). Never stored; recomputed on every read. T-06-05 (A 250/250 «bé», B 180/150 «manca oferta», C 200/200 «ajustat»; 240 → `TIGHT`, 190 → `TIGHT`, 189 → `SHORT`, 149 → `EXPAND`; `activeDogWeeks = 1` counts only the current week), T-06-18.
7. **`WeekCalendarRules`** (R-06-14, pure): ISO-8601 week (Monday–Sunday) computed in `club.timeZone`; `startsAt/endsAt = ZonedDateTime.of(date, time, zone)`; non-existent local time → shifted forward + log line; ambiguous → first occurrence; `reviewAt` helper for R-06-13 (used by E4-T03). T-06-33 (weeks of 19/10 and 26/10/2026 in `Europe/Madrid`: identical local hours, `startsAt` one UTC hour apart; `America/Argentina/Buenos_Aires` without jump).
8. **`WeekGenerationUseCase`** (R-06-07, `application`): candidates = ISO weeks from the current one (club-local today) to +12 not generated; proposal = first week after the last generated one (none → current week); body `weekdayTemplateId` (`kind = WEEKDAYS`, else `TEMPLATE_KIND_MISMATCH`), `saturdayTemplateId?` (`kind = SATURDAY`; `null` → no Saturday classes); preconditions `Week.generatedAt == null ∧ state ≠ VALIDATED` (`WEEK_ALREADY_GENERATED`), no inconsistency in either template (`TEMPLATE_INCONSISTENT`), week not finished (`WEEK_IN_PAST`); for each `TemplateClass`: `date = startDate + offset(dayOfWeek)`; `date ∈ club.holidays` or `date < today` → skipped (`skipped[{date, reason: HOLIDAY·PAST, count}]`); else a `ClassSession` **DRAFT** copying band hours, ring, levels, instructors, capacity + mode, manual description, `origin {templateId, templateClassId}`, `counters {0,0}`, `risk.exempt = false`, derived `startsAt/endsAt`; existing loose classes of the week are kept (no dedup); one Mongo transaction (`Week` get-or-create by `startDate`, `state = GENERATED`, `generatedAt/By`, template ids, `version + 1`, `WeekGenerated{weekId, classCount, templateId}` to the outbox); optimistic lock + unique index → of two concurrent calls one 200 and one `WEEK_ALREADY_GENERATED`; same `Idempotency-Key` → same response (filter of E0). §13-9: generating over a `VALIDATED` week with loose classes → `WEEK_ALREADY_GENERATED`. `POST /weeks {startDate}` = get-or-create (`PENDING`; not a Monday → 400). T-06-11 (2026-W35 with holiday 26/08: 40 + 6 template classes → 41 `DRAFT`, `skipped [{2026-08-26, HOLIDAY, 5}]`; second call 422; `saturdayTemplateId = null`; past week `WEEK_IN_PAST`; current week → past days `PAST`), T-06-22 (two parallel generations → exactly 41 classes, one 200 + one error; same key → two identical 200), T-06-31.
9. **Endpoints** replacing the stubs (`clubs/scheduling/api`): `/week-templates*` (every mutation emits `WeekTemplateChanged{templateId, diff, inconsistencies[]}` and returns form A with `displayDescription` in the caller's locale, `inconsistencies[]`, `canGenerate`; `PATCH` = one change per call with `version` → `STALE_VERSION`; `DELETE …/classes/{classId}` is physical (A22(b)) and audited `@Audited(TEMPLATE_CLASS_DELETED)` with before/after; `DELETE …/bands/{bandId}` physical only when empty (`BAND_NOT_EMPTY` 409 otherwise), audited `@Audited(TEMPLATE_BAND_DELETED)` — in S14 R-14-09 since 16-09), `GET /coverage`, `GET /weeks` (universal list through `ListEngine`, `classCounts` aggregated), `GET /weeks/generation-candidates`, `POST /weeks`, `GET /weeks/{id}`, `POST /weeks/{id}/generation`. INSTRUCTOR reads all of them (A22(c)), never writes. Cache of the template read (60 s per club + locale) invalidated by `WeekTemplateChanged`, `LevelChanged`, `RingChanged`, `InstructorChanged`, `ParameterChanged` — nothing is stored on those events (the detector reads the live catalog).
10. **Usage counters**: make `MongoUsageCounter`/`MongoInstructorUsageCounter` count real template classes (`week_templates.classes[]`) so S05 `LEVEL_IN_USE`/`RING_IN_USE`/`INSTRUCTOR_IN_USE` see them (E2-T03 left the storage contract to this task); S05 «desactivar una pista amb classes de plantilla = incoherència a D3» (part C) is covered by `RING_INACTIVE`.
11. Messages `scheduling.description.andAbove`, `scheduling.description.join`, `scheduling.inconsistency.{RING_DOUBLE_BOOKED|INSTRUCTOR_DOUBLE_BOOKED|RING_BLOCKED|RING_TRAINING_CONFLICT|LEVEL_INACTIVE|RING_INACTIVE|INSTRUCTOR_INACTIVE}` in `messages_{ca,es,en}.properties` (S06 §10; the `ca` values are the mockup literals: «dimecres 20:00 — pista Central amb dues classes alhora», «dj 18:50 — Marc assignat a dues pistes alhora (Cadells i Petita)» rendered from variables `{day}`, `{time}`, `{ring}`, `{instructor}`, `{rings}`).
