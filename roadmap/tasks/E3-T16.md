# E3-T16 · The member's document types in `GET /me/dogs`

## Objective
Screen 13 (`/gossos`, MEMBER and impersonation) has «＋ DOC.»: a dialog with the document type, a name and the file (R-03-15). The types are the club's `census.dogDocumentTypes` catalog.
- The web reads them from `GET /parameters/census.dogDocumentTypes`.
- `/parameters/*` is ADMIN only and refused under impersonation (`SettingsController`: `hasRole('ADMIN') and imp != true`; MATRIU_PERMISOS).
- On the real core the read gets 403, and the dialog falls back to the vaccination card. A member cannot upload `INSURANCE` or `OTHER`.

The web executor of E4-W08 reported it, and the organizer confirmed it in the code. S03 was amended on 25-09: `GET /me/dogs` returns `documentTypes: [{key, label, required}]`. The web adopts it in E3-W12.

Jordi also answered question 4 of E3-T10 on 25-09, and chose the public footer: the Cànic's legal identity goes into its seed, and `/branding` gains the town shown and the registered office (step 3). The web shows them in E3-W12.

This must be done before the gate re-run E3-T11, which depends on this task.

**Each fix comes with a test that fails before the fix.**

## Steps
1. **`documentTypes` in `GET /me/dogs` (R-03-15, R-03-32).** Return the club's catalog as `documentTypes: [{key, label, required}]`:
   - in catalog order, with `label` resolved in the reader's locale (fallback `club.defaultLocale`), like the other `LocalizedText` values;
   - for every member, with or without dogs, and under impersonation;
   - `/parameters/*` stays ADMIN only.
   
   Tests:
   - a contract test;
   - extend T-03-26 (or add an IT next to it): a member in `ca` gets the Cànic's types with Catalan labels, and one in `es` gets Spanish labels;
   - after an ADMIN changes the catalog, the next `GET /me/dogs` shows the new type (the configuration cache is evicted as usual);
   - a member upload with a type from `documentTypes` gets `201`, and an unknown type still gets `400 DOCUMENT_TYPE_UNKNOWN`.
2. **`level` follows `levels.enabled` (R-03-30).** The web will show «Nivell {codi}» only when a dog carries `level`. `CensusQuery.level()` already returns nothing when `levels.enabled=false`. Pin that with a test: with levels disabled, a dog with a stored `levelId` has no `level` in `GET /me/dogs`. This test may pass before any change.
3. **The Cànic's legal identity and the public footer (Jordi, 25-09; E3-T10 question 4; S02 amended).** Jordi wants the footer to read «Club Agility Cànic · G63189617 · Cabrera de Mar», with the registered office below: «Carrer Sant Pere, 10 · 08392 Sant Andreu de Llavaneres».
   - **The club gets `displayCity`** (S02 §3): the town shown with the club's name, optional, defaulting to `address.city`. The club definition (S17), the club settings API and the `club:apply` diff carry it.
   - **`GET /branding`** (R-02-02, additive): `club.city` becomes `displayCity ?? address.city`, and a new `club.legalAddress: {street, postalCode, city} | null` gives the registered office for the footer (LSSI art. 10). It is `null` when the street or the postal code is missing.
   - **The Cànic seed** (`seeds/club-canic.yaml`):
     - `legalName: "Club Agility Cànic"`;
     - `taxId: "G63189617"`, which the Spanish country profile must accept;
     - `address: {street: "Carrer Sant Pere, 10", postalCode: "08392", city: "Sant Andreu de Llavaneres", region: "Barcelona", country: "ES"}`, the registered office;
     - `displayCity: "Cabrera de Mar"`.
   
   Tests:
   - the Cànic's `GET /branding` gives `city` «Cabrera de Mar», its `legalName` and `taxId`, and `legalAddress`;
   - a club without `displayCity` shows `address.city`;
   - a second `club:apply` gives no changes;
   - a contract test.
