## Steps
1. `Money { long amountMinor; String currency }` (value object): `plus`, `minus`, `percent(int bp)` with `HALF_EVEN` rounding, `format(Locale)` with ICU (`45,00 €` for `ca`, `€45.00` for `en`). `LocalizedText { Map<String,String> values; String defaultLocale }` with `resolve(locale)` returning the value or the default-locale value and a `fallback` flag; Jackson serialisation as `{ "ca": "...", "es": "..." }`.
2. `ErrorCode` enum containing **every** code of `CATALEG_ERRORS.md` with its HTTP status; `ApiException(ErrorCode, Map<String,Object> details)`; a `@RestControllerAdvice` producing `{ "code", "message", "details", "traceId" }` — `message` resolved through the message source (E0-T08; until then, the code itself), `traceId` from Micrometer tracing or a generated UUID per request; Bean Validation failures → `VALIDATION_ERROR` with `details.fieldErrors[] {field, code, message}`; unknown routes → 404 `NOT_FOUND` with the same shape. **Test**: parse the markdown tables of `docs/specs/00-transversal/CATALEG_ERRORS.md` and assert the set of codes equals `ErrorCode.values()` (a missing or extra code fails).
3. Idempotency (CONVENCIONS_API §7): a filter/interceptor for `POST` requests carrying `Idempotency-Key`; collection `idempotency_records { clubId, accountId, key, requestHash, status (IN_PROGRESS|DONE), responseStatus, responseBody, createdAt (TTL index 24 h) }`; same key + same body → replay the stored response; same key + different body → the conflict error code defined in the catalog (if the catalog has none, use `409` with code `IDEMPOTENCY_KEY_REUSED` **and list it as a catalog proposal in your report**); concurrent duplicate → second request gets 409 while the first is `IN_PROGRESS`.
4. `Clock` bean (UTC, overridable in tests) and `ClubClock` interface (`LocalDate today(clubId)`, `ZonedDateTime now(clubId)`) backed by a `TimeZoneProvider` interface (implemented by `ClubConfigService` in E0-T05; a simple map-based implementation for now).
5. Outbox: `DomainEvent` interface (`type()` = the catalog name, `clubId`, `aggregateType`, `aggregateId`, `occurredAt`, `payload`), `DomainEventRecord` in collection `domain_events { …, status PENDING|PUBLISHED|FAILED, attempts, nextAttemptAt, publishedAt, error }` with a TTL index of 90 days on `publishedAt`; `EventPublisher.publish(event)` writes the record **in the same Mongo transaction** as the aggregate change (`MongoTransactionManager`); `OutboxDispatcher` (`@Scheduled(fixedDelay = 1000)`, batch 100, claims records with `findAndModify` so several instances do not double-deliver) delivers to every `DomainEventHandler<T>` bean (in-process), marks `PUBLISHED`, retries with exponential backoff (1 s → 5 min), sets `FAILED` after 10 attempts; Micrometer gauges `outbox.pending`, `outbox.failed`.
6. **Test**: every `type()` returned by the `DomainEvent` implementations in the codebase (scan with reflection/ArchUnit) exists in `CATALEG_ESDEVENIMENTS.md` (parse the tables). Include one sample event (`ClubConfigChanged`) so the test is meaningful.

### Assumptions

- Catalog precedence: explicit §1 error HTTP statuses always win. For concrete §2 entries not individually mapped, conflict families (`ALREADY`, `_EXISTS`, `_TAKEN`, `_IN_USE`, `_LOCKED`, `_OVERLAP`, `_CONFLICT`), explicit duplicate/invalid-state/nonempty/full conditions use 409; remaining unmapped preconditions use 422. The complete assignment list is in Evidence; clarification is appended to MESSAGES.md. Wildcards and superseded prose aliases are excluded from enum membership.
- The catalog has no dedicated idempotency error. `STALE_VERSION` is the closest existing 409, with a reason distinguishing different request content from an in-progress request. This follows AGENTS.md's closed-catalog rule while preserving the exact-set contract; the task's proposed new code is recorded for organizer approval instead of silently expanding the enum.
- Model precedence: LocalizedText falls back to first available text if the club default is absent, as MODEL_DADES_PLATAFORMA §2 requires. Empty maps are rejected. The wire map cannot carry a club default; deserialization uses `und` and the caller supplies the club locale with `withDefaultLocale`.
- New infrastructure stays in `shared`, as this task explicitly requires, although the glossary assigns the future outbox concern to platform. Records retain model metadata (`actorAccountId`, per-consumer `processedAt`) plus catalog origin/impersonation metadata and task-required delivery fields. `eventJson`, `claimToken` and `lockVersion` are private persistence support for typed handlers and fenced ownership, not new business catalog items.
- Until E0-T05, `TenantRepository` requires an explicit trusted club scope. Idempotency derives club/account only from an authenticated JWT (never headers/body); keyed anonymous or global requests without club identity are rejected. E0-T09 will supply real JWT authentication; tests supply authenticated JWT principals. The map timezone provider has no club literals and rejects unknown clubs; E0-T05 replaces it with ClubConfigService.
- Idempotency wraps synchronous POST handling and response persistence in one Mongo transaction. The response hash includes method, URI, query, content type and body, preventing cross-target replay. Representation headers (Content-Type, Location, ETag, Cache-Control, Content-Language) are retained; per-request security/session headers are not stored. A thrown request failure rolls back Mongo effects and removes its IN_PROGRESS claim. Process-crash IN_PROGRESS claims remain conflicts until the 24-hour retention expires.
- Outbox claims use a five-minute lease. Each consumer transaction forces a record write before invoking the handler, so another instance cannot take over an active handler's write lock even if the lease expires. Checkpoints commit atomically with the consumer's Mongo changes. External effects still require consumer idempotence by event ID across process crashes; the interface documents this requirement. Bean names are stable consumer IDs, encoded for safe Mongo map keys. No matching consumers is a valid no-op publication.
- Dispatcher defaults are the task's technical constants: 100 records/tick, one second between ticks, ten attempts, 1–300 second exponential retry delays, 90 days after publication. Failed records have no publishedAt and are retained. `shared.scheduling.enabled=false` disables scheduling only in deterministic integration tests; dispatch is called explicitly. Exception class names, rather than potentially sensitive exception messages, are stored.
- Error message keys are `error.<CODE>`, falling back to the code pending E0-T08. Security still denies every known nonpublic route by default; unmapped `/api/v1/` routes reach MVC for NOT_FOUND. The existing deny-all security behavior remains 403 until identity/authentication is implemented.
