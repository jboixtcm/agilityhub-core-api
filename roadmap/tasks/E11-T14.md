# E11-T14 · Jackson 3 with springdoc 3.1

> **The last task of E11.** The organizer opens it only when every other api task is `verified` before the launch rehearsal of 25-10. If that does not happen, it stays `not_open` and the api ships R1 with Jackson 2 (`spring-boot-jackson2` is deprecated in Boot 4.1 but still shipped; this task must land before a Boot release drops it). Never take it from `check.py --next` while it is `not_open`.

## Objective
E11-T07 moved to Spring Boot 4.1 and Spring Framework 7 but kept the JSON on Jackson 2 (`spring-boot-jackson2`, `spring.http.converters.preferred-json-mapper: jackson2`) and springdoc on 3.0.3, because springdoc 3.1 changed the contract (E11-T07 §5b; its study is `roadmap/evidence/E11-T07/10-openapi-diff-attempts.log`). Ruling E132 made both the task at the end of development. This task moves the api to Jackson 3 (`tools.jackson`) and springdoc-openapi 3.1, and proves that nothing observable changes: the contract (`docs/openapi/openapi.json`), what is stored and read back (outbox payloads, idempotency responses, audit diffs), the exports (`data.json`, the club definition, `BuildSessionExportV1`), the SEPA XML, the error contract and the ICU messages.

**No product change, no functional change, no stored-data change.** One task, one publish. The proof is fixtures serialized on the current code and compared byte-for-byte after the upgrade, not a reading of release notes.

## Steps
1. **Baseline on the current code (Jackson 2), before any edit.** Under the host lock: `./mvnw -q clean verify` with its totals; `bin/openapi-snapshot` → no diff, sha256 of `docs/openapi/openapi.json`; `bin/security-scan rootfs target`; `./mvnw -q dependency:tree` lines for `jackson` (both groups), `springdoc`, `swagger-core`, `json-schema-validator`, `sentry`; the PIT run of E11-T07 (`-Pmutation`, `clubs.bookings.domain.*` with its tests) and its score.
2. **The fixtures (the proof).** Add `src/test/java/com/agilityhub/core/configuration/JsonFixturesTest.java` and `src/test/resources/fixtures/json/`: on the baseline, the test writes with the application's mapper and **commits** the golden files; after the upgrade the same test must produce byte-identical bytes and read every golden file back into the same objects. The set, one file each: every outbox event type as `MongoEventPublisher` writes it (list them from `EventCatalogContractTest`'s catalog); the error body of `ApiExceptionHandler` for a 400 with `details`, a 404, a 500 with `traceId`; a stored idempotency response (`IdempotencyFilter`) and its fingerprint; `CensusAudit.view` of a `Member`, a `Dog`, a `FamilyGroup` and a `DogDocument` with an audit diff; `MemberDataExports`' `data.json` for the demo member; a `ClubDefinitionCodec` export of `seeds/club-canic.yaml`; a `BuildSessionExportV1`; a course `normalizedJson` that `CourseSchemas` validates; and the scalar edge cases: `Money`, `BigDecimal` (`taxPercent`: a string in Mongo by `StoredRepresentationIT`; on the wire, whatever it is today), `LocalDate`, `Instant`, `Duration`, nullable fields with `@JsonInclude`, `@JsonIgnore` secrets (`RefreshToken.tokenHash`, `replacedByHash`), `@JsonProperty` names, records with a compact constructor, enums (every enum with a `toString()` override), `Map<String, Object>` payloads with nested lists, an unknown property on input (today's behaviour, whatever it is). Fixture data is fictional.
3. **The upgrade.** Remove `spring-boot-jackson2` and `spring.http.converters.preferred-json-mapper: jackson2`, drop `jackson-2-bom.version` if Jackson 2 leaves the runtime (step 4 decides), keep INC-70's `jackson-bom.version` at the newest 3.1.x. Move the 181 main and 205 test files from `com.fasterxml.jackson.*` to `tools.jackson.*`: `ObjectMapper` → Boot 4's `JsonMapper` bean (`tools.jackson.databind.json.JsonMapper`), `JsonNode`/`ObjectNode`, `TypeReference`, `SimpleModule`, `SerializationFeature`, the checked `JsonProcessingException` → the unchecked `JacksonException` (every `catch` reviewed: a swallowed exception must still be swallowed, a propagated one still propagated), the three runners' `Jackson2AutoConfiguration` → `JacksonAutoConfiguration`. Then restore every Jackson 2 default the fixtures show the api relied on, explicitly, in one place (`spring.jackson.*` in `application.yml` or one `JsonMapperBuilderCustomizer` with a comment per feature): Jackson 3 flips, among others, unknown properties (tolerated), dates and durations (ISO text instead of timestamps), enums (through `toString()`), scalar coercion (off), trailing tokens (refused), `BigDecimal` output; the list you work from is Jackson's own (JSTEP-2), and the fixtures of step 2 decide, feature by feature. The report has the table: feature → Jackson 2 value → Jackson 3 default → what the api sets → the fixture that proves it.
4. **Libraries that embed Jackson 2.** `json-schema-validator` 1.5.9 (networknt) takes a `com.fasterxml` `JsonNode` (`ClubDefinitionCodec`, `PlatformDefinitionSchema`, `CourseSchemas`): move to a release built on Jackson 3 if one exists at the newest line; otherwise keep `com.fasterxml.jackson.databind` only as that library's transitive dependency, bridged in **one** adapter class (bytes in, Jackson 2 tree out, validation messages back), with an `ArchitectureTest` rule that no other class imports `com.fasterxml`. Check in the dependency tree what Sentry's Boot 4 starter, Stripe (Gson), SendGrid, Twilio, web-push and Testcontainers pull; list every `com.fasterxml` artifact that stays in the runtime and why. The dependency audit (`bin/security-scan rootfs target`) and the image scan stay green with no new suppression.
5. **springdoc-openapi 3.1** (newest 3.1.x, swagger-core as it manages it; never pin swagger-core under it: the `##default` leak of E11-T07 §B). `bin/openapi-snapshot`: the contract is byte-identical, or the diff is only ordering or representation changes, explained per path. E11-T07's study found 33 new `minimum`/`exclusiveMinimum: 0` bounds and the class-level `types: ["object","null"]` lost on `LastChange` and `RequiredConsent`: fix `RequiredPropertiesModelConverter` and the nullable module of `OpenApiConfiguration` so the nullable types stay; a new bound is kept only when the code declares it (`@Min(0)`, `@PositiveOrZero`) and is then listed as a documentation gain; a bound the code does not declare is removed by the converter. `OpenApiSnapshotTest`, `OpenApiNullableEnumContractTest`, `OpenApiRequiredContractTest`, `UriReferenceContractTest` and `ListContractValidationTest` green. Any residual diff is a contract change for the web: the organizer stages it (`openapi.next.json`), the web regenerates (E52); say so in `docs/openapi/CHANGELOG.md` with the per-path list.
6. **Error contract and ICU messages.** `S04ErrorContractTest`, every `E*ResponseContractTest` and `E*ContractIT`, `ErrorCatalogContractTest` green; the error-body fixtures of step 2 byte-identical (the `details` map order included). ICU messages are read from properties (`IcuMessageSource`), not Jackson, but the variables the engine receives come from outbox payloads: `TemplateVariableParityIT` and `NotificationEngineIT` green, and one message of each channel compared with the baseline in `bin/e7-smoke`'s output.
7. **Stored data across the deploy.** Mongo mapping is Spring Data, not Jackson (`StoredRepresentationIT` stays green: UUIDs `java-legacy`, `BigDecimal` as string). What Jackson writes to Mongo and reads back later must survive a restart in the middle: an outbox event written by Jackson 2 before the deploy and dispatched by Jackson 3 after (`MongoEventPublisher.readValue` on each golden file of step 2), an idempotency response stored before and replayed after (24 h window), audit `details` maps read by `AuditReadService` and the exports. One IT that inserts the Jackson 2 golden documents into Mongo and reads them through the real repositories and consumers.
8. **The gate's proofs, re-run on the upgraded tree** (host lock, each inside the evidence runner's one-hour deadline): `./mvnw -q clean verify` with totals at or above the baseline (every removed or skipped test explained); `bin/openapi-snapshot`; `bin/security-scan rootfs target`; `docker build` + `bin/security-scan image`; `bin/deploy-smoke`; the smokes E11-T07 ran (`bin/e1-smoke`, `bin/oidc-smoke`, `bin/e8-smoke`, `bin/e10-smoke`) plus the payload-heavy ones (`bin/e5-smoke`, `bin/e7-smoke`); `bin/security-inventory`; the PIT run of step 1 with the same score (E11-T07's `31`: 255 generated, 250 killed). The dependency-tree lines of step 1, after.
9. **Report**: the deprecated APIs removed (no `spring-boot-jackson2`, no `preferred-json-mapper`, no `com.fasterxml` import outside step 4's adapter), the defaults table of step 3, the libraries table of step 4, the contract diff of step 5 (or «byte-identical, sha256 …»), the versions before and after, `CHANGELOG.md` (Unreleased) and `docs/DEPLOY.md` if an environment or override changed.

If springdoc 3.1 cannot keep the contract without a web change that the organizer has not accepted, or a library has no Jackson 3 build and the bridge of step 4 is not clean, set the task `blocked` with the diff or the proposal in `MESSAGES.md` (`@organizer`): the organizer decides whether R1 ships with it.
