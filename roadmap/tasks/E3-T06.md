# E3-T06 · Hardening INC-01…INC-04 + INC-06: health endpoint independent of tenant/data, 500s logged with traceId, compose healthcheck on the real endpoint, configurable Mongo port, TokenResponse.scope always present

## Objective
Five small defects found by Jordi on 09-09 while checking gate E0 on his Mac (`docs/INCIDENCIES_OBERTES.md`). They block the promotion of `main → release` (gate E0) and make any staging incident undebuggable, so they are fixed now instead of in the E10 clean-up round.

## Spec references
`docs/INCIDENCIES_OBERTES.md` INC-01 (`GET /api/v1/health` → `500` with an **empty database**, reproduced with `docker compose down -v && docker compose up -d --build --wait && curl -sS -i localhost:8080/api/v1/health`; also with `Host: app.agilitycanic.cat`), INC-02 (the `500` leaves no trace in the logs), INC-03 (compose healthcheck hits the actuator on 8081, not `/api/v1/health` on 8080 → false «Healthy»), INC-04 (`compose.yaml` publishes `27017` fixed), INC-06 (`TokenResponse.scope` omitted when the granted scope set is empty while the OpenAPI marks it `required`; found by web E1-W04) · S02 R-02-01 (tenant by host; unknown host → `404 UNKNOWN_HOST`, never `500`) · E0-T02 (compose), E0-T04 (error handler), E1-T02/E1-T13 (token response).

## Context to load
`shared/api/HealthController`, `TenantFilter` (public/global route lists), `RequestLocaleFilter` + `RequestLocaleResolver` (they run for every request, including `/api/v1/health`), `ApiExceptionHandler` (E0-T04), `compose.yaml`, `Dockerfile` (actuator port), `identity` token serialisation (`TokenResponse`), `OpenApiSnapshotTest` · this file.

## Steps
1. **INC-01 — find the real cause first**: reproduce with an empty database (`docker compose down -v`, `up --build --wait`, `curl -i /api/v1/health`), capture the exception (after step 2 it will be in the log), and fix it at the source. Expected behaviour: `200 {status: UP, version, builtAt}` whenever the service and Mongo are alive, regardless of `Host` and of the database content (no club yet). `/api/v1/health` (and `/actuator/health`) must not depend on any tenant, locale or club lookup: make the request filters skip it explicitly (`TenantFilter` already lists it as global — check the other filters: locale resolution, rate limit, account state, idempotency) and add an IT that starts the context with an **empty** database and asserts `200` on `/api/v1/health` with and without a `Host` header, plus `404 UNKNOWN_HOST` (not `500`) for a tenant route with an unknown host.
2. **INC-02**: `ApiExceptionHandler` (or a fallback `@ExceptionHandler(Exception.class)`) logs every unhandled exception at `ERROR` with the full stack trace and the correlation `traceId` that the body already carries; expected business errors (4xx) stay at `DEBUG`/`WARN`. Test: an endpoint that throws in a test slice → one `ERROR` log line with the `traceId` of the response (use a log capture appender).
3. **INC-03**: `compose.yaml` (and `docker-compose.consumer.yml`) healthcheck of the `api` service checks `GET http://localhost:8080/api/v1/health` (the actuator check may stay as an additional condition); `docker compose up --wait` must report unhealthy when the endpoint fails. Verify with the reproduction of INC-01 before the fix (unhealthy) and after (healthy).
4. **INC-04**: `ports: "${MONGO_PORT:-27017}:27017"` for the Mongo service in `compose.yaml` (and the consumer file); `README.md` «Run locally» documents `MONGO_PORT=27018 docker compose up` for machines with a local Mongo.
5. **INC-06**: serialise `TokenResponse.scope` always (`""` when the granted set is empty) so the published OpenAPI stays truthful (`required`); IT on the password grant of an account without scopes; snapshot unchanged (or regenerated if the description changes).
6. `docs/INCIDENCIES_OBERTES.md` (synced doc): mark INC-01, 02, 03, 04, 06 as «resolta (E3-T06)» with the commit reference in your report only — the organizer updates the registry itself; do not edit `docs/`.

## Fixed conventions
- No new parameters/events/error codes; `UNKNOWN_HOST` and the existing codes only.
- Keep the fixes minimal and local; no refactor of the filter chain beyond what step 1 needs.
