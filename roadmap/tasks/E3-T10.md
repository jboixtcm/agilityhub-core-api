# E3-T10 · Gate E3 audit fixes (api, 3/3)

## Objective
The last api fix task of the gate E3 audit (`roadmap/reviews/gate-E3/consolidated.md`). It closes the api minors that are not security (E3-T09 took those). It also strengthens the spec tests that the audit found weaker than their §11 row. None of these changes the E3 scope.

Where a minor has behaviour, write a test that fails before the fix.

## Steps
1. **Family claim at submission (R-04-12).** A claim that was FOUND in the lookup, but is no longer unique or eligible at submission, falls back to `NOT_FOUND_PENDING` when `signup.allowFamilyGroupPending` allows it. It must not answer `422 FAMILY_HOLDER_NOT_FOUND`.
2. **`ACCOUNT_NOT_PROVIDED` (R-04-18) reads `ibanLast4`.** Migrated SEPA members have `ibanLast4` without a full IBAN, and must not get a false «Compte no informat». Fix it in `SignupService`, `DashboardRepository` and `CensusListProjection`.
3. **The D2 `PATCH` of `paymentMethod` (R-04-19)** keeps the holder, `holderTaxId` and `mandateSignedAt` unless the request changes them.
4. **Rejection (R-04-23).** `censusSignupRejected` deactivates the dogs of `payload.dogIds`, not «the pending dogs now».
5. **The `Member.signup` snapshot (§3).**
   - Persist `ipHash`, `userAgent`, `paymentMethodTypeRequested`, the frozen `upfront` (with `firstMonth`), `validatedAt`/`validatedByAccountId`, and `rejectedAt`/`rejectedByAccountId`/`rejectionReason`.
   - An add-dog submission must not overwrite the block of the original public signup. Keep the add-dog submissions apart, one per dog; propose the shape for `MODEL_DADES_CANIC.md` in the report.
6. **Event payloads (`CATALEG_ESDEVENIMENTS.md`).**
   - `MembershipChanged` carries the roles before and after.
   - The identity events keep the actor and the origin.
   - `UpfrontPaymentRecorded` carries `memberId`.
   - `DogDocumentPending` carries `trigger`.
   - `MemberValidated.dogs` comes from the persisted state, not from the request.
   - Validation emits **no** `DogLevelChanged`: the first level is an assignment, and otherwise N-09 would fire at every validation.
7. **Notification locale.** N-02 and N-39 render in `Account.locale` when the account exists, falling back to `signup.locale`.
8. **GENERIC `validateIban`** runs the mod-97 check; today it always returns true.
9. **OpenAPI error lists.** Complete the error responses of the S04 routes with the codes the code throws:
   - `VALIDATION_ERROR`, `INVALID_IBAN`, `MEMBER_ERASED`;
   - `IDEMPOTENCY_KEY_REUSED`, `DOCUMENT_TYPE_UNKNOWN`;
   - `MODULE_DISABLED` on the checkout;
   - `LEVEL_NOT_ACTIVE`;
   - the 409 of `GET /members/{id}/signup`.
   
   Where it is feasible, add a contract test that compares, per route, the codes the handlers can throw with the documented ones.
10. **D1 details (S14).**
    1. `deltaThisMonth` subtracts the members whose `leftAt` (the instant they became `LEFT`) falls in the month, not those whose `leaveDate` does (R-14-02, amended 24-09). Today a leave dated 31-08 and applied on 01-09 is never subtracted. Update T-14-02.
    2. `waitingTotal` is `null` when `WAITLIST` is off. Make it nullable in the record and in the OpenAPI.
    3. `followUpUnread` is gated by `TASKS` (R-14-08). The current test asserts the opposite of T-14-23: fix it.
    4. `RiskNotified.gender` is nullable in the event catalog.
    5. `percent` is an integer (R-14-03, HALF_UP).
11. **Tests the audit found weak.** Make each one assert what its §11 row says:
    - T-04-11: the email case asserts `VERIFICATION_SENT` exactly; today it would also pass with `NEW`.
    - T-04-17: assert `AccountCreated`, `MembershipChanged`, `UpfrontPaymentRecorded`, `levelAssignedAt` and `nextInvoiceDate`.
    - T-04-10: assert the keys the code really uses.
    - T-04-16, T-04-19, T-04-21, T-04-26 and T-04-28: complete them against their rows.
    - T-14-11, T-14-22 and T-14-23: a club B that is not empty, and the module assertions of §9.
12. **The club's legal identity on `/branding` (web E3-W05, question 4).** `GET /branding` adds `club.legalName` and `club.taxId` from `ClubConfig` (S02 §3; they are public business identifiers, which LSSI art. 10 requires on the web). The public footer shows them (web E3-W08). Update R-02-02's contract test.
13. **Seed text.** `seeds/club-canic.yaml`: the Pack 6 condition starts with a capital letter («Només un cop»), as in the mockup.
