### Assumptions

- ROADMAP's «S08's `RingSetupPort`» is the existing `clubs.training.application.ports.RingSetupPort` (S09 R-09-15, E5-T04); E9-T01 named it so. Screen 07's line («A la pista hi ha muntat…», T-16-20) reads `GET /me/ring-setups`, which hides setups from members while `courses.showSetupToMembers = false`; S08's contract is unchanged.
- `GET /me/ring-setups` without `ringIds` lists every active ring of the club, a superset of R-16-09's «per pista reservable (i per a les de les seves classes)»; the clients pass `ringIds`.
- A setup's `expiresAt` is the start of a club-local day (R-16-08's example: «Dl 12-10 06:00 → EXPIRED» for a setup of Monday 5-10); `expectedUntil` is the last day it is shown. A start of day in a DST gap moves forward; an ambiguous one takes the first occurrence (`LocalDate.atStartOfDay(zone)`).
- A renewal publishes no event (the setup stays `ACTIVE`; §5 lists none) and is not audited (S14 R-14-09 has no action for it).
- `pathLengthM` absent with a new model stores 0, not null: `CourseStats.pathLengthM` is a required number in the published `Course` form, and making it nullable would be a breaking change for the web.
- E115 point 6 uses two new S16-owned counters, `rings.geometryReferences` and `courses.references`, written only with `$inc` (a same-value `$set` would be a no-op that conflicts with nothing). The AgilityHub library is not written (never deleted; shared by every club). A write conflict is answered `409 STALE_VERSION` (CATALEG_ERRORS §1), as `RingSetupService` already did; nothing retries.
- `levels.enabled = false` is checked before a level's club on courses and setups, so a foreign level with levels off is `422 LEVELS_DISABLED`, not `404`.
