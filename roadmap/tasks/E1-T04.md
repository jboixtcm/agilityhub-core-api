# E1-T04 · Impersonation grant and handoff between apps

## Objective
Work package WP-01-C: «Entra com l'abonat» tokens for admins, and the one-time code that moves a session from `clubs` to `clubs-admin` (and back).

## Spec references
S01 R-01-09 (impersonation), R-01-13 (handoff), R-01-17 · tests **T-01-11, T-01-12** · `docs/specs/S14-*.md` (audit of impersonated actions) · `docs/specs/00-transversal/MATRIU_PERMISOS.md`.

## Context to load
S01 R-01-09, R-01-13, §6 rows `/members/{id}/impersonation-token`, `/auth/handoff`, `/oauth2/token` handoff grant · S14 §5 (`impersonatedMemberId` in AuditEntry, E0-T07) · this file.

## Steps
1. `POST /members/{id}/impersonation-token` (ADMIN of the same club; a token that is itself impersonated → `403 IMPERSONATION_DENIED`): checks `Member ACTIVE/INACTIVE` + its `Membership` (R-01-09), creates `ImpersonationGrant` (collection, `auth.impersonationMinutes` = 60, `reason`), issues an access JWT **without refresh token** with `sub` = the member's account, `roles [MEMBER]`, claims `imp = true`, `actorAccountId`, `impersonatedMemberId`; event `ImpersonationStarted{actorAccountId, memberId}` (catalog) + audit `IMPERSONATION_STARTED{reason}` in the same transaction; `POST /oauth2/revoke` of that token → `ImpersonationEnded`. `ADMIN`/`INSTRUCTOR` endpoints reject `imp = true` with `403 FORBIDDEN` (a `@RejectsImpersonation` guard or the existing role resolver).
2. Request filter: when `imp` is present, `CurrentUser.impersonation()` is set so every audited mutation records `actorAccountId` and `impersonatedMemberId` (E0-T07 `AuditWriter` reads it); expose `CurrentUser.origin()` = `DomainEvent.Origin.BACKOFFICE` for S08 (the model's `origin` enum is `APP · BACKOFFICE · INSTRUCTOR · SYSTEM`; an impersonated write is `BACKOFFICE` with both ids in the audit entry).
3. Handoff R-01-13: `POST /auth/handoff {targetClientId}` (authenticated) → single-use code (60 s, hashed) bound to the account, the club context and the target client; grant `urn:agilityhub:grant:handoff` exchanges it for tokens of the target client; reuse → `400 HANDOFF_INVALID` + `SecurityEvent HANDOFF_INVALID`; `403 NO_MEMBERSHIP` when the account lacks the target role. The web lands on `https://{target host}/entrar?handoff=<code>` (R-01-13) — the code is only ever in that query parameter, never logged.
4. `POST /oauth2/revoke` accepts impersonation tokens.
