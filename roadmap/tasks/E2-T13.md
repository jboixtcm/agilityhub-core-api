# E2-T13 · CI stability: export size check without a full aggregation count (ExportEngineIT 100 001 rows exceeded Mongo's time limit on the runner)

## Objective
`main` must be green. The first CI run after E2-T06 (`7783b83`, code of `4e3657e`) fails only in `ExportEngineIT.T_14_16_100001RowsRejectBeforeCreatingAJob`: `UncategorizedMongoDbException: PlanExecutor error during aggregation :: caused by :: operation exceeded time limit` (34.8 s). The `EXPORT_TOO_LARGE` check counts the whole result set through the list engine's aggregation (now with the real census projection, lookups and indexes of E2-T06) over 100 001 documents on a 2-core runner. All other 386 ITs and the 294 unit tests pass.

## Spec references
S14 R-14-12 (`count > 100 000` → `422 EXPORT_TOO_LARGE`; `ExportPolicy.maxRows`), T-14-16 · E2-T07/E2-T08 list engine and export admission · this file.

## Context to load
`shared/application/lists/ListEngine.java`, `shared/persistence/MongoListRepository.java` (count/aggregation and any `maxTime`), `clubs/common/application/ListExportService.java` + `ExportPolicy.java`, `src/test/java/com/agilityhub/core/clubs/common/api/ExportEngineIT.java` (`T_14_16_100001RowsRejectBeforeCreatingAJob`, its fixture insertion), the CI log excerpt above · this file.

## Steps
1. **Size check by bound, not by full count**: the admission only needs to know whether the selection has more than `maxRows` rows. Replace the full count with a bounded count on the **base match** (tenant + filters, before any `$lookup`/projection stages): `countDocuments(filter, limit = maxRows + 1)` (or an aggregation `[$match, $limit maxRows+1, $count]`) — O(maxRows) index/collection scan without lookups. Keep the accurate `rows` value for the accepted jobs (computed during rendering, as today). Same for the 5 000 sync threshold if it is computed by a full count.
2. **Test cost**: the 100 001-row fixture must be inserted with one unordered bulk write of minimal documents (only the fields the base match needs), reused within the class if several tests need it; assert the request answers `422 EXPORT_TOO_LARGE` in well under 10 s on your machine (paste the timing). Do not raise Mongo `maxTimeMS` to hide the cost; if a `maxTime` exists on the count, keep it and let the bound make the query cheap.
3. Run `ExportEngineIT` three times locally (`./mvnw -Dit.test=ExportEngineIT verify`; tails per the evidence rule) and the full `./mvnw -q verify` once.
