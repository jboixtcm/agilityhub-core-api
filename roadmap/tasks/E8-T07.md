## Steps
1. **A receipt with a zero or negative total is never direct-debited (review #1, major; R-12-12, ruling E89).**
   - `includeInNextRun` applies only to a manual receipt whose total is positive. Creating one with a total of zero or less and the flag → `400 VALIDATION_ERROR {field: includeInNextRun}`.
   - The run never picks up a receipt whose total is not positive, whatever its flag says (a receipt stored before this fix).
   - The admin settles a negative adjustment by hand (R-12-16).
   - Test: R-12-19's own example, «Ajust quota setembre −30,00 €», on a `SEPA_DD` member.
2. **A rollback reissues its whole block (review #2, major; T-12-13, R-12-14, ruling E89).**
   - A rollback rolls back every receipt of the run, including any receipt the admin cancelled meanwhile. That receipt becomes rolled back as well, and its history keeps the admin's reason.
   - The counter returns to the run's first number, and the numbering floor ignores the run's own block. The next generation therefore reissues the same numbers.
   - Test the review's sequence: run R1 numbers 0912…1026; the admin cancels 0950; rollback; the second generation starts again at 0912, with no gap and no duplicate among the live receipts.
3. **The waiting manual receipts are part of the simulation (review #3; R-12-07).**
   - The `includeInNextRun` receipts the run would remit are in `invoicesPreview` and in the KPIs («Import de la remesa»), so D6's confirmation matches the remittance.
   - They get the run's incident checks: a member who has `LEFT`, has no bank account left (`NO_BANK_ACCOUNT`) or no longer pays by `SEPA_DD` is an incident, and the receipt is not remitted.
   - A flagged receipt, or a pending charge, created after the simulation makes it stale (`409 SIMULATION_STALE`).
   - Test each.
4. **Rolled back comes from the run (review #4; §5).**
   - A receipt is rolled back when it belongs to a run whose status is `ROLLED_BACK` (or carries the run's `FAILED{ROLLBACK}` collection), not when its `cancelReason` holds a reserved word.
   - The admin's cancellation reason is free text again: «Rollback» typed by an admin is accepted.
5. **An index the numbering can use (review #5).** Add a non-partial, non-unique `{clubId, series, number}` index, so that `highestNumber`, `numberedFrom` and `GET /billing/periods/{period}` use an index instead of scanning the club's invoices. Show the `explain()` before and after in the report.
