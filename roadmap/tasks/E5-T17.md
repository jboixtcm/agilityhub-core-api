## Objective

## Steps
1. **E37 for a class that starts before its review time (review #1, S15 §6).** P2 skips a class that has already started (`RiskReviewJob:55` and `:74`). So `RiskReviewQuery.reviewWillRun` also requires `c.startsAt().isAfter(reviewAt)`, the same comparison P2 makes at `reviewAt`.
   - A 07:00 class with `classes.riskReviewTime=07:30` and 0 booked is `AT_RISK`, never `WILL_CANCEL`. With `classes.riskAutoCancelSameDay=false`, it is never `WILL_REVIEW`.
   - A class that starts exactly at `reviewAt` is `AT_RISK` too, as P2 skips it.
   - Add those rows to `RiskReviewQueryTest.T_15_15_…`, and one case to `RiskReviewJobIT.T_15_15_E37_…` (with the D1 parity it already checks).
2. **D1 follows the risk-review switch (review #2, S14 §7 amended 25-09).** The switch is a parameter write (`jobs.riskReview.enabled`, `ParameterChanged`), and `DashboardEvents` already evicts D1 on every `ParameterChanged`.
   - Pin it in `RiskReviewJobIT`: after `PUT /jobs/risk-review/switch {enabled: false}`, dispatch the outbox the way the ITs do, with no `dashboards.invalidate(CLUB)`. The next D1 read shows `AT_RISK`.
   - If the test fails, wire the eviction.
   - Remove the manual invalidations that the dispatch makes unnecessary in that IT, or say in a comment why one stays.
3. **The E5-T15 nits (review #3–#6).**
   - `CatalogService.stopsBeingReservable`: the Javadoc says what `update()` says. The retried ring change answers `422 RING_HAS_BOOKINGS`, and `409 STALE_VERSION` only once the retry budget runs out.
   - The ring-change backoff is injected, like the `SchedulingTransactions` one, so `CatalogServiceRetryTest` does not sleep.
   - The 112 / 11000 / `TransientTransactionError` check lives in one shared helper (for example `shared.application.TransactionRetries`), used by `CatalogService`, `SchedulingTransactions` and `TrainingTransactions`. Their unit tests stay green unchanged.
   - `ActivityIT.T_07_16_T_07_18_theAppRowsCarry…` → `T_07_16_R_07_13_…`: T-07-18 is `finishEnded`, which the test does not assert.
   - Optional: a `CleanupJobIT` variant in which `JobRunner` itself commits `FAILED` and the `Job.failed` hook throws (the path swallowed at `JobRunner:235-237`). The next run of the day still starts.
4. **The `ring_slot_locks` retention (review «Not checked»; S15 R-15-19 and `MODEL_DADES_PLATAFORMA.md` amended 25-09).** Every touched slot adds a document, and nothing removes them.
   - Each upsert sets `expiresAt` = `startsAt` + 7 days.
   - A TTL index on `expiresAt` (`expireAfterSeconds: 0`) is created with the collection, in `schedulingCollections`. It must be idempotent on restart and on a second instance, like the collection itself.
   - A past slot takes no booking. A later write that touches it recreates the document with the same upsert.
   - P9 `cleanup` reports the expired documents that the TTL has not removed yet, in `ttlPending.ringSlotLocks`, like the other TTL collections.
   - Tests: the index exists with its options after startup; an upsert sets `expiresAt`; the P9 counter counts an expired document.
