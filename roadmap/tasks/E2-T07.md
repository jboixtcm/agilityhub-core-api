# E2-T07 · Universal list, filter-values, saved views and synchronous exports (S03 WP-03-C)

## Objective
Work package WP-03-C: one reusable list engine for every backoffice list (D5, D15 now; every later list).

## Spec references
`docs/specs/00-transversal/CONVENCIONS_API.md` §3–5 (list contract, operators per type, `filter-values`, `fields`, sort, page limits, `INVALID_FILTER`) · S03 R-03-22 (filter-values), R-03-23 (saved views per user and `listKey`), R-03-24 (exports: xlsx/pdf, `columns=`, `202` when > 5 000 rows), `ExportPolicy` (INSTRUCTOR → 403 per A17a; IBAN masked) · tests **T-03-08, 09, 10, 11**.

## Context to load
CONVENCIONS_API §3–5 · S03 R-03-22…R-03-24, §6 rows `/members`, `/members/filter-values`, `/members/export`, `/saved-views` · `docs/DECISIONS_PENDENTS.md` A17 · this file.

## Steps
1. `ListQuery` parser (`page,size,sort,q,filter=<field>:<op>:<value>` repeatable, `fields`) → Mongo criteria from a per-endpoint `ListDefinition` (filterable fields with types/operators, sortable, searchable text fields, default sort); unknown field/operator → `400 INVALID_FILTER`; page size caps.
2. `filter-values?field=` facets (value + count, top 50, respecting the other active filters).
3. `SavedView` (per account + `listKey`: name, columns, filters, sort; CRUD endpoints).
4. Synchronous export (`format=xlsx|pdf`, `columns=`): Apache POI (xlsx) and a simple PDF renderer with the club brand; ≤ 5 000 rows inline, otherwise `202 {jobId}` handing over to E2-T08; `ExportPolicy` (role, masked fields); event `DataExported` + audit `DATA_EXPORTED`.
5. Apply the engine to `/members` and `/dogs` (E2-T06 controllers).
