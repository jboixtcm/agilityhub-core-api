## Steps
1. **Nulls in the standard form (review #1).**
   - `GET /club` (`ClubSettings`) sends `legalName`, `taxId`, `address`, `contactEmail`, `contactPhone`, `websiteUrl`, `pwa`, `legal` and `lastChange` as `null` when unset. Declare them nullable.
   - The dashboard (`Dashboard.riskReview`, `pendingSignups`, `dogsByLevel`, the four `DashboardKpis` blocks) and `TrainingBookingRequest.override` still use the house forms (`$ref` with `type: [object, null]`, or `$ref` + `type: "null"`). Write them as E3-T16 did, so that openapi-typescript keeps the `null`.
   - Extend `T_04_29_T_04_33_everyOptionalProperty…` (renamed in step 3) to the `ClubSettings` and `Dashboard` roots.
2. **A normalized tax id (review #3, R-02-06).** Store the tax id normalized: upper case, no spaces or separators. Compare normalized values, so that the same id with other spacing is no change. `/branding.taxId` then publishes the normalized form. Test: `"g-6318 9617"` is stored and published as `G63189617`, and resending it with other spacing is no change.
3. **Test names by spec id (review #2).** Name the tests by the rule they assert, as the `R_04_20_` tests are:
   - `SettingsIT` `T_02_11_R_02_06_…` and `T_02_11_R_02_02_displayCity…` → `R_02_06_…` and `R_02_02_…`;
   - `ClubDefinitionsIT` `T_02_04_T_17_01_…` → by rule;
   - `SignupPaymentMethodsIT` and `E3GateFixesContractTest` `T_04_29_T_04_33_…` → by rule, because T-04-29 and T-04-33 are web UI tests;
   - `SignupPaymentMethodsIT` `R_04_27_T_17_01_clubApplyRefreshes…` → `R_04_10_…` (the organizer's E3-T14 note).
4. **One nullable helper (review #5).** Move `nullableReference` into one shared customizer used by the E3, E4 and E5 configurations. The generated document stays byte-identical, apart from step 1.

### What changed
1. **Nulls in the standard form (review #1).**
   - **`ClubSettings`:**
     - `legalName`, `taxId`, `contactEmail`, `contactPhone` and `websiteUrl` are `string | null`.
     - `address`, `pwa`, `legal` and `lastChange` are `anyOf [$ref, null]`: `nullable = true` in the record, then the new E2 list `NULLABLE_REFERENCES = ["ClubSettings"]`.
   - **The records `ClubSettings` reaches**, found by the extended test:
     - every `ClubAddress` field, `ClubDomain.verifiedAt`, `ClubLegal.imageConsentText`, `ClubPwa.name`/`shortName`, `Theme.logoUrl`/`logoDarkUrl`/`markUrl` and `LastChange.actorName` are nullable;
     - three maps that are never `null` became **required** (Assumption 3): `ClubSettings.paymentProviders`, `ClubPwa.iconUrls` and `ClubLegal.imageConsentTextI18n`.
   - **Dashboard:** `Dashboard` and `DashboardKpis` are in the E3 list. Their blocks stay required, and are now `anyOf [$ref, null]`.
   - **Training override:** `TrainingBookingRequest` is in the E5 list, so `override` is `anyOf [TrainingOverride, null]`.
   - `E3ContractIT.T_14_01_…` asserted the old form (`type` contains `null`). It now asserts the union, and that the four KPI blocks are required.
2. **Normalized tax id (review #3, R-02-06).**
   - `CountryProfile.normalizeTaxId(value)`: upper case (`Locale.ROOT`), every character that is not a letter or a digit removed, and `null` when nothing is left.
   - The `Club` record's compact constructor applies it. So `PUT /club`, `club:apply` and any other writer store that form. A value stored before the rule is read in that form too.
   - `ClubSettingsService` compares the normalized request value with the stored one before the profile check, so the same id with other spacing is neither checked nor audited.
   - `ClubDefinitionWriter` compares two normalized values (its `isBlank` guard is gone), and so does its diff.
   - `SpanishCountryProfile.validateTaxId` checks the normalized form. Dots and slashes are now accepted as separators: `G.6318.9617` passes.
   - Descriptions: `ClubSettings.taxId`, `/branding` `ClubSummary.taxId` and `ClubUpdate.taxId` say the value is normalized.
3. **Test names by rule (review #2):**
   - `SettingsIT`:
     - `T_02_11_R_02_02_displayCity…` → `R_02_02_R_02_06_displayCity…` (it asserts both rules);

### Assumptions
1. **Normalization rule.**
   - Upper case, with every character that is not a letter or a digit (`[^\p{L}\p{N}]`) removed, so spaces, `-`, `.`, `/` and `_` go.
   - A value with nothing left is `null`. So `PUT /club {taxId: ""}` now clears the tax id to `null`, where it used to store `""`. `/branding` already sent `null` for a blank one.

   - That makes it an invariant of the stored club, for every writer (`PUT /club`, `club:apply`, a future console) and for values stored before this change.
   - Side effect: a legacy `EXAMPLE-ORG` in Mongo reads as `EXAMPLEORG`. The existing `R_02_06_theTaxIdIsCheckedOnlyWhenTheRequestChangesIt` now expects that.
