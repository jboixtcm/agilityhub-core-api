- The task was `ready`; all three local dependencies were `verified`. No other task was started or edited; no Organizer verification section or ROADMAP edit, and no git-writing command.
- `ClubDefinition` means WP-A's already published schema, not the illustrative YAML layout in S17 §3: localization stays inside `club`. The console schema is derived from that schema, with the S17 credential fields restricted to `{env}` references and `COMPLET` added to the existing presets. Console input excludes seed accounts/passwords and local page files. The CLI schema and behavior remain unchanged; no environment variable is resolved by a stub.
- The data model wins for the seven checklist keys: `sepa` represents at least one configured provider when BILLING is enabled (including Stripe/manual), not three extra checklist items. The console publishes domain `BROKEN` and internal `notes` without changing persistence in this contract task.
- The existing error catalog/code wins over S17's status examples: `VALIDATION_ERROR` is 400 and `TIMEZONE_CHANGE_BLOCKED` is 422. No error code, event, notification or parameter was added.
- DELETE domain/admin uses 204; DELETE provider uses the spec's 200 summary and `?version=`. Theme writes use uploaded file keys and return the existing display-URL Theme.
