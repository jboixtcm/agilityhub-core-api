# E0-T02 · Docker Compose for development and the integration-test base (Testcontainers)

## Objective
`docker compose up` starts Mongo (single-node replica set) + the API; integration tests start Mongo with Testcontainers; a smoke test proves transactions work.

## Spec references
`docs/PLA_BACKEND.md` §9 (testing layers) · `docs/decisions/ADR-003`.

## Context to load
`AGENTS.md` · `docs/PLA_BACKEND.md` §9 · this file.

## Steps
1. `compose.yaml`: service `mongo` (`mongo:7`, `--replSet rs0`, an init container or healthcheck script that runs `rs.initiate()` and waits for `PRIMARY`, named volume); service `api` built from a multi-stage `Dockerfile` (maven build stage → `eclipse-temurin:21-jre`, non-root user, `HEALTHCHECK` on `/api/v1/health`); environment from `.env` (default values documented in `.env.example`).
2. `AbstractIntegrationTest`: `@SpringBootTest` + `@Testcontainers`, a **static shared** `MongoDBContainer("mongo:7")` (Testcontainers starts it as a replica set), `@DynamicPropertySource` for the URI; `MockClock` (`@TestConfiguration` that replaces the `Clock` bean with a mutable clock — the `Clock` bean itself is created in E0-T04, so for now a `java.time.Clock` bean in a config class); `Fixtures` helper to load JSON test data.
3. `MongoTransactionSmokeIT`: writes two documents inside a transaction and asserts both are visible; a failing transaction leaves nothing.
4. `README.md`: "Run locally" section (compose + curl), "Run tests" (Docker required for `verify`).
